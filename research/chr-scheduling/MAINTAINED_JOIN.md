# A3 maintained prefix entry

`maintained_cases.cases()` supplies 36 proposed finite source fixtures. Root-owned
registrations and runners control comparative execution. The hand tests do not
constitute a registered comparative matrix.

`check_maintained_source.check(case, mode, quantum=8, transitions=True)` executes
actual source rules with `prefix`, `full`, or `selective` matching. With transition
checking enabled, every source transition is compared against the independent tree
control. With it disabled, full outputs/residuals, raw alternatives and exhaustion
are checked against the independent analytic fixture formula. Candidate work
counts exclude the independent oracle. The ten-million cap covers all instrumented
source, matching, index, support and fork actions, not just successful matching.
No elapsed-time claim follows. `maintained_store_cases.cases()` supplies four finite
families and eleven update stages; `check_maintained_store.validate` compares all
context projections with exhaustive ordinary prefix matching.

Rows contain rule identity, ordered occurrence IDs and nonbinding rule-variable
values. The global row registry carries context support masks. Each context retains
its own successful and failed extension tests, occurrence/variable/parent reverse
indexes, predicate pools, substitution and last snapshot. `full` rebuilds the same
representation after any store/binding delta; `selective` invalidates dependent
tests and descendants. Both rebuild predicate pools and visit retained prefixes
while discovering missing extensions. No maintained join-key hash index is claimed.
Current guards, history and final ordered selection remain in `StepJob`.

`maintain.match_call` and `maintain.test_create` count physical computations;
`maintain.row_payload_create` counts global row-payload introductions (including
reintroduction after removal), while `maintain.row_support_extend` counts support
extension of a currently retained payload. Fork tests/rows are separately counted.
Support merging does not mean identical new tests in different contexts execute
once. This entry measures retained-update and inherited-prefix reuse, with shared
row payloads; new heterogeneous-context matching work remains a separate contrast.

High-water row, test, dependency and index-edge fields count retained records, not
heap bytes. They include fork copies and are updated at record mutations. Actual
allocation, transient host tuple/hash/sort costs, and pointer sharing require a
separate cost harness. Completed contexts remain retained through the query's
reported endpoint; returned metrics expose that retention. Dropping the index
releases its ownership. Incremental completed-context reclamation is unimplemented.

Updates are serialized and may yield. The source gate drains each update before
another matcher operation; no simultaneous source jobs share a mutating update.
Closing or failing an update poisons the index, which must then be discarded.
This is explicit unsupported abandonment, not rollback or resumable cancellation.
No partial matching state can become a source answer. Genuine concurrent
subscriptions, context reclamation and dynamic unbounded support are not provided.

The six-rule source generator uses a balanced command tree. Let C=NR+5 for keep,
and C=3NR-2N+5 for consume. Conservative per-context live-occurrence bounds are
4N+2NR+9 and 6NR+9 respectively (777/1545 at the largest proposed fixture).
Initial pending length is 4N+3 (259 maximum); rule-body pending length is at most
two. A maximum of eight explicit alternatives is supported. The private command
interpreter and full output handling are charged source work, not free input events.
