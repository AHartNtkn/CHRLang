# Prepared query prefix: source entry gate

Registered before execution. T082 remains active.

**Question:** can the existing prepared-query API reuse unchanged tables while preserving the complete answer and the exact consuming choice of fresh execution?

Compare `prepare_query(prefix).start(suffix)` with `start_search(prefix + suffix)` on identical ordered ground inputs. No additional baseline or language restriction is introduced. Four families exercise selective keys, a request consumed after neutral heads, duplicate left/right rows, and broad matching. Selective and neutral reuse both tables; duplicate and broad reuse only the left table because right rows change with the request.

Cross widths 8/32/128, Global/Active, Scan/Indexed, and two successive endpoint requests. Run ordinary counter-free control and selective-probe builds separately. Each of the 96 configurations executes two fresh and two reused searches plus one cancelled reused search. Require an independently constructed full residual multiset, exactly one raw completion, empty bindings, and the analytically expected occurrence tuple for both modes. Retain answers until the template and rules have been disposed. Each search is bounded at 2,000,000 ticks; each test command at 120 seconds and 1 GiB address space, one test thread. No timing inference is licensed by this source gate.

Any mismatch blocks cost interpretation and triggers repair or an explicit experimentally demonstrated change in selection contract. Passing permits a separately registered ownership/cost comparison; it does not establish that cloning a prepared store is economical. Next compare that cost investigation against integrated admission, graph attribution and direct solving. This is package one since the portfolio review.
