# Structural prefix reuse: source and work qualification

This experiment asks whether deeper prefix matching exposes reusable work after competent selective access. It establishes source correctness and operation counts; it makes no timing or allocation claim.

Selection follows T081 and the current sequence. The cheap-prefix lifecycle comparison leaves this architectural benefit untested. A bounded source/work screen is less costly than another timing matrix and can determine whether a cost comparison has a meaningful contrast. Useful symbolic union is the strongest ready distinct alternative; the required fourth-package portfolio review follows this screen, including an obstruction.

## Sources and controls

Use one deterministic rule keeping `left(f^D(X))` and `middle(f^D(Y))`, consuming `right(X,Y,Out)`, and equating `Out` with `hit`. Widths 4 and 8; depths 0, 8 and 32; two distinct query seeds per prepared rule set. Test four families separately:

- Sparse terminals repeatedly select the last left/middle key pair.
- Keyed terminals select the diagonal, giving indexing an opportunity.
- Broad invalidation consumes all left occurrences with a higher-priority kill rule before any join.
- Deep mismatch replaces the innermost wrapper in every middle input; at depth zero it uses no middle facts. No joins should fire. This is a negative semantic control, not a matched depth-zero cost contrast.

There are 48 source configurations. Compare local scan, complete tuples, partial joins and proper intermediates, each with diagnostics enabled and disabled. Compare conventional Scan/Indexed and inferred-specialized Scan/Indexed with their normal access algorithms. Preserve canonical ground-term identity and usable key indexes. Inferred specialization is the existing specialization control; it is not a measurement of independently compiled generated Rust.

Check each full answer against the independent scalar source executor, then check expected hit count, residual resource counts and raw answer cardinality. For each query run cancellation after one adapter advance, then start and complete a fresh execution using the same preparation. Keep completed answers until after engine and preparation disposal and verify them again. A one-step cancellation checks that boundary only; it is not sustained lifetime evidence.

## Diagnostics and runs

Expose the existing local graph's actual pattern/equality node counters through the multihead adapter, using its existing const metrics parameter. Verify a nested match counts nodes only with diagnostics enabled and has identical complete answers. Count local head attempts, fact visits, intermediate-map visits, peak retained entries and firings. For conventional execution retain structural tests, candidate visits, generic AST visits, key visits and specialized applications. These counter definitions differ; compare depth slopes within an engine and matching savings within local strategies, not numerical counts across engines as equal-cost units. Collect counters before observation.

Run the source test twice in each of two release builds: compiled metrics enabled through `compiled-work`, and all compiled metrics disabled. Local diagnostic and plain instances run in both. Freeze sources and binaries before these four runs; require exact repeated diagnostic rows per build and identical complete answers in all configurations. Preserve test failures and repairs. Initial test-process bounds: 60 seconds wall/CPU, 1 GiB virtual memory, 200,000 adapter advances per complete query; builds have 300 seconds. A cutoff requires diagnosis, not rejection.

## Interpretation

Hypothesis: proper intermediates pay prefix matching once while scanning repeats it across consumed terminals. Establish whether actual pattern visits increase less with depth; also inspect whether the strongest conventional indexed/specialized control retains depth-dependent structural work and what its key construction costs do. Broad invalidation and no-match inputs expose work done without useful reuse.

If these contrasts qualify, register separate full-lifecycle sizing before comparative timing. If existing indexing/canonical reuse eliminates the benefit, identify the exact operation and source premises; do not reject broader intermediate joins or subscriptions. A successful work screen does not prove an efficiency win. The portfolio review must compare completing these costs with useful union and unfinished integration/demand work; the research remains active.
