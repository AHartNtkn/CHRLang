# E06 — backend service and correspondence investigation

E06a (ordinary/local nets), E06b (encoded functional backend), and E06c
(native choice integration) remain independent. None is closed by another's cost.

## E06a first gate: finite encoded-data services

Implement literal principal-port graph replacement with a finite signature and
one rule per unordered active pair. Validate each generated RHS uses each boundary
and internal port exactly once. Validate graph wiring and the active queue after
every interaction in correctness tests. Do not implement an unbounded host
unification operation behind one net rewrite.

The first service vocabulary is immutable encoded data: unary numbers, references
containing encoded numbers, application tags and child lists, pairs, options and
Booleans. Compare, copy, erase, and first-match association-list lookup are actual
controller/data rules. Preserving lookup returns both the original table and the
optional result. The initial protocol explicitly duplicates the table; its fan
and eraser traffic is measured. Copying Ref(n) preserves n; it does not allocate a
new logical variable. These are components of a binding service, not yet a unifier.

Check all generated shallow data pairs plus nested encoded terms against host
structural equality. Exercise FIFO and newest-first reduction, composed copy then
comparison, preserved table lookup with duplicate keys, erasure, and quantum
boundaries. A service result is unavailable while work remains or a controller is
stuck. Quiescence alone is not a CHR answer or proof of successful unification.

The net rewrite performs a fixed finite RHS replacement. Queue service can yield
after any interaction. This establishes finite administrative yields for these
services, not fair unbounded source search. Host input/output encoding and Python
allocation are separate costs. Node slots currently accumulate tombstones; report
allocated slots as well as live nodes instead of claiming physical reclamation.

## First lookup comparison (registered before comparative runs)

V={0,1,4,16,64} bindings, payload unary depth D={0,8,64}, and query positions
first/last/absent give 45 requests. Key i is unary i; value i is an encoded Ref(i)
inside D unary constructors. Table order is ascending, with unique keys. Empty
first/last requests both query zero and are retained as explicit workload variants.

Compare ordinary-net FIFO with direct immutable borrowed lookup and direct copied
lookup. Both direct controls use explicit structural pair traversal, preserve the
original table, and materialize the entire table/result at extraction. The copied
control additionally copies input data before lookup, isolating representation
ownership from the best direct immutable control. No input construction or expected
answer generation is inside the engine interval. Charge net rule generation,
encoding, all active-pair/fan/eraser work, lookup scans, and full output extraction.

Record per-phase elapsed microseconds and traced Python current/peak allocation,
net interactions by rule, created/live/peak-live agents, retained slots, direct
comparison pairs, table entries visited, and output data size. Traced storage is
not RSS or cumulative requested allocation. Tracing changes timing overhead, so
this is an instrumented service comparison, not a prediction of optimized native
backend speed. A direct lookup scan and a net interaction are different work units.

Run 135 sequential fresh processes with PYTHONHASHSEED=0, seeds 601 and 602, at 60 seconds/process and
200,000 net interactions/request. Preserve timeouts, errors and unfinished runs;
require full expected outputs and deterministic non-time replay for completed
runs. A timeout does not justify closure. Before a comparison, pass correctness
tests and commit the harness/registration. Hypothesis: explicit preservation and
erasure traverse unrelated table data even for a first-entry hit, while borrowed
lookup avoids that service work; output materialization still scales with V and D
in every mode. Misses expose encoded-key comparison and scanning costs. A result
supporting this hypothesis motivates a preserving traversal or shared-data protocol,
not rejection of nets.

## Remaining service/backend work

Implement dereferencing, transactional finite-tree unification and occurs traversal,

Multiport operand inspection and routed variable-cell fusion need distinct probes

Continue pinned encoded-backend and native-label correspondence work independently.

## E06a preserving-prefix ablation (v2, registered before runs)

Add Keep/KeepEntry/KeepDecide/Restore/Unpack controller rules. Keep returns the
preserved table paired with the option result. On a miss at one entry, retain its
key and value in Restore while recursively querying the tail. On return, Restore
reconstructs that Cons/Pair prefix. On a hit, route the untouched tail directly
into the preserved output and duplicate only the selected value. Encoded keys are
still explicitly copied for destructive comparison and continued lookup.

The protocol has the same first-match table/result contract. Structural induction
on table length supplies correspondence: the empty result preserves Nil; a hit
preserves the current entry and tail; a miss reconstructs exactly that entry around
the recursively preserved tail. No binding or source failure is committed here.
Test duplicate keys, both reduction orders, quanta 1/3/16, and physical survival of
unselected Ref payload nodes as well as full returned values.

Repeat all 45 requests in four modes (180 fresh processes) using seeds 603 and
604, with the same time/interaction bounds and measurement phases. Both net modes
compile the same extended rule system. Keep v1 results separately; compare v2
modes within this common compiler. Hypothesis: first-hit interactions cease to
scale with unrelated payload depth; they still scale with the selected value's
copy size. Misses retain unary key-copy/comparison costs, but avoid payload-wide
erasure and full table duplication. Reconstruction and extra controller overhead
may lose on empty or tiny tables. Full output extraction remains mandatory and
can dominate after service work improves. Require exact non-time replay; investigate
rather than suppress any mismatch.

## E06b first continuation gate

Use HVM4 source revision `6defdfc7dae2a3cca5dd6e74ed0612385b5646a8`, already
inspected in the research dossier. Compile its unmodified src/hvm.c with installed
clang -O2 to a temporary executable. This is a pinned experiment, not a claim
about current upstream behavior. Record compiler/version, source hash and commands.

Begin with a finite defunctionalized controller: Loop, Emit(x), Bind(x), Done(x),
and Choice(a,b) are ordinary constructor data. One step maps Emit to Bind to Done,
Loop to itself, and leaves an explicit Choice boundary for a source scheduler.
Advance decrements unary fuel, returning More(state). This gate tests backend
normalization of finite continuation boundaries; it is not yet a general CHR
machine or finite-tree unifier. Done is a quiescent state in this small machine;
More and Choice are private protocol data, never user terms.

Test fuel 0,1,2,4,16 on Loop/Emit/Choice, and a round holding both an infinite-loop
continuation and the finite sibling. Compare exact independently derived output
states under ordinary normalization and collapse limited to one output. Also test
More(spin(Loop)) and More(lambda u. spin(Loop)); the recursive spin has no base
case. Retain process outcomes at 0.5 seconds for these adverse cases and 5 seconds
for positive cases. A timeout is an observed lack of return; the source recurrence
and backend normalization path provide the accompanying explanation. This is not
a comparative timing claim or a proof of fairness from a timeout.

If a boundary fails, inspect the generated program and runtime path, repair the
encoded continuation protocol, and rerun. Successful tiny boundaries do not close
general machine compilation, source-step correspondence, compilation/storage cost,
label trace invariants or native collapse scheduling. A second identical gate run
checks stable result states; preserve backend statistics without treating timing
as deterministic.

## E06a finite-tree binding-service conformance gate

Extend the local rule system with dereference, occurs traversal and transactional
unification. Terms are Ref(encoded ID) or App(encoded tag, child list). Dereference
follows preserved-table lookup to an unbound representative or constructor root.
Occurs traverses dereferenced children. Both return the table unchanged. Their
termination premise is a finite acyclic input binding graph; a cyclic-table adverse
probe must yield unfinished work rather than a successful observation.

Unification privately processes an equation list, dereferences both operands,
checks free representative equality, checks constructor tags/arities, and adds a
binding only after occurs succeeds. A caller-owned table copy remains observable
only after quiescence, including on failure. Success returns the private resulting
table, failure returns no partial substitution. These result tags are service
protocol data, not source-visible failure or choice constructors.

Validate explicit alias, direct/indirect occurs, constructor/arity clash, repeated
variable and late failure cases. Then independently export 432 reference requests:
12 finite terms squared under three initial environments (empty, X=Y, X=f(Y)).
Select all three original variables, retain complete reference observations and
require exhaustion. Run each net request in FIFO and newest-first order, checking
all graph ports/active pairs at every 32-interaction yield up to 100,000 steps.
Compare successful projected MGUs modulo joint variable renaming, failure, and
unchanged original table. No candidate code enters the reference interpreter.
This is a correctness gate; comparative operation costs require a subsequent
registered direct-control matrix. Record complete outcomes and repeat the gate.

## E06a full-service cost matrix (registered before comparative runs)

Compare four modes: native immutable terms with a map, the same terms with a
linear table, encoded Ref/App/unary-ID data with a direct linear table, and the
ordinary net service. The three direct controls use the same private-worklist
algorithm with independently tested representations; all pass the 432 reference
requests. Map versus native table isolates lookup organization. Encoded versus
native table exposes representation and key traversal. Encoded direct versus net
also differs in destructive graph ownership and explicit copies, not just dispatch.
Do not attribute the entire difference to active-pair reduction.

Use 12 predetermined reference requests: environments 0/1/2 crossed with operand
indices (2,3), (9,8), (10,2), (5,6). Add seven hand-derived families at N={0,1,4,16}
and D={0,4,16}: fresh binding, binding followed by clash, occurs failure, alias-chain
binding, occurs through an alias chain, identity, and binary constructor
decomposition. N is padding size or alias-chain length; D is unary constructor
depth. Select all involved variables and return complete original/result tables
plus projected values. This is 96 requests and 384 mode configurations.

Padding uses known values under keys outside the active query variables. Chain
requests use X0=X1=...=XN with free XN. Net preservation of unrelated original table
entries is charged even on failure. Fresh/identity cases distinguish ordinary
binding work from preservation cost; late clashes test transactional failure.
Constructor decomposition and indirect occurs exercise services beyond lookup.
Hand-derived expectations and all direct/net observations must agree before runs.

For each fresh process separately measure code/rule construction, initialization,
execution and full extraction under tracemalloc, recording phase current/peak
bytes and elapsed microseconds, net rule counts/work/live agents/slots and direct
pairs/dereferences/entries/encoded-ID visits/occurs/child links/bindings. Traced
memory is not RSS or cumulative allocation. Direct terms are immutable and may
retain references to unchanged values; this is a credible control, not hidden
whole-tree copying to equalize it with destructive net operations.

Run seeds 605 and 606 sequentially with PYTHONHASHSEED=0, 60 seconds/process and
200,000 net interactions/request. Preserve all incomplete/error outcomes and
require exact non-time replay for completed configurations. Instrumented Python
timings do not predict native backend performance. No comparative run precedes
validated controls/workloads and a committed registration/harness.

Hypothesis: maps avoid repeated environment scans, encoded unary IDs magnify scan
cost, and explicit copying/preservation remains a net cost even after preserving
lookup. First-hit/identity requests with irrelevant table padding and indirect
occurs distinguish these explanations. A poor net result calls for charged
representation/ownership alternatives, including the independently open routed
variable-cell protocol; it does not close source regions, HVM, or richer nets.

## E06c first native-choice correspondence probes

Advance this path independently of ordinary-net costs. On the same pinned HVM4
revision, generate finite probes for correlated copies, independent births,
reused/overflowed labels, recursive choices and two simultaneous recursive calls,
lambda copying, disconnected failure, guarded branch effects and divergent versus
finite siblings. Record the intended source answer set and raw multiplicity
separately from the predicted behavior of each tested encoding. A deliberately
faulty encoding is a counterexample, never a source-conforming success.

Use explicit numeric birth and copy labels in generated programs. Correlated
copying uses an administrative label distinct from the source choice; test a
same-label and a 24-bit-wrapped collision as adverse encodings. Recursive numeric
labels use disjoint finite invocation ranges in the repaired case and overlapping
ranges in the adverse case. These finite allocations are not a general label
allocator or a proof of safe reclamation. Reusing a label after passing a choice
through a function tests whether an apparently consumed decision still affects
future alternatives.

Build an unmodified baseline and a separate instrumented source copy. Instrument
DSU-NUM, DDU-NUM, DUP-SUP and DUP-LAM to log requested/effective numeric labels and
administrative binder superpositions. Retain full generated programs, build/source
hashes, collapse outputs, numeric events and separate ordinary -D graph traces.
The pinned CLI rejects combining -D and -C, so never claim a -D trace observes the
collapse scheduler. Compare instrumented versus baseline answer multisets.

Finite probes use -C32 and a five-second bound; the finite-first sibling uses -C1.
The divergent-first probe uses -C1 and a 0.5-second observation bound. Do not trace
an unbounded graph. A timeout is limited observed behavior, supplemented by the
source recurrence/runtime path; it is not a general fairness theorem. Retain a
finite data-continuation alternative showing an explicit resumable boundary.

This is an exploratory correspondence gate, not a speed matrix. Confirm finite
predictions, inspect contrary evidence, repair invalid encodings and replay the
gate. Distinguish source-equivalent final sets, raw duplicate multiplicity, label
provenance and administrative effects. Passing ground outcomes alone does not
close dynamic allocator lifetime, branch-local unification/store/history effects,
collapse yields or a general native compiler.
