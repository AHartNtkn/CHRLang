# E06 — backend service and correspondence investigation

E06a (ordinary/local nets), E06b (encoded functional backend), and E06c
(native choice integration) remain independent. None is closed by another's cost.

## E06a first gate: finite encoded-data services

Implement literal principal-port graph replacement with a finite signature and
one rule per unordered active pair. Validate each generated RHS uses each boundary
and internal port exactly once. Validate graph wiring and the active queue after
every interaction in correctness tests. Do not implement an unbounded host
unification operation behind one net rewrite.

The first service vocabulary is immutable encoded data: unary numbers, references
containing encoded numbers, application tags and child lists, pairs, options and
Booleans. Compare, copy, erase, and first-match association-list lookup are actual
controller/data rules. Preserving lookup returns both the original table and the
optional result. The initial protocol explicitly duplicates the table; its fan
and eraser traffic is measured. Copying Ref(n) preserves n; it does not allocate a
new logical variable. These are components of a binding service, not yet a unifier.

Check all generated shallow data pairs plus nested encoded terms against host
structural equality. Exercise FIFO and newest-first reduction, composed copy then
comparison, preserved table lookup with duplicate keys, erasure, and quantum
boundaries. A service result is unavailable while work remains or a controller is
stuck. Quiescence alone is not a CHR answer or proof of successful unification.

The net rewrite performs a fixed finite RHS replacement. Queue service can yield
after any interaction. This establishes finite administrative yields for these
services, not fair unbounded source search. Host input/output encoding and Python
allocation are separate costs. Node slots currently accumulate tombstones; report
allocated slots as well as live nodes instead of claiming physical reclamation.

## First lookup comparison (registered before comparative runs)

V={0,1,4,16,64} bindings, payload unary depth D={0,8,64}, and query positions
first/last/absent give 45 requests. Key i is unary i; value i is an encoded Ref(i)
inside D unary constructors. Table order is ascending, with unique keys. Empty
first/last requests both query zero and are retained as explicit workload variants.

Compare ordinary-net FIFO with direct immutable borrowed lookup and direct copied
lookup. Both direct controls use explicit structural pair traversal, preserve the
original table, and materialize the entire table/result at extraction. The copied
control additionally copies input data before lookup, isolating representation
ownership from the best direct immutable control. No input construction or expected
answer generation is inside the engine interval. Charge net rule generation,
encoding, all active-pair/fan/eraser work, lookup scans, and full output extraction.

Record per-phase elapsed microseconds and traced Python current/peak allocation,
net interactions by rule, created/live/peak-live agents, retained slots, direct
comparison pairs, table entries visited, and output data size. Traced storage is
not RSS or cumulative requested allocation. Tracing changes timing overhead, so
this is an instrumented service comparison, not a prediction of optimized native
backend speed. A direct lookup scan and a net interaction are different work units.

Run 135 sequential fresh processes with PYTHONHASHSEED=0, seeds 601 and 602, at 60 seconds/process and
200,000 net interactions/request. Preserve timeouts, errors and unfinished runs;
require full expected outputs and deterministic non-time replay for completed
runs. A timeout does not justify closure. Before a comparison, pass correctness
tests and commit the harness/registration. Hypothesis: explicit preservation and
erasure traverse unrelated table data even for a first-entry hit, while borrowed
lookup avoids that service work; output materialization still scales with V and D
in every mode. Misses expose encoded-key comparison and scanning costs. A result
supporting this hypothesis motivates a preserving traversal or shared-data protocol,
not rejection of nets.
