# Source request priority versus representation repair

The CHR constructor encoding already preserves bounded constructor consistency and consuming chains, but descriptor tuple order can choose a different consumer from ordinary source order. Local handles have later lifecycle evidence; repeating those gates would not resolve this CHR-specific eligibility obstacle. Test whether moving request selection ahead of descriptor selection is sufficient, before designing a larger scheduling protocol or comparing unequal workloads.

Compare the unchanged kept-descriptor encoding with a source-rule variant that consumes take/token/descriptor in that order and reposts the descriptor before posting the result union. The latter is an experimental source protocol, not a host matcher change. It retains descriptor meaning but changes occurrence identity and propagation work, so any favorable correctness finding still needs full costs.

Use two competing requests for f(a) and f(b), both request orders, both descriptor orders, no alias repair or repair of either request's input to a fresh equivalent node, and zero/one/two tokens. This gives36 source configurations and72 encoding configurations. Each executes under compiled Scan and Indexed (144 complete runs). Independently execute both the ordinary source and encoded rules with the scalar evaluator. Compare decoded complete outputs and residual multiplicities, not just the winner. Check local handles against ordinary source as the already available alternative. Require each encoded execution to agree with its own independent scalar trace. Use complete exhaustion and a200,000-step bound; no elapsed-time or memory comparison.

Hypotheses: prioritizing the request removes descriptor-order sensitivity when no repair occurs; remove/repost repair can still alter source-request priority when only one token exists. Zero/two-token cases control absence of competition. Assert exact source outcomes and exact contrary encoded outcomes, including aliases and residuals. Record whether repair actually runs before consumption and whether only the representation's occurrence order explains disagreement.

Run the targeted test twice, then the containing constructor test suite and strict scoped Clippy. Preserve commands, logs and source hashes. Bound each test process to60seconds wall/CPU and1GiB address space; builds may use300seconds without the runtime address-space cap. A failure or cutoff requires diagnosis. This is a correctness/selection attribution package, not evidence rejecting CHR integration. If repair order remains consequential, preserving source priority requires stable source provenance and an eligible-application selection protocol, or a separately specified scheduling contract. Charge that obligation in the subsequent common-source comparison. Intermediate joins remain the strongest ready distinct alternative at the next package boundary.
