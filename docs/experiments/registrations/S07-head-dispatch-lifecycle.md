# Registered head-dispatch lifecycle pilot

Registered before comparative execution. Compare actual unary discovery elimination with source checking and admission, preserving mixed-source local inference. H1: avoided query buckets, known-tuple keys and discovery jobs repay the prepared dispatch map on repeated or larger unary work. H2: empty/small sources and wide prepared maps expose preparation costs. H3: checked and required valid declarations have the same runtime ownership as inference. H4: mixed sources retain general join costs while benefiting locally. No restriction is adopted.

Seven source families: history (16n propagation occurrences), chain (16n consuming successor steps plus terminal), wide (0/4/32 distinct unary rule predicates at n=0/1/3, one query occurrence each), choices (n independent unary choices), mixed_same (n unary p(a) and consuming p(b)/q joins sharing predicate p), and existing broad independent/delayed sources. n=0/1/3, preparation reuse=1/4, consumers=query/prepared. Query tags, atom names and output variable identities vary across reuse. The small unary encodings do not generalize the earlier bundled-resource reformulation.

Every family has five controls: feature-off general filtered conditional, feature-on general filtered conditional, feature-on inferred, feature-on Scan and feature-on contextual resumable. The four unary families additionally have feature-on optional declared and required declared modes. This gives 516 cells. Mixed declared sources and missing required declarations are semantic rejection cases established separately in the head-dispatch source gate; they are not timed as successful zero-work cells.

Build release with no default features, experiment, selective-discovery, equality-invalidation; on builds add head-dispatch. Meter builds add alloc-meter; ordinary timing builds do not. All engine/kernel/local-work counters are disabled. General feature-on/off controls distinguish representation overhead from inferred execution. Use the audited join lifecycle phase structure: preparation (including inference/checking and map construction), input, setup, first and remaining delivery, query/search/answer disposal, three independent cancellations after 1/64/256 service calls, prepared disposal and final retained-answer disposal.
