# Reserved-token selection: work and lifecycle pilot

Test whether one reserved token removes the multiplicative eligibility discovery caused by identical source tokens, and whether the complete cost improves. Existing ordinary/local and unreserved CHR controls remain in the comparison. This registration precedes comparative lifecycle runs; the independent source/work exploration and correctness tests already exist and are explicitly exploratory.

## Mechanism and predictions

Open a selection round only with a ready request witness, removing one token and the epoch and posting one round marker. Discover eligible candidates against that marker without a token head. Retain the existing pruning and epoch renewal at commit. The token is reserved until the selected request commits; no other source operation interleaves in this fragment. Completed encoded answers must have the ordinary epoch and no unfinished round, using the unchanged decoder.

The predicted flat-size-six discovery count is 21 instead of 91, with zero duplicate candidate absorptions and six extra round openings. This removes the token multiplicity factor, not repeated discovery across rounds. Sparse and one-token competition cases supply low/no-saving controls. Equality-enabled chains and reordered requests challenge readiness and stable priority. Persistent eligibility, cheaper precedence, ancestry and richer bodies remain distinct investigations.

## Accounting and interpretation

Use release builds, default features disabled. Ordinary primary has neither allocation nor work counters. Allocation and work builds/runs are separate; metered/work clock fields are not primary evidence. Freeze code archive, binaries, exact ordered jobs and feature receipts before comparisons. The host CPU clock is an additional timer, not a work diagnostic; primary comparisons use wall intervals.

Charge source creation, preparation, input construction, source encoding, engine setup, complete execution, owned observation/decoding, consumer action and all disposal. Independent expected answers, validation and preallocated recording buffers are outside intervals. Outputs must remain valid after source/engine/preparation disposal; final requested-live heap must restore and consecutive heap phases must agree. Requested heap is not RSS. Source-builder overhead is charged as implemented. Compilation/artifacts, process startup, clock reads outside wall intervals and sustained ownership remain outside the claim.

Analyze median paired complete-session ratios for reserved versus corresponding unreserved controls and each ordinary/local competitor. Report every control; do not invent weights or a universal winner. Attribute changes using exact allocation repeats, phase totals and independently executed source-rule counts. Match trace application totals with compiled-work totals. Five samples are exploratory; no confidence or policy selection follows. Flag comparisons if either cell has any total below 100 × largest calibrated empty wall-interval median × number of phases. Preserve signal-limited cases without classifying reliable gains.

Pin children to available CPU 0; 60 seconds wall/CPU, 1 GiB address space, 2,000,000 service calls per lifecycle query. Source tests retain their 200,000 service bound. Campaign limit 30 minutes excluding builds; retain partial receipts on obstruction. More resources require a recorded diagnostic justification before extension.
