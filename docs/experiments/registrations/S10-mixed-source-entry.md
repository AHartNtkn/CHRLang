# S10 mixed-source entry gate

Before running the new gate, compare three existing organizations: conventional compiled Scan, contextual relational execution (ordinary, shared deductions, persistent equality with/without sharing), and direct conditional execution. Reuse prepared rules across 16 changing queries per source variant. No new baseline or timing comparison is introduced.

The mixed source combines a kept permit, propagation history, two-head consumption, constructor matching, equality guards, late payload aliases, explicit choice, duplicate alternatives and local failure. Vary duplicate choices, failed second arm, extra resource multiplicity and query occurrence order independently. Two source variants place the propagation rule before/after the other rules: 32 configurations total. Independently construct every complete output and residual multiset, including their joint fresh-variable aliases. Check the scalar source oracle against these expectations, then each candidate against those same expectations. Do not require identical internal traces or microstep counts.

Bound each finite run to 200000 service calls; a cutoff fails qualification and is not exhaustion. Run default and counter-free configurations and scoped Clippy. These are semantic tests, not cost samples. A failure requires a minimized witness and root-cause investigation before comparison continues.

This gate does not establish general confluence, finite-sibling progress, lowering composition, sustained ownership or complete architecture costs. Those remain T078 obligations. Its decision is whether mixed matching/equality/search/resource semantics permit these candidates to proceed to the next composition gate.
