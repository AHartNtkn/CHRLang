# Cross-query answer ownership allocation gate

Compare sustained consumer ownership across eight changing queries using one prepared ruleset. H1: query-owned state releases independently of retained answers. H2: equivalent complete owned answers can have materially different retained heap costs across execution organizations. This allocation-only gate attributes owners; it makes no timing or architectural superiority claim.

Use the existing independently checked stream schema with resource consumption enabled, work=4 and payload=8. Primary cells cross conditional/inferred-unary/Scan/resumable execution, aliases/distinct outputs, depths 16/64, immediate release/window-four/retain-all, and successful/explicitly failing terminal branches: 96 cells. Twelve cancellation cells use aliases, depth64, successful terminal and every mode/consumer, interrupting query zero after four answers; later queries complete. Each process runs depths n through n+7 and alternates input order. Unlike the earlier stream pilot, consumer answers survive across query-engine boundaries. Two allocation processes per cell give 216 total, shuffled seed7860.

Build release with no defaults and experiment,alloc-meter,serial-body-accounting,head-dispatch,equality-invalidation. Both conditional variants use the serial improvement; prefix joins are not enabled in this attribution. Freeze source, registration, driver, toolchain and binary before execution. Each process has 1GiB address space, 120 CPU seconds, 150 wall seconds and 2,000,000 service calls per query. A cutoff is an unfinished cell requiring diagnosis, never a measured loss. No comparative timing run is authorized by this registration.

Before measured ownership exists, validate every complete query against the independent scalar source evaluator and analytical expected answers, including joint aliases and raw multiplicity. Preserve those answers across engine and prepared disposal and check them again. Measured runs retain only the specified consumer's answers. Preallocate identical queue/snapshot capacity for every consumer at a given depth, outside the owner baseline. Include preparation, input/setup, delivery, consumer eviction and engine/prepared disposal in cumulative allocation readings. Record common answer counts, exhaustion/cancellation and every engine disposal.

The difference immediately before/after engine disposal attributes its remaining requested-live memory without conflating retained answers. With engines disposed, excess over the prepared baseline belongs to retained answers; require it to be zero for immediate release. Consumer release after query eight must restore the prepared baseline; prepared disposal must restore the root baseline. Check exact allocation replay and engine-disposal deltas across all three consumer policies. Report requested heap bytes, not RSS. Keep terminal failure and cancellation distinct. Native compilation, independent validation, process startup and fixed harness buffers are excluded; no complete lifecycle speed claim follows.

Selection: this boundary extends the established stream gate to strengthened conditional and resumable paths and consumer retention across changing queries. It can change observation representation and ownership responsibilities directly. Stronger non-overlap/effect certificates remain the ready alternative requiring a new beneficiary; reconsider that comparison after this owner gate, before timing or reclamation changes.
