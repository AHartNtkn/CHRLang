# R01 cost measurement design

Measure the prepared, indexed execution paths without hot diagnostic counters, then collect physical-work and allocation evidence separately. This document fixes measurement responsibilities and interpretation. It is not the final executable run registry: source freeze, runner commands and environment still need to be attached before any comparative run.

## Question and contrasts

The question is whether generated execution and local activation earn their preparation, access maintenance and lifetime costs after obvious lookup work is addressed. Compare generic/generated execution, global/active policy and scanned/indexed access as separate factors. Within one policy, access and code form must preserve selected applications; across policies, the main cost cases have independent confluent observations.

Use recursive construction, selective flat-key chains, delayed-grounding chains, large equal-key buckets and low-yield binding repairs. Flat keys separate store size from key depth; structured keys remain a distinct later contrast when normalization cost can change interpretation. A fixture must actually exercise its claimed operation: an equal-valued Cartesian join is not a keyed-bucket probe.

The first sizing pilot should use small and moderate runtime sizes, cold preparation and actual reuse across changed queries. Exact sizes, repeat counts, process bounds and query sequence must be registered with the frozen runner. Pilot findings are exploratory. They choose sufficient duration and a decision-relevant range, not favorable cases to report as confirmatory evidence.

## Phase ownership

Start from an owned source ruleset and query AST; the project has no measured text parser. Fixture construction and validation are outside execution timing and are reported as harness work. Measure ruleset preparation, per-query lowering/setup, bounded execution to trustworthy completion, full observation, engine destruction and prepared-program destruction separately. Also record their complete request total so small phase noise cannot determine the ranking.

Reused preparation means multiple genuinely started queries over the same immutable prepared object. Their bindings, occurrence IDs, histories, queues and answers remain independent. Retaining a prepared object without issuing further queries is not amortization evidence. Timed observation is the actual first export; do not estimate it by subtracting a second warm inspection. Correctness checks occur outside the timed intervals, while source computation and answer materialization stay inside.

Native source generation and native compilation are separate preparation costs. The current bundled build is not yet a measurement of independently compiling one new user ruleset. Record that limit; no compilation break-even or total cold architecture recommendation is justified until the compilation unit and reusable runtime boundary are measured credibly. An execution advantage can guide the next comparison without pretending this cost is zero.

## Instrumentation and memory

Use a compile-time configuration to disable diagnostic updates throughout the compiled engine and its shared term/map kernel. Disabling only generic-template counters leaves other representation-dependent increments in the timed path. Preserve changed-variable reporting: it drives activation and is semantic work. Retention observations must come from real collections or explicitly retained gauges, not zeroed counters.

Keep the ordinary instrumented configuration for semantic/counter tests and physical-work receipts. Validate full answers and cutoff/resume with counters off as well. Capture the resolved dependency feature graph in isolated package builds; Cargo feature unification can otherwise enable counters through another consumer. Shared source included by other experimental crates must retain its owner-selected accounting policy.

Primary timing uses the ordinary allocator. A separate allocation-metered build/process records requested live/peak heap bytes and allocation counts at the same phase boundaries. These are allocator requests, not resident memory. Record RSS separately when a claim concerns resident memory. Keep prepared data, per-query engine state, source ASTs and exported answers distinct in both baseline and retention readings. Charge their actual disposal and detect unexpected retention between repeated queries.

A paired counted/uncounted pilot can reveal instrumentation-sensitive rankings. It cannot supply a universal subtraction factor because counters can alter generated instructions and optimization. Likewise, allocation-metered timing cannot replace ordinary-allocator timing.

## Evidence and interpretation

Freeze source and generated artifacts, compiler/options, resolved features, workload registry, scheduling policy, processor affinity where available, execution bounds and per-process timeout. Preserve every cutoff and failure with its status. A budget exhaustion is incomplete execution, not a source refutation or a timing sample for a completed answer.

Use isolated processes and a registered randomized order. Measure clock/harness overhead and select adequate sample duration without subtracting a speculative fixed overhead from individual cells. Confirm exact non-time results separately. Report per-regime distributions and paired contrasts; do not invent workload weights, combine unlike counters into a cost score, or select a universal winner through averaging.

If indexing removes most of an apparent activation advantage, shift attention from global scans to activation overhead and representation. If generated code still wins on competent indexed paths, inspect whether execution savings plausibly repay its actual preparation before adopting it. If normalization, storage or extraction dominates, prioritize that consequential boundary instead of further compiler tuning. An unselective or cold regime favoring scanning/interpreting is positive architectural evidence.

The next cost registration is eligible only once the APIs, instrumentation configurations and semantic controls above are verified. R02 representation work remains independent; this protocol supplies a credible dedicated-path comparison without prescribing the integrated candidate's organization.
