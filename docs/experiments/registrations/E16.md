# E16 — parallel execution

## First gate: owned equality requests with FIFO source commits

This is a semantic gate, not a timing comparison. It tests whether pure finite-tree
equations from distinct explicit-choice branches can execute on workers while one
owner preserves the existing FIFO source execution. The [entry analysis](../../goals/chr-experiments/notes/T016-parallel-entry.md)
identifies the validated E12 integration and the independent certified-region route.
Neither route depends on E15 active sharing. This first gate adopts no production
rule order, worker architecture or language restriction.

Keep the persistent Machine, its Rc cursors, arena, commits and exact AnswerSet on
the owner. Workers receive owned resolved operands and return the existing owned
direct service's complete substitution or unification failure. They do not run source
rules, mutate a caller environment, allocate source variables or observe answers.
Worker/channel failure is an execution error, never logical failure.

The request channel has capacity equal to the outstanding limit; the reply channel
has one slot. Reservations bound all queued, running and completed requests, so a
new submission batch fits the request channel even while workers wait to send replies.
The prefix shutdown test leaves two replies to drain, exceeding reply capacity and
making drain-before-join necessary. These are experimental transport settings.
The owner-buffered peak counts accepted replies only; responses in the channel or
blocked sends remain covered by the outstanding bound, not that peak. Neither is a
byte-storage measurement.

Maintain frontier entries in their ordinary FIFO positions. Bounded lookahead may
export only the equation already pending in an entry; it cannot execute an ordinary
source step, expose a future choice, or issue a second equation from that branch.
Commit only the front entry, waiting for its result when necessary. Append Continue
and Split successors in the existing order and retain ordinary failure/answer handling.
This preserves a comparison selector while allowing service completion out of order.
It deliberately retains head-of-line blocking; completion-order search is separate.

Count issued but uncommitted requests against the outstanding limit, including
completed buffered results. Each request has a unique ID and a fixed caller. Reject
unknown or duplicate replies. Receiving a reply does not commit a source transition.
Exhaustion requires an empty frontier and no uncommitted requests/results. On a finite
prefix stop, stop issuance and close request producers. Finish every accepted request,
draining responses before joining workers so a bounded result channel cannot deadlock
shutdown. Then release parked cursors/results. Account for speculative work and buffered
results; no result drained after the prefix stop commits a source continuation.

## Controls and cases

Retain the existing Shared arena and Owned sequential searches. Compare a new inline
lookahead driver with the identical controller using one and two real workers.
For each new driver use outstanding limits 1 and 4, and a lookahead bound of 8
frontier visits per owner scheduling action. An action performs one lookahead pass
before attempting one committed source transition. Receiving replies while waiting
does not start another lookahead pass. These eight configurations over all
64 E00 cases give 512 case/configuration observations. Use each fixture's existing
source-step budget and exhausted/prefix contract; worker activity does not consume
or extend a source-step budget. Keep the reference implementation independent.

Require complete exhausted answers, residuals, alias relationships, raw completions,
failures and exhaustion to agree with independent expectations/reference. For fixed
FIFO prefixes, also compare committed source-step counts and answer sequence under
exact equivalence with Owned. Do not require identical internal variable representatives.
Machine::pending_equation exports operands and charges dereferences in Machine statistics;
speculative export can therefore increase that field at a fixed committed prefix.
Report projection/lookahead and speculative work separately, without requiring the
whole Machine statistics record to equal Owned. Run exact semantic and deterministic
counter replay: fixed passes and reservations retained until commit should preserve
issued requests and aggregate solver work. Completion order, receive waits, worker
assignment, per-worker work and buffered-result peaks may vary and must be retained
as such. Forced interleavings supply reproducible protocol evidence independent of
OS scheduling. The threaded matrix records worker IDs and completion order using
an after-solve diagnostic hook. This instrumentation supplies semantic evidence
only and must not be carried into uninstrumented timing runs.

Focused tests must force reverse completion while holding the first reply, distinguish
receipt from commit, and show the outstanding limit still holds with buffered replies.
Test two alternatives binding a pre-split variable differently, dependent equations
within one branch, constructor/guard wakeup with external aliases, occurs failure,
constructor mismatch beside success, duplicate branch multiplicity, unknown/duplicate
delivery, and an entirely parked frontier that is not exhausted. Verify that the
threaded path executes the same controller as the forced-order and inline paths.
Demonstrate two simultaneous outstanding requests and, separately, use a synchronization
barrier around the real solver in the production worker loop to prove that two workers
can enter service before either completes. Queued requests alone would not detect a
receiver mutex accidentally held throughout solving. Do not use timing sleeps as
the concurrency witness.
Report these focused tests separately from the 512-case matrix; observation agreement
alone would also pass for an accidentally serialized implementation.

Bound each full gate subprocess to 300 seconds and 1 GiB where the host permits;
record actual host/toolchain and limits before running. A bound violation requires
investigation, not a semantic failure result or closure. No elapsed-time ranking
from these correctness runs will support a performance claim.

## Interpretation and next dependency

Passing establishes this ownership/commit protocol on the tested cases. It does not
establish useful speedup, bounded-service fairness, whole-branch parallelism, shared
store commits, or intra-branch independence. Atomic source matching, unification and
observation remain explicit fairness limitations. These are feasible follow-ups.

Before a cost comparison, run an exploratory resource pilot and freeze a separate
matrix with explicit-OR frontier width, equation size and skew. Include cheap identity,
unique equations, failures, allocation-heavy inputs, single-chain no-parallelism
controls and intended applications. Charge lookahead, projection, transport, buffering,
installation, observation, worker startup/shutdown and retained memory. Preserve the
Shared control: E12 found that the owned interface can lose substantially to it, so
recovering part of that penalty is not sufficient evidence for a project speedup.
Use ordinary System allocation for uninstrumented timing and separate global-allocator
metering runs; the existing atomic allocation counters would add worker contention.
Read/reset phase counters only at quiescent boundaries. Heap-request counters omit
OS thread stacks and other non-Rust allocations; pair them with recorded stack
configuration and process memory for whole-worker storage claims.
