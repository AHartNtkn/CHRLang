# Discover awaited equalities without hiding notification work

T072 compares endpoint subscriptions, event filtering and indexed awaited value pairs. This is a diagnostic source/work gate, not primary timing. The previous four-package review selected this causal comparison because 64 unresolved requests incurred 4,160 inspections under irrelevant aliases. Broader integrated source execution, dynamic reunion and elimination remain required.

## Mechanisms and hypotheses

Endpoint subscriptions notify every request attached to either merging class. Filtering visits those same notifications but only reinspects a request when its blocked pair becomes identical or both sides have descriptors. Pair indexing records the actual awaited class pair and reverse incident relations, so an unrelated class merged into a stable endpoint need not enumerate that endpoint's requests.

H1: filtering reduces full inspections but retains broad notification discovery. H2: pair indexing can avoid that discovery when a high-degree endpoint survives. H3: moving a high-degree endpoint, supplying descriptors, coalescing relations and deleting subscriptions charge real index maintenance and can offset the gain. No counter alone decides total efficiency.

Preserve constructor-only notification behavior from the preceding repair. Matching remains nonbinding. A blocked structural equality observes its first unresolved descendant pair, not only its outer constructors. Identity or two known descriptors cause reevaluation; established equality is monotone until branch failure. Pending equations settle before consuming tokens, and ready request order remains unchanged.

## Interpretation and next boundary

If filtering only moves work into notification checks, say so. If indexing avoids the intended scans but relocates relationships, preserve both regimes and inspect any consequential accounting omission. A semantic failure requires repair, not a weaker notification contract. A successful source/work gate removes a comparison confound; it does not establish architecture superiority.

At this boundary select broader integrated consuming-source support or complete lifecycle comparison against the strongest ready dynamic-reunion/source-elimination alternative.
