# E06: direct distributed named-choice graph semantic gate

Status: implementation and hand examples may proceed; generated execution awaits
an exact case matrix and source freeze. No comparative timing is authorized by
this registration.

## Question and candidate boundary

Can distributed correlated choice connectors preserve joint observations and
active obligations while ordinary opaque computation remains physically shared?
In particular, can a local validity network, global compatibility observation,
and lazy invalidation each exclude failed interpretations without requiring
immediate reclamation or whole-store duplication?

The prototype is a separate graph rewriting fragment, not a service called by the
reference or persistent interpreter. Same-name connector interactions correlate
arms; distinct source births are independent. Choice and failure are internal
execution structure, unavailable to source pattern matching. First-order outputs
may contain jointly aliased free variables. An unused choice-interface port is
unconstrained and must preserve its external aliases.

A small deterministic carry/connect/filter fragment is sufficient for this first
mechanism gate. It does not establish compilation of arbitrary CHR, destructive
multihead rules, propagation histories or general unification. Those remain
explicit subsequent correspondence questions. Fresh host integers may represent
names initially; physical finite-label reuse is a separate lifetime question.

## Independent meaning and controls

The oracle evaluates original fixture syntax independently for finite assignments
to active source choice births. It observes joint output values/aliases and all
active obligations. Assignment enumeration belongs to the oracle; a runtime that
performs it must disclose and charge it, and cannot claim graph-local execution
merely because it uses graph-shaped inputs.

Source births and copied references to an existing birth must be distinguished.
Births under inactive arms do not introduce extra observable solutions. Raw
interpretations and exact distinct answers are recorded separately. Oracle
expected results must not come from the candidate's projection or reducer.

Each validity strategy must expose its own mechanism. Local wiring must include
completion/validity connections for components with no data path to outputs;
absence of encountered failure is not completion. A global checker must charge
actual compatibility and completion bookkeeping, whether scans or maintained
summaries. Lazy checking may avoid work on
known-invalid interpretations but must validate publication even when no output
traversal encounters the failed component. Physical reclamation is not required
by this gate and must not be inferred from validity success.

## Required discriminating fixtures

- Multiple interface wires from one choice produce correlated tuples only;
  identical-looking distinct births produce Cartesian combinations.
- An opaque carry chain consumes already-created distributed choice connectors
  without examining their alternatives; the first discrimination follows carry.
  This must distinguish post-choice sharing from ordinary common-prefix work.
  Include failure rejecting
  one arm early, in the middle, or late. Live interpretations retain shared work.
- A completed ground output alongside disconnected active failure has no answer;
  a failure in an inactive alternative does not poison the live answer.
- A branch with an unused port returns the corresponding unbound variable with
  its external alias intact, without exporting a padding predicate.
- Repeated dynamic invocations create fresh choices; copying an already-created
  choice preserves correlation. Branch-only creation preserves activation.
- An output-shaped intermediate graph is not published before a late failure or
  unfinished obligation is resolved.
- A disconnected loop prevents publication in its interpretation while an
  independent finite alternative receives service under bounded work quanta.
- A name remains meaningful while a continuation or interface refers to it;
  no unsafe reuse is introduced to make a bounded probe pass.

## Evidence and interpretation

Record physical rewrite work, choice interaction/distribution, created/retained
nodes, validity propagation, compatibility checks, scheduled service and answer
extraction separately. Physical node counts are not heap bytes. A smaller carry
count is evidence of shared carry computation, not a runtime speedup. Include
both high-sharing and immediate-discrimination cases; record construction and
observation rather than counting only the shared operation.

Before generated runs, append exact dimensions, seeds, per-child time/memory and
work bounds, observation milestones, and replay criteria. Freeze implementation,
oracle, fixtures, registration and runner. Retain every cutoff and discrepancy;
minimize defects and repeat the affected gate after repair. Divergence fixtures
need an explicit transition argument, not a timeout interpretation. A finite
prefix establishes bounded service observations, not universal fairness.

A passing gate supports only the stated fragment. Next useful questions include
finite-tree equality, occurrence consumption, propagation/freshness correspondence,
validity-network costs, fair collapse and graph reclamation. Failure of one
strategy does not block independent implementations of the others.
