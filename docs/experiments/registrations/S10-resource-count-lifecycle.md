# Resource-counting complete lifecycle comparison

The source gate establishes the transformation and its resource/observer/scheduling boundaries. Test whether removing common traversal work repays inference and query-transformation costs across complete execution organizations. The strongest ready alternative is conditional selective discovery; counting may remove the work that motivates it, so this comparison goes first.

Original/counted forms of compiled Scan, Indexed, inferred-specialized Scan, contextual eager/demand/shared-persistent and direct conditional: 14 modes. Families common/independent/early; choices 0/3; common depth 0/1/16; reuse 1/4; query schedules eligible/mixed. Total 1008 cells. In mixed schedules, odd-numbered queries omit permits and must fail certification; cancellation uses an odd query too. Original execution remains the selected path on rejection. Independently construct all complete observations, including suspended run terms, untouched fuel and unbound results on permit-free paths.

Two allocation processes per cell (2016), shuffled seed 7850, exact phase replay and owner checks before five ordinary-allocator timing processes per cell (5040), seed 7851. Bounds: 1 GiB address space, 60 CPU seconds, 75 wall seconds per process, 500000 service calls per finite query. Preserve failures/cutoffs and stop interpretation; do not silently reduce scope. The one debug runner check before the matrix is correctness/ownership qualification only.

Charge one source inference, reusable rule preparation, each actual input, query certification/transformation, setup, first and remaining owned-answer delivery, engine and answer disposal, transformed-query and original-input disposal. Charge cancellation input/transformation/setup/one service operation and disposal, then prepared and certificate disposal. Counting leaves rules unchanged, so both eligible and rejected queries reuse the same prepared rules. The current transformer clones an admitted query; retain and charge that artifact through execution rather than concealing its ownership. Returned answers are released per query.

Counter-free ordinary-allocator timing is separate from requested-allocation diagnostics. Delivery includes execution and observation. Native compilation, startup, source AST construction, oracle/expected-answer validation and preallocated bookkeeping remain outside measurement. Allocation is requested traffic/live bytes, not RSS. Independent expected answers and scalar results are checked outside intervals, for warm and measured queries.

Hypotheses: counting can reverse the relative value of repeated versus shared execution on substantive common depth; shallow and rejected cases can expose analysis costs; branch-specific suffixes retain real work; source specialization and discovery may still matter after counting. Deterministic allocation conclusions require exact replay and complete ownership restoration. Five-sample timing medians/ranges are exploratory, with no practical-win classification or workload weighting. A favorable eligible result does not resolve broader lowering or rejected-query/sustained-lifetime regimes. Review the strongest unresolved alternative after this package.
