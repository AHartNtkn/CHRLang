# Registered resumable contextual lifecycle pilot

Registered before comparative execution. Determine whether retained matching progress repays cursor construction, environments, invalidation and disposal. Eager and restarting-demand contextual execution are deliberate controls; existing Scan and filtered conditional execution are stronger complete-path comparisons. No new baseline engine or default policy is introduced.

## Hypotheses and matrix

H1: stable history and dense duplicate propagation can benefit from avoiding repeated offers without materializing all candidate tuples. H2: frequent equality invalidation, relevant head insertion, shallow inputs and branch cloning can offset that benefit. H3: retained answer ownership can change peak comparisons independently of cursor traffic.

Five modes: Scan, contextual eager, restarting demand, resumable, and filtered conditional. The conditional implementation uses `selective-discovery` in both allocation and time builds. Engine/kernel metrics and contextual `local-work` diagnostics must be disabled. The runner asserts diagnostic absence and the filtered build; prior separate work tests establish the mechanism.

Ten families: the seven established broad mixed sources (independent, shared, delayed, early, late, history, deep), plus stable_history, reset_history and dense. Broad sources include meaningful binding changes, relevant posted heads, source branching, consuming joins, guards and fresh results. Stable history has 16n items; reset history adds a redundant self-equality after each application; dense has 2n identical occurrences and requires all ordered distinct pairs. New source expectations are independently constructed, preserving multiplicity and query-specific atom names.

Cross n=0/1/3, prepared-source reuse=1/4 and consumers=query/prepared. Query consumers release each query's complete answers; prepared consumers retain answers across queries and release them only after the prepared source is dropped. There are 600 cells. This is bounded retention, not a sustained-lifetime study.

Two allocation processes per cell (1200), shuffled seed 7810, must replay every memory reading exactly before timing starts. Then five ordinary-allocator time processes per cell (3000), shuffled seed 7811. Total 4200 processes. Freeze source, driver, registration and two binary hashes with toolchain and order receipts.

## Bounds, lifecycle and correctness

Each process: 1 GiB address space, 60 CPU seconds, 75 wall seconds. Each complete query is limited to 500,000 public service calls. A cutoff or failed assertion stops the gate and requires diagnosis; it is not a loss or an empty answer. Do not restart a live process after an observation timeout.

Measure preparation, input construction, setup, first complete delivery/exhaustion, remaining complete delivery, search disposal, answer policy and input disposal separately. Include one-service cancellation, search/input disposal, prepared-source disposal and retained-answer disposal. Cursor frames, owned head copies, retained environments and actual invalidation/reconstruction stay within measured setup/execution/disposal. Preparation is reused across changed queries.

All warm and measured answers must match independently constructed complete observations; the independent scalar must agree outside intervals. Validate retained answers again after preparation is dropped. Query and cancellation disposal must restore the prepared-plus-consumer baseline; preparation disposal must leave exactly the consumer's retained answers; final answer disposal restores the initial baseline. Every adjacent measured phase must agree on live memory ownership.

Allocation diagnostics measure requested heap traffic/live memory, not RSS. Primary timings use the ordinary allocator with all counters off. Exclude original source AST construction before preparation, process startup, native compilation, scalar/expected validation and preallocated bookkeeping. Execution and observation remain coupled in delivery. Do not claim native-compilation-inclusive or sustained-lifetime superiority.

## Interpretation and next action

Report pointwise complete-cost traffic, peak and retained answer bytes, with phase attribution. Five time samples provide exploratory medians and ranges, not formal practical-win classifications. Do not subtract clock overhead, invent workload weights or aggregate unlike outcomes into a winner.

Investigate consequential cursor construction or invalidation costs before treating them as necessary architectural costs. The redundant-equality control identifies a conservative policy, not a proof that all equality requires restart. Any precision repair must preserve meaningful binding changes and newly enabled earlier matches.

After this pilot, compare a concrete consequential repair against support-aware conditional joining and the broader complete-architecture obligations. Review breadth: the recent declaration, filtering and cursor packages are bounded evidence, not closure of their parent directions. Further refinement requires an explicit architectural consequence relative to the strongest ready alternative.
