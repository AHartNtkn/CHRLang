# Broader mixed-source lifecycle pilot

The 42-configuration source gate qualifies seven source families and seven execution configurations using independently constructed complete answers. The next comparison tests whether their discovery/equality/search costs survive combined guards, history, alias changes, failure and output structure. The strongest ready alternative is further resumable/conditional discovery refinement; broader sources can first establish where that work changes a complete architectural decision.

## Configurations and hypotheses

Seven modes: compiled Global Scan, Global Indexed, inferred-specialized Global Scan, contextual eager, contextual restarting-demand, persistent contextual with shared deductions, and direct conditional. Seven families: independent choices, shared aliases, delayed binding/guard activation, early failure, late failure, propagation history, and depth-16 returned structure. Counts 0/1/3; prepared reuse 1/4; consumers query-release or prepared-retention. Total 588 cells.

H1: demand may avoid materialized joins but lose on retained propagation/history work. H2: shared alternatives can favor conditional or shared-equality organizations, but different failure placement and independent branches may expose their obligations. H3: consumer-retained answers can dominate memory independently of execution representation; query release must distinguish that from engine retention. No workload weighting or universal winner is assumed.

Two allocation processes per cell (1176), randomized seed 7830. Exact phase replay and all ownership baselines must pass before five ordinary-allocator timing processes per cell (2940), seed 7831. Per process: 1 GiB address space, 60 CPU seconds, 75 wall seconds; 200000 service calls per finite query. Save any cutoff/error and stop the comparison rather than treating it as exhaustion. The single debug conditional/history/3/4/retention run before registration checks runner ownership only.

## Lifecycle and controls

Prepare source once. For each changing query, charge input construction, query setup, first delivered answer or exhaustion, remaining answer delivery, engine disposal, answer-policy action and input disposal. Then charge cancellation input/setup/one service operation/disposal, prepared disposal and retained-answer disposal. Prepared-retention holds answers through subsequent queries and prepared disposal, revalidating them afterward; query-release drops answers after each complete query. Both use the same owned full-answer endpoint. This is finite reuse retention, not a sustained-stream memory theorem.

Engine and kernel counters are disabled. Allocation is requested heap traffic/live memory, not RSS. Timing uses the ordinary allocator in a separate frozen release binary; allocation timings are diagnostic only. APIs couple execution and observation, so delivery includes both. Native compilation, process startup, source AST construction, scalar and expected-answer construction/validation, and preallocated measurement bookkeeping are excluded. There is no lowering in this pilot, hence no inference/certification phase. Specialization's runtime preparation is charged.

Each process checks its warm and measured batches against independently constructed full observations, and checks the scalar against those expectations outside intervals. Returned residual multiplicity and aliases participate. Freeze source/binary hashes and toolchain before running. Only independently audited per-cell traffic/peak differences are deterministic findings. Report timing medians/ranges as exploratory; five samples do not justify practical-win classifications. Investigate consequential contrary results before interpreting architecture or selecting follow-up work.
