# Size complete continuation-reuse costs against competent controls

The generalized source gate establishes useful renaming and dead-history projection, but not total efficiency. This pilot measures whether key construction, retained transitions and raw answer replay overwhelm saved execution. It precedes confirmatory inference and is selected over sustained observation because the mechanism now has independent semantic evidence and a ready complete comparison.

## Configurations and contract

Use `continuation_cost` with seven modes: Direct, ExactIds, Alpha, AlphaLive, compiled Scan, inferred specialization with Scan, and direct demand graph execution. Mode strings are `direct`, `exact`, `alpha`, `live`, `scan`, `sealed`, `dependencies`. Four sources each make four alternative calls followed by a recursive countdown and complete owned box output: identical future arguments (`exact`), renamed unknowns (`rename`), different amounts of temporary consumed history (`history`), and different ground arguments (`distinct`). Temporary calls explicitly return an unused unit, permitting the graph control to execute the same source. This source differs from the prior history witness; no claim relies on its earlier step counts.

Cross depth 0/16/64, one/four changed queries, token consumption absent/present and both starting query orders: 96 source configurations, 672 engine cells. Changed queries alternate depth n/n+1 and order. Resource cases add a finishing consumer and token; all four raw outcomes remain. Prepared rules are reused across queries; each query owns its tables and graph. Complete raw owned answers are the measurement contract; unique presentation is outside all measured engines.

Before timing, the independent scalar gate checks all seven modes over four families, resource absence/presence, depths 0/1/8 and both orders, including cancellation. During each process, independent scalar expected answers for both changed queries are computed before primary intervals; complete outputs, aliases and residual multiplicity are checked outside those intervals. Cancelled outputs must form a valid submultiset.

## Runs and bounds

Freeze current source files, binaries, compiler, driver, registration and configurations. Build ordinary with `cargo build -p chr-reuse --release --no-default-features --example continuation_cost`; meter with the same command plus `--features alloc-meter`. Engine, kernel, observer and reuse-wrapper diagnostic counters must be disabled. Meter self-check must pass; requested allocations are not RSS. No meter elapsed-time speed claims.

Run two meter repetitions of all 672 cells first, requiring exact allocation replay. Run one exploratory ordinary timing per cell, shuffled with seed 7811. Cancellation uses rename/depth16/two queries/resources/forward at zero/one ticks, all seven modes and both allocator builds: 28 processes. Total 2,044 processes plus meter self-check. Pin each process to the first available CPU; enforce 60 seconds wall/CPU, 1 GiB address space and the existing two-million-step service/scalar bound. Preserve and investigate cutoffs and failures; do not restart a live process.

Primary cost includes source-rule preparation, query setup, execution with complete raw observation, engine/answer disposal and prepared disposal. Source and input construction are separate and available for an inclusive total; record first observation, phase timings, requested traffic and peak requested growth. Native compilation is excluded. Query and prepared ownership must return to their recorded requested-live baselines after disposal.

## Interpretation and follow-through

This is sizing: no significance intervals, practical gain/loss classification or universal ranking from single timings. Retain all configurations. Investigate consequential key serialization, history scans, answer copies and retained transitions before treating a loss as intrinsic. Favorable execution counts cannot compensate for unmeasured lifecycle obligations.

After sizing, register paired confirmation against the strongest applicable controls, preserving adverse cases. Inspect whether a stable key representation, justified projection or replay ownership change could reverse a decision; do not blindly polish the current prototype. Call-level reuse, broader relevance, eviction and sustained query lifetimes remain separate investigations. Reconsider sustained S08 and distinct S02 integration at the next package boundary. T075 and the architecture goal remain active.
