# Prepared prefix ownership comparison

Registered before comparative execution, following the independent prepared-prefix source gate.

**Hypotheses.** Reusing unchanged query tables can reduce repeated admission allocations, but copying the prepared engine and retaining its store can erase that saving or raise peak ownership. Changing right tables and cancellation challenge amortization. Probe and ordinary execution may differ after admission is included; neither receives automatic preference.

Use the existing `probe_lifecycle` runner and its allocator, answer oracle and lifecycle phases. Its optional final mode selects fresh or reused table-first query construction through the already-qualified APIs. Fresh constructs all tables for each query; reuse constructs the stable prefix once, clones it at start and constructs only the changing suffix. Selective/neutral reuse both tables; duplicate/broad reuse left only. Prefix construction and all copying are charged, not supplied free by the harness.
