# E12 exact reuse

Status: first implementation gates. No comparative timing matrix is frozen yet.
The three mechanisms below are separate investigations; a poor result for one
will not close the others. Reference code remains independent.

## Exact equation-operation table

An operation receives the two fully resolved finite terms of an equation that is
actually being executed. Canonicalize free variables jointly across the ordered
pair, preserving all aliases. Cache failure or the most-general substitution for
all input holes. A hit renames the result into the current caller's holes; it
must not bind a fresh unrelated variable, ground a hole, or reuse a result for a
stronger input without checking that input. This operation does not cache whole
CHR calls, change rule scheduling, or prune a context where the equation was not
posted. The caller must apply returned bindings to its shared environment and
perform ordinary wake-ups. Host integration is a separate obligation.

First validate the table against an independent unifier on exhaustive small
finite operands, caller renamings, repeated holes, stronger inputs, constructor
clashes and late occurs failure. Include multiple callers sharing a table, with
no shared mutable substitution. Controls must distinguish a cold miss, repeated
alpha-equivalent calls, structurally distinct calls, and copies sharing physical
identity. Count key construction and replay as well as avoided pair/occurs work.
Freeze performance workloads, repetitions and resource limits after correctness;
an easy copying reference alone is not a sufficient performance comparison.

## Whole-state reconvergence

Implement an exact conservative continuation key retaining pending work order,
output roots, resolved live occurrences, occurrence order under the fixed policy,
aliases and relevant propagation tokens. Begin with exact IDs/counters if needed
as a conservative baseline, then test alpha-renaming as a separate ablation.
Keep derivation lineage/multiplicity even when the continuation is evaluated once.
Duplicate future OR must produce children for each represented lineage. Equal
answers are never used as state keys. Test near matches differing in a token,
resource multiplicity, alias, pending goal or ordering before measuring merging.

## Finite failure certificates

Generate finite constructor-clash and occurs-path evidence from a posted equation
and its binding dependencies. Verify the certificate independently. Reuse is
conditional on the assumptions and committed source event that caused the
operation; matching printed arguments alone cannot prune another branch.
Compare no learning with exact certificates before investigating assumption
minimization. A context with an unexecuted or differently selected event is an
adverse case, not an allowed cache hit.

## Applications and remaining obligations

After operation gates, exercise reuse in relational arithmetic, SK evaluation and
type/synthesis workloads, counting hits that avoid actual work. Full-state and
failure probes need resource/history examples as well as isolated equations.
Generalized call tables, caller filtering, entailment, retained storage, cache
lifetime and source wake-ups remain explicit follow-ups. The E10 structural memo
measurements supply context but do not establish any of these reuse mechanisms.

## Equation-table gate result

`research/chr-reuse` implements independent direct and alpha-canonical operation
modes over owned finite terms. Five tests pass. The exhaustive test covers all
576 ordered pairs from 24 small terms, each in two caller namespaces, comparing
both modes with independent reference observations. Adverse tests separate repeated
holes, stronger inputs and a late occurs cycle. Key and result-replay traversals
are explicit counters; complete allocation, map comparison and host wake-up costs
are not yet measured. The current direct service resolves owned trees eagerly;
a credible performance matrix must account for that representation and compare
against an appropriate shared-term service before making an engine recommendation.

This is an operation correctness gate only. No E12 subdirection is closed, and
no speed or application benefit is claimed. Next work is to validate the other
reuse contracts and register measured controls, including cache lifetime and
workloads where canonicalization/replay can cost more than the avoided equation.

## Fixed-ID continuation table gate

Use the validated persistent scalar candidate as a transition service; do not
import reference internals. Add an explicit cursor/key interface to that candidate.
The first key contains resolved pending work in order, outputs, identified live
occurrences, every propagation token, and next-variable/occurrence counters.
Variable and occurrence IDs stay exact. This conservative criterion may miss
alpha-equivalent reconvergence; that is a separate ablation.

The reuse driver memoizes a state's single outgoing transition (including both
children of explicit OR), retaining a FIFO job for each derivation. A cache hit
forwards that job through the stored transition; it does not erase its lineage or
its future children. Source-step budgets count forwarded jobs as well as executed
transitions, permitting exact finite-prefix comparison with the no-table control.
This saves transition work, not automatically scheduler jobs. Terminal answers
retain raw multiplicity before full-answer deduplication. Keys and retained edges
are charged to reuse; retaining every state is an explicit storage limitation.

Validate full E00 answers, raw multiplicity, exhaustion and prefixes in both modes;
add a reconvergent explicit-OR case with another OR in its common continuation.
Test key distinctions for pending work, aliases, occurrence order/multiplicity and
history. A differing key is not itself a semantic proof; pair relevant contrasts
with independently checked future behavior. No timing comparison precedes this
gate and its cost registration.

## Next failure-certificate gate

Begin with sufficient structural certificates for an equation that is actually
next in the source pending queue. A clash certificate identifies a common child
path whose ancestors have equal constructor names/arities and whose endpoints
have incompatible constructors. An occurs certificate identifies such a pair
where one endpoint is a variable and the other contains that same variable under
at least one constructor. An independent checker inspects the current resolved
operands and paths. This permits reuse across unrelated variable names and term
content while retaining the assumptions that make the contradiction valid.

A learned path is not permission to inspect arbitrary constraints and prune them.
The source driver must establish that this equation is currently being executed;
an unposted equation or a differently selected committed event supplies no such
permission. Test that boundary explicitly. Charge lookup and certificate checking
to reuse. Discovery on a failed equation is also charged.

These initial certificates do not cover a cycle that becomes apparent only after
several equation-pair bindings, such as p(X,Y)=p(Y,f(X)). That case remains normal
finite-tree unification unless a richer, independently checked dependency witness
is available. Investigate that richer witness separately rather than calling the
restricted certificate generator complete. Operation tables and their comparative
costs remain independent of certificate implementation.

## Structural failure-learning comparison (frozen before runs)

The independent checker passes 91 path-certificate templates over 576 operand
pairs (52,416 checks against reference execution). The source driver preserves all
64 E00 observations and counts. An adverse committed-rule example learns a clash
but retains the branch where a prior consumer prevents that equation from being
posted. Structural paths are checked against current resolved operands; original
variable names and unrelated arguments are not unchecked assumptions.

Compare Direct and Learn on all 64 E00 cases plus 36 registered failure cases:
K in {0,1,4,8} duplicated explicit choices, chain depth in {0,8,64}, and early
constructor clash, late clash after a variable equality prefix, or occurs failure
after a ground prefix. Every generated case fails on all 2^K derivations, checked
independently against the reference. K0 measures a cold failure with no reuse.
Early clash challenges avoidable projection cost; late clash/occurs offer more
unification work to avoid. The source prefix and failure counts must remain equal.

Use release builds and two fresh sequential 200-run batches, seeds 1211 and 1212,
with 60 seconds per process. Charge source initialization, operand export, proof
lookup/checking, discovery on misses, ordinary unification, scheduling and full
answer extraction. Count projected equations, proof checks/nodes, discovery nodes,
learned paths/hits, executed versus logical transitions, rule firings, pair/occurs
work, allocations, requested/live storage and elapsed time. Preserve failures and
timeouts. Require exact non-time replay before interpretation. Input generation
and expected-answer validation remain outside the engine interval.

Hypothesis: proof reuse reduces equation-service work on repeated contradictions,
but eager full operand projection can dominate, especially on early clashes or
shared ground prefixes. This candidate exports owned trees; its result cannot
establish the cost of checking paths directly on the shared arena. If projection
is material, that more selective interface is a concrete follow-up, not grounds
for rejecting learned failure. Certificates requiring intermediate bindings also
remain open. No generalized branch pruning or arbitrary CHR nogood claim follows.

### Operand-order coverage correction

The initial batch and exact replay complete, but counters show the intended late
clash uses only two pairs and the intended long occurs case only two visits per
branch. Inspection establishes that this persistent unifier pushes children in
source order and pops rightmost first. The initial operand placement therefore
does not exercise the registered long-prefix controls. Preserve v1/replay as
placement diagnostics, with no intended early/late cost conclusion.

Place the early clash in the rightmost child, the late clash to the left of its
variable prefix, and the repeated variable to the left of the ground occurs
prefix. Add exact control checks: per derivation, early uses 2 pairs, late uses
D+3 pairs, and occurs uses D+3 visits. Validate these and independent outcomes
before repeating the unchanged 200 configurations and two seeds as v2/v2-replay.
This corrects the workload's operation order without changing source or engine
semantics. Reconsider cost conclusions only from the corrected controls.

## Shared-arena path-checking follow-up

The corrected v2 matrix and replay pass all 200 configurations. At K8 D64, late
clash pair work falls from 17,152 to 67 and occurs visits from 17,152 to 67, yet
owned-projection learning has greater requested allocation and elapsed cost in
these probes. Test the representation explanation directly: keep the same learned
certificates, but inspect only the claimed paths in the persistent term arena.
Each read must dereference the current cursor's bindings and refuse an absent
next equation. On a miss, discover only after ordinary equation failure, exporting
that saved input once; successful operations need no full export in this mode.

Implement a second checker over path-to-head observations, independent of the
owned-tree checker. Compare its validity against the existing exhaustive path
