# Stronger serial control for the worker source

Before interpreting the reusable-worker pilot as an architectural opportunity, compare its sources with the existing checked carrier-contraction path. The gate accepts all four countdown predicates and validates24 complete source-product cases. It is not necessary to implement another compiler to test this question.

Use `PreparedRuleset::specialize_inferred` followed by `contract_carriers_inferred` under Global/Scan selection, and compare complete unpartitioned source execution with the existing factored inline and four-worker controls. These are whole execution organizations; do not force a product-worker interface onto the lowerer. Include an uncontracted specialized control if attribution between direct selection and contraction would change interpretation.

Match the prior balanced/skewed depths64/256, tiny control, cold/reused query lifetimes, full answers and raw multiplicity. Measure preparation, query setup, source execution/observation and complete disposal. Register exact repetitions, phase endpoints, source/binary freezes and interpretation before timing. Record allocation separately if a time result changes the current tradeoff.

This comparison is selected over marginal worker timing refinement and before generated multihead access because a ready optimization may eliminate the work responsible for the apparent parallel opportunity. A contracted-path win would narrow this worker result to an unoptimized source path; it would not reject parallelism on work that cannot be contracted. A worker win against contraction would strengthen the bounded opportunity. Either outcome materially improves the architectural interpretation at the cost of integrating an existing control.
