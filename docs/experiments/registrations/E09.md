# E09 — scheduling and finite service

E06's completed net service makes this investigation ready independently of its
remaining native/compiler refinements. Those questions stay queued and open.
Compare per-alternative FIFO, sealed symbolic rounds and asynchronous sealed jobs
on the same operations; preserve source identities independently of shared work.

## First prerequisite gate: whole-request yields

The E06 harness reduces nets in finite quanta but builds inputs and reads complete
results atomically. Expose a sealed UnificationJob whose immutable inputs are
already in the encoded backend data representation and whose rule system is
prepared once and shared read-only. Request admission allocates only fixed-size
control state. Do not hide rule compilation in each admission.

Yield on each input data node or header operation, each actual net interaction,
each stored-node validity check, and each output visit/assembly operation. Delay
reduction until the private graph is fully wired. Delay publication until both
complete outputs are materialized and no active/stuck controller remains. Keep
original-table preservation and failure privacy from E06.

The fixed data signature and rule interfaces bound explicit graph work per action.
Python allocation, dictionary resizing and garbage collection do not have a
hard wall-time bound. This gate establishes finite resumable service, not real-time
scheduling. Input/source compilation, support management, source matching and
final answer deduplication remain separate operations requiring their own accounting.

Validate the 96 existing unification workloads at quanta 1,8,64, up to 250,000
service actions each. Require complete independent expected observations and
exact per-phase work agreement across quanta and replay; record quantum-dependent
resume counts separately. Test rejection of observation throughout partial build
and readback. Interleave a small identity with a large request during both build
and read phases and require the small request to finish while the large request
remains in that phase. These are service-isolation tests, not a complete source
scheduler comparison or a general fairness proof.

## Scheduler questions retained

Implement the three policies and grouping/quantum factors after this gate. Include
divergent source siblings, large equalities and tuple scans, source wake-ups,
nested explicit choices inside shared work, partial supported completion and
duplicate-heavy observation. Charge support/selector work and observer costs;
completed supports may publish without awaiting unrelated work. A sealed round
barrier can delay the next source step even when individual services yield.

The liveness claim must state immutable finite inputs, finite operation completion,
finite predecessors, preserved queue age under splitting, a draining observer and
available storage. Different queue ordering alone cannot repair an atomic
unbounded backend normalization. Do not generalize one service's results to other
matching/observation implementations; E15 owns the required second-service check.

## Source adapter gate (before policy comparisons)

Use an independently implemented resumable direct-tree source adapter with the
same fixed committed selector as the existing controls. It is an explicit direct
service factor, not net integration. Check every continued/forked state against
the independent E11 tree interpreter, including occurrence IDs, propagation
history, pending goals, fresh variables and substitutions. Check terminal answers
against both the hand expectations and Rust reference for all 64 E00 cases.
Use source-step budgets and answer limits from those fixtures; run service quanta
1, 8 and 64 with a 2,000,000-action cap per source step. Record action counts,
source transitions, raw answers, exhaustion and exact replay. No timing superiority
claim comes from this correctness gate. An action cap failure remains a failed
validation requiring investigation, not a semantic answer.

Queries are initialized before source-step measurement; initialization and host
collection allocation must be accounted for separately in comparative runs.
Instrumented traversal/copy actions are resumable, but Python collection freezing,
hashing and permutation advancement do not have a constant wall-time guarantee.
The full residual alpha-equivalence checker is an independent validation oracle;
it is not yet the resumable final observer for policy runs.
