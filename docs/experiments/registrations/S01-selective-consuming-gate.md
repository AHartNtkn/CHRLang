# S01 selective and consuming discovery: prospective source gate

Extend the serial driver experiment with the nonbinding join left(K,f(X)), right(K,g(X)), request(K,R). The propagation variant emits receipt(R,f(X),g(X)) for each distinct pair. The consuming variant keeps left and request, consumes right, and emits the same receipt; source-order selection gives a right resource to the first eligible left. Acknowledgement follows the join rule and resumes the driver only after all eligible applications finish.

Retain request, replacement and binding instructions; add right insertion. Row values may contain unknowns. Bind instructions assign distinct variables to ground finite terms, allowing a structural match or repeated-value equality to become established. Queries are closed serial scripts; binding conflicts/rebinding and other sources are rejected by the prototype admission check, not treated as logical failures. A missing replacement leaves the original driver residual, including consumed-row cases.

Direct access must use composite (resolved key, established f/g child) indexes, not rescan a large right key bucket to rediscover available structural information. Retained additionally maintains eligible pairs and reverse incidence. Both track dependencies in keys and payloads. Consumption removes every incident pair, including pairs sharing a different kept left. Only live identified occurrences participate; equal-valued duplicates remain distinct.

Before costs, compare both modes with independent owned-syntax source execution and the existing Global Scan/Indexed controls. Vary candidate key fanout, child-value selectivity, unknown dependency breadth and update fraction independently. Include zero requests, missing matches, duplicate values, driver-first/last order, repeated requests, sparse replacement, broad binding, insertion after consumption, stale shared partners, blocked replacement and joint unknown residual/output aliases. Preserve the original all-pairs experiment as separate evidence; this source is a different architectural contrast, not a compatibility mode.

Finite bounds: 2,000,000 service/source steps and 60 seconds per process. Validate bounded resume and cancellation/reused preparation. Run default and counter-free semantics, and repeat diagnostic work counts. Record source/certificate mutation failures before a prospective lifecycle pilot. No timing result follows from this gate.
