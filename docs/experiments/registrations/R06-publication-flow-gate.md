# Publication flow-control feasibility gate

Prospective deterministic T041 service comparison, selected by [restricted-publication results](../results/R06-restricted-publication.md). This is a bounded source/service gate, not a timing or memory matrix. It asks whether strict global observation priority incurs a consequential sibling-delay tradeoff before a more invasive scheduler or reclamation design is selected.

Use actual conditional Engine execution and its actual observer. The candidate test controller gives queued certified observers service before further source work; when no observer is queued it resumes normal Engine.tick. It may use private test access to the observation-turn flag, but must not copy the evaluator/observer or expose a new production policy API. The control is ordinary interleaved Engine.tick. No persistent production scheduler change is selected by this gate.

The source witness has an explicit root OR. The bulk arm makes n independent equal-arm explicit choices then leaves a nonground `bulk(X,X)` residual with repeated-variable aliasing; the other arm makes a finite16-step countdown to a distinguishable sibling residual. Use n=0,2,4,8. The independent complete raw multiset has exactly2^n bulk answers and one `sibling()` answer, with no other residuals or outputs. Equal answers remain separate raw histories. Check both policies to exhaustion with a maximum5million ticks per case; any cap is a recorded unresolved outcome, not permission to change the case. Source syntax construction and hand counts are independent of candidate traversal.

Record the number of bulk answers preceding the sibling, source applications when the first bulk observer is queued and when it drains, whether the sibling remains runnable at that boundary, and final exact raw counts/exhaustion. For the strict-priority treatment, verify actual executor suspension while an observer remains owned and source resumption after it drains. Require a real source-generated frozen observer boundary; do not inject a synthetic ready answer or manually invent a candidate state. No nanosecond or allocator comparison is authorized by this gate.

Predictions: strict priority may retain complete answers and eventual exhaustion, yet withhold the distinct sibling until the bulk region is drained. If the interleaved control discovers the sibling while bulk work remains, this demonstrates a tradeoff governed by the region's raw multiplicity, not the implementation's fixed tick ratio as a language requirement. The n8 witness is the discriminating case; small cases check exact multiplicity and resumption without presuming a timing order.

A witnessed exponential bulk-drain dependence rejects strict global priority as an unqualified streaming improvement. It does not reject all backpressure or claim a semantic error from scheduling differences. Avoiding the delay may require attributing production to support-local continuations and preserving service for others, which exceeds a queue-length adjustment. If that ownership expansion is necessary, stop this bounded intervention and reassess mixed-phase generalization or repeated coarse-region parallelism against broader reclamation. No automatic scheduler expansion, output deduplication or bounded-memory claim follows.
