# S02 relational head plans: first semantic gate

The existing integrated engine already stores constructor descriptors and source occurrences under value identities. It still walks source Term patterns recursively after choosing occurrence candidates. The new contrast compiles all source heads and constructor patterns into one join plan: source-occurrence atoms and constructor atoms share logical slots. Ground constructor relations and bound columns may restrict the join before selecting a source occurrence. This is different from flattening a pattern into instructions that must still start at an occurrence root.

Implement the read-only head-plan boundary first. A relation view contains canonical finite-tree value identities, constructor facts and identified source-occurrence facts. Index facts by relation/signature and each value column. At each join step choose the remaining atom with the smallest available bucket; do not use a complete-store scan estimate that itself executes the query. Repeated source variables share a slot. Occurrence identities filling distinct heads must differ; identical values do not merge source resources. Keep kept/removed head positions in source order in results. Duplicate constructor proofs must not multiply source applications.

Check complete candidate tuples against an independent owned-term, exhaustive head matcher on small stores. Include partial constructor patterns with selective inner constants, unknown structure, repeated variables, equal-valued distinct occurrences, reversed arrival, multiple kept/removed heads and changed equality snapshots. Expected tuples must not be computed through relation indexes or the plan. Instrument a test-visible explanation of selected atoms to establish that a selective constructor can precede occurrence selection; do not infer speed from that capability.

This view requires canonical values for the supplied equality state. It is not yet an incremental equality implementation, source executor or context-local equality solution. Before integration, document the responsibility for canonical-key repair, congruence, finite-tree failure, source resource commits and publication. A single unqualified global canonical relation is unsound for alternatives with different equalities: contextual facts must be joined only within compatible interpretations. Separate per-context views can be a correctness control, not an assumed efficient final architecture.

Run candidate tests and strict Clippy with 60-second process bounds. No comparative timing or architectural superiority follows. The next gate must connect the plan to an actual equality/resource owner and complete source effects; do not replace that work with an admission label.
