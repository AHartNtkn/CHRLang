# E11 bounded whole-evaluator compilation

Status: implementation registration; no comparative matrix frozen yet. E11 remains independent of structural-solving results. The first correctness gate is an exact finite-handle unification circuit, followed by the complete bounded transition relation. Passing the gate does not complete the experiment.

## Selected first encoding

Use quantifier-free Boolean/integer formulas over finite slot vectors. A slot denotes a logical variable handle or a constructor with child handles; substitutions are explicit vectors. Unbound handles remain unbound in decoded results. Do not encode source unification merely as equality of freely chosen ground solver terms: that would admit arbitrary instances instead of preserving the most-general substitution.

Represent Robinson unification as bounded deterministic microsteps with an explicit pair stack, dereference, constructor comparison, binding and occurs check. A microstep limit is a distinct cutoff, never failure or success. Validate concrete finite arenas and symbolic equation operands against an independently implemented tree unifier, including aliasing, occurs failure, constructor/arity clash and an unfinished equation. This finite service will later be used inside source transitions; its cost remains separately visible.

The machine encoding must then include finite pending-goal slots, live occurrences with identities, substitution/term allocation, propagation tokens, explicit OR bits and a fixed committed first-enabled rule/tuple policy. Quiescence requires pending emptiness and the absence of an enabled unused rule instance. Only explicit OR is a semantic alternative. Failed branches cannot produce endpoints. Bound exhaustion is separate from quiescence. Canonical fresh allocation prevents arbitrary identity assignments becoming extra witnesses.

Start with vectors rather than array theory for these small fixed domains. The Z3 guide specifically recommends individual variables for small finite collections. Z3 supports incremental assertion scopes and model extraction, allowing later comparison of rebuilding against extending compatible transition prefixes. This is an experimental backend choice, not an architecture recommendation. [Z3 finite collections](https://microsoft.github.io/z3guide/programming/Z3%20Python/advanced/), [Programming Z3, §4](https://z3prover.github.io/papers/programmingz3.html).

## Required comparisons and limits

Compare bounded direct execution and symbolic compilation at identical transition, term, variable, occurrence, history, choice and service bounds. Register workloads and exact bounds before comparative runs. Include arithmetic failures, aliasing, repeated occurrence consumption, propagation history, nonground SK holes and quiescence. Inspect decoded intermediate witnesses independently, not only endpoint agreement. Measure formula construction/size, solving, model decoding, full residual observation and repeated-bound work. A reachability table built by enumerating all concrete states is only an ablation, not the factored candidate.

An increasing dominating bound sequence and incremental prefix reuse remain required after the first finite instance. Unsatisfiability at one bound establishes only bounded absence. No production language or search-order decision is made by the fixed experimental policy.

## Equality composition and witness-validation gate

The equation circuit carries substitutions through sequential equations and prevents later work after failure or cutoff. The independent direct transition checker now passes all 64 E00 cases against both registered expectations and the Rust reference (2,771 transitions), including full residual alpha equivalence, raw multiplicity and exhaustion/prefix status. A decoded-witness interface checks every supplied state and action, occurrence/history state and final quiescence; malformed-history, wrong-choice and unfinished-endpoint tests exercise rejection.

These are correctness gates, not comparative runs or a completed symbolic compiler. The copying checker retains traces for validation, so it is not a credible timing baseline without a separately registered configuration. Next implementation obligations are bounded symbolic allocation and state transitions, with decoding into this checker. Bounds and the performance matrix remain to be frozen once the complete transition encoding is validated.

## Symbolic allocation gate

The finite-slot heap now supports guarded variable/constructor allocation between equation services. Branch-dependent allocation updates both node and variable counters; a variable retains a distinct identity even when another alternative allocates additional nodes. Constructor children refer to allocated handles. Substitution edges are separate and protected by occurs checks. Inactive services do not bind or create cutoff; active allocation overflow is explicit cutoff. The fixed-arena checks use this heap implementation.

This permits a factored transition to allocate different bodies in different explicit alternatives without pre-enumerating concrete stores. It does not yet encode pending-goal selection, rule matching, history or quiescence. Those whole-machine obligations remain active before comparative measurements.
