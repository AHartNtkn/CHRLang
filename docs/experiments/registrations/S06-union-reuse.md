# Union reuse extension: test a predicted traffic crossover

The lifecycle pilot measured lower per-cycle output traffic but higher preparation for union. Its eight-coordinate overlap data predict a small requested-allocation reversal near 15 full-output queries. This extension tests that prediction and whether other costs follow it. No algorithm or source semantics change.

## Fixed contrast and controls

Use the same six modes, four families, endpoints and consumer policies as [the lifecycle registration](S06-union-lifecycle.md). Fix width eight and three names. Query counts are 14, 15 and 64: immediately before/at the predicted crossover and a longer reuse regime. Preserve the exact caller cycle and membership assignment generator. This yields 432 allocation cells; retained-all timing covers 144 cells. The initial one/eight-query results remain separate frozen evidence, not additional repeats of these cells.

Repeat every allocation cell twice (864 processes), shuffled with seed 76031. Run five exploratory ordinary timing repetitions of every retained-all cell (720 processes), shuffled with seed 76032. Pin to the lowest permitted CPU and record it. Preflight every process against independent complete answers, including first-result cancellation and prepared reuse for full output. Confirm final owned-heap restoration and surviving retained outputs. Run the existing 24 small smoke cases before the freeze. Record the toolchain before builds and five clock checks before timing.

Preserve source construction, operand preparation/union, request handling, fused execution/complete observation and all disposal/consumer phases. The allocation build has no phase clocks; the ordinary build has no allocation meter; both disable engine metrics. The original exclusions remain explicit: process/toolchain startup, oracle fixtures and fixed harness containers are outside totals. First-row latency, native compilation and arbitrary raw CHR observations are not measured.

Each process has 60 seconds wall/CPU, 1 GiB memory, and the existing one-million-tick diagram bound. Each build has 300 seconds; the matrix has 30 minutes. Retain failures and diagnose cutoffs. Exact source and binary hashes precede comparative runs. Never overwrite pilot binaries.

## Prospective predictions and analysis

For overlap/full/all at 15 queries, the pilot predicts 1,282,728 requested bytes for union versus 1,304,768 for deduplicated explicit execution, assuming unchanged five-query allocation cycles and source/preparation. Compare measured phase counts with those predictions; explain any disagreement rather than adjusting the forecast. Fourteen queries checks the nearby boundary, including its changed final caller. At 64 queries test whether larger traffic savings coexist with an adverse peak or preparation-independent runtime limit.

Require exact normalized allocation repeats. Report traffic and peak separately for every matched cell, without workload weighting. Reconstruct complete session time from phase sums; show medians and full matched-repeat ratio ranges. Apply the pilot's insufficient-signal threshold (100 times the maximum median empty-clock cost times measured interval count). Five samples remain exploratory; a ten-percent contrast selects consequential confirmation, not statistical significance or a universal winner. No outlier exclusion.

Inspect the strongest contrary controls: source deduplication on redundant alternatives, short-circuit membership, disjoint alternatives and a single branch. Attribute a consequential disagreement to preparation, output, retention or measurement before expanding the matrix.
