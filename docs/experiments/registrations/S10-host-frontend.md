# Native host frontend qualification

Test whether the existing native source emitter and numeric query encoder can consume the same complete source text as the Rust lifecycle runner without changing source meaning, prepared programs or query protocols. This supplies a missing host accounting boundary, not a comparative performance result.

Use all 22 prepared native plans (383 queries, including new symbols and cancellation) and four substantive groups (96 queries). Decode each plan's rules and changing queries from the common text protocol; compare reconstructed syntax with the independently stored source AST. Compile each ruleset once with the existing source emitter and empty initial query. Compare the emitted program byte-for-byte with its frozen qualified artifact. Encode each changed query using its recorded budget and retention flag; compare bytes and dictionaries with the existing prepared/independently reconstructed substantive protocol.

Run each newly emitted program and encoded session through the frozen ordinary native wire runner. Check answer bytes, service counts, pending status and dynamic words against the prior native wire records. Validate complete decoded observations and cancellation prefixes through those independently qualified records. Malformed source syntax must be rejected rather than silently truncated; test nested choices, empty bodies, variable identity and arity delimiters against explicit examples and the entire corpus.

Record one diagnostic frontend observation per session: common-text decoding; source emission including kernel-file reading and source dictionaries; each query encoding including query-only symbol extension; and explicit release of syntax, emitted program/protocol and dictionary owners after outside-interval validation. Python interpreter startup/imports, test construction, native process execution, validation and evidence serialization are outside these frontend intervals. This is a component accounting qualification: do not sum it into the native runtime or Rust lifecycle and claim complete costs. Reference-count disposal does not imply RSS restoration; no allocation/RSS claim is made.

No comparative repetitions or thresholds apply because no timing ordering will be interpreted. Bound each native child at 15 seconds wall and 10 CPU seconds, with the previously required 96 GiB virtual address allowance for reserved native mappings. Keep existing 65,536 service limits for common sources and 1,048,576 for substantive sources; never recategorize pending work as completed failure. Freeze scripts, emitter/kernel, inputs and native binary. After this qualification, integrate native host transport/lifetime boundaries and separate allocation diagnostics before cost registration, then reassess one pilot against broader source analysis.
