# E04 v1 — occurrence-local dispatch and cached expansion

The question is whether closed single-headed relation regions gain from local dispatch and provenance-based expansion reuse, separately. This first prototype uses whole-program eligibility; mixed general-CHR regions and their interfaces remain a required follow-up. No source-language restriction is adopted.

## Contract and controls

Accept simplification rules with exactly one removed head and no kept heads. For rules with the same predicate/arity, require a conservative constructor-disjointness certificate: at least one corresponding constructor position must differ. Potential overlap is rejected, even when guards might disambiguate it. Unknown head demands suspend without generating terms. Body OR remains the only search split. Equations are transactional finite-tree unification; guards only test entailed equality. All active constraints participate in quiescence and failure, including those disconnected from selected outputs.

Compare three modes on the same runtime: general rule/occurrence scanning; predicate-local dispatch without expansion caching; and predicate-local dispatch with caching. All three use the same contextual binding and branch-state snapshot services. The cache is keyed by source occurrence identity, selected rule, and raw matching witness. Reusing an expansion does not commit an application elsewhere: each requesting context must independently match, consume its occurrence and activate its body. Fresh variables and body occurrences belong to the expansion event; separate calls retain separate identities even with equal printed arguments. Shared pending body nodes retain their identities through OR. Cached contextual witnesses cannot be used to turn unknown constructor demands into success.

The first implementation uses separate branch binding maps and active-root maps with shared immutable work nodes. It therefore isolates event reuse while explicitly charging branch snapshot and commit work. It is not a claim that graph representation removes conditional state. It does not import the reference interpreter or its normalizer. The E14 observer and process allocation meter are common experimental measurement services.

## Semantic validation and cases

Record acceptance or rejection, with reason, for every E00 case. For accepted cases require the registered full residual answers, raw successes and finite completion/prefix behavior in all modes. Rejections are fragment coverage evidence, not failed source programs. Add direct checks for equal-but-distinct calls with fresh body variables, branch-specific constructor demand after a shared birth, alias-driven wake-up, active rejection unrelated to an output, and a newly linked multiheaded rule invalidating eligibility. Cover both cache hits and misses. Cache reuse must never merge independent invocation variables or skip a context's active work.

Use the natural carry grid k={0,1,2,4,8}, W={0,1,8,64,256}, noise={0,16,128}. Expected projected applications remain 2^k-1 + 2^k*W. On synchronized opaque carry, cached physical expansions should be k+W; local dispatch alone should not reduce physical expansions. Use E03's immediately discriminating constructor-tag family k={1,2,4}, W={1,8,64}, noise={0,16}: cached carry expansion should become branch-specific, with k+2^k*W event constructions. Include accepted arithmetic, SK evaluation, no_c and typing cases; unbounded synthesis and mixed lambda regions remain open.

## Measurements and interpretation

Before comparative runs, freeze this registration, engine, case inventory and runner in a commit. Run each accepted case/mode in a fresh release process with a 60-second bound and the registered case budget, plus a full replay. Preserve failure and timeout rows. Record source steps/applications, physical expansions, cache hits/misses and retained entries, rule/occurrence candidates, contextual binding reads, unification and occurs work, fresh variables/work nodes, snapshot entries copied, contextual commits, frontier/retained state, complete/raw answers, observation work, allocation payload and elapsed time. Allocation baseline brackets construction and execution but excludes expected-fixture preparation. Elapsed time is diagnostic; no statistical speed claim follows from a pair of runs.

Attribute a reduction from general to local mode to dispatch. Attribute a reduction from local to cached mode to provenance reuse, including cache bookkeeping and retention. Cross-engine comparisons with E01/E03 must name their storage, matching, term and service differences. Endpoint agreement does not establish whole-machine simulation or fairness of atomic services. Cache retention, mixed-region boundaries, resumable wake-up and larger synthesis remain feasible subsequent investigations regardless of this first probe's outcome.
