# Existential projection: denotation, multiplicity and caller boundary

Package one after the descriptor breadth review. Test a distinct operation absent from the current finite-path solver: eliminate hidden finite coordinates before enumerating visible assignments. This is a correctness and mechanism gate, not a cost comparison or general structural-theory implementation.

A problem has finite coordinate domains and set-valued relation filters over named coordinates. Domain lists represent independent source choices: duplicate alternatives contribute derivation multiplicity. Filter rows denote membership sets: duplicates do not contribute multiplicity. For each visible tuple, the independent oracle enumerates every full domain-choice tuple, rejects those outside any relation, and counts remaining witnesses. Logical projection returns its support; counted projection retains its integer weight. This claim applies to this source construction, not arbitrary CHR derivations or effectful hidden work.

Candidate: finite factor multiplication and elimination. Join only factors mentioning a hidden coordinate, then sum that coordinate out (Boolean support for logical projection, checked u128 arithmetic for counted projection). Keep remaining visible factors until answer observation. Test ascending and descending hidden-variable orders; these must have the same denotation, though representation costs may differ. Constraints on surviving coordinates can be added after preparation. Reject any attempt to hide a declared caller-shared coordinate or to apply a later restriction to an eliminated coordinate. This is an explicit semantic boundary, not a language restriction selected for adoption.

Independent checks: scalar full-choice enumeration with direct relation tests; existing Grammar/Search for matching flat tuple/equality sources; unchanged CHR reference for source choices, equality filters, visible answers and total completed-branch multiplicity. Source-reference output sets and raw completion counts are checked separately. No candidate projection logic enters either oracle.

Test named witnesses for collapsed hidden alternatives, hidden-mediated visible correlation, empty hidden domains, duplicate source choices versus duplicate filter rows, later visible restrictions, shared hidden identities and empty visible tuples. Add256 deterministic generated finite problems (up to six coordinates, values0..2, duplicate domain choices and unary/binary/ternary filters); use eight visible selections per problem, both semantics and both elimination orders. Require exact map equality with full enumeration. Test malformed relations, incomplete elimination orders, resource bounds and counted overflow explicitly. Preserve failing receipts and distinguish an operation cutoff from an empty denotation.

Each materialized join/observation is bounded to100,000 assignment visits and the test process to60 CPU/wall seconds and1GiB address space. Run semantic tests in default and metrics-off builds, plus applicable existing finite-path regressions. Diagnostic work may demonstrate that hidden full assignments were not enumerated; no time, allocation or whole-architecture superiority follows. Exact sizes, repetitions and full-lifecycle endpoints for subsequent comparative costs must be registered separately.

After the gate, compare representation/lifecycle qualification against adaptive costs (strongest ready alternative), native local ownership, conditional equality and broader reuse. Names, disequality, normal/neutral theories and general source projection remain separate obligations.
