This prospective exploratory pilot supplies ordinary-allocator CPU measurements alongside the completed allocation gates. It tests whether reduced enumeration, reusable candidates or exact-family elimination repay their preparation and lifecycle work. It does not select an architecture or assign formal gain/loss classifications.

Use the unchanged runner and sources at `e5a6b1d72`: five modes (lazy, reduced, enumerate, enum-reuse, lowered), six families (all, equal, selective, empty, redundant, overlap), widths 0/4/6, immediate/retained consumers and complete/first-answer cancellation. Each process executes four changing queries over one prepared owner. Run five fresh ordinary-allocator processes per cell: 360 cells and 1,800 processes. Shuffle each complete block with seeds 760901 through 760905. All cells retain all five samples, including cancellation cells; cancellation and complete enumeration are separate endpoints.

Build release with `--no-default-features`, without the allocation-meter feature. The runner rejects enabled finite-solver counters. Freeze source, binary, toolchain and host before running. Primary total sums preparation, input construction, setup, execution/owned observation, query disposal, consumer disposal and final prepared disposal. Also report the sum excluding separately recorded input construction. First-observation latency is setup plus execution through its first owned value, with preparation separate. For zero-answer queries, report first observation as absent. Immediate consumer disposal occurs inside execution/observation; retained consumer disposal has its own phase.

Each process independently validates all four full results and warms execution before the measured owner. Startup, parsing and native compilation are outside the primary endpoint; allocator state is warmed. Cap each process at 60 seconds and 1 GiB address space and retain the runner's 2,000,000-service-unit query bound. Errors or cutoffs stop the matrix for diagnosis. Validate cell/repetition coverage, phases, exact expected counts and first-observation timing bounds before analysis.
