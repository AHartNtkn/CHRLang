# Concurrent regional allocation diagnostic

Before comparative timing, test whether allocation accounting and disposal remain trustworthy with active regional concurrency and cancellation. The previous single-region witness did not establish this.

Run inline and 1/2/4 workers, source quanta 1/16, and phased versus whole-lifecycle meter windows: 16 configurations, five fresh processes each. Each process creates and disposes four runtimes. Each runtime answers five changed queries: four balanced recursive regions at depth32; cancellation after one coordinator advance with four depth128 regions; four skewed regions at depths8/16/24/32; one depth0 region; and two depth8 regions. Each completed regional countdown ends with the two alternatives `a` and `b`. Expected global products and raw counts are hand-derived, including all output coordinates.

Use existing prepared source, conservative certification, request-order admission and window4. Each completed query is bounded at 100,000 coordinator advances. Cancelled queries perform one advance and must remain unfinished, then close/drain and dispose. Later complete queries must still agree exactly. Every process has a 60-second timeout and 1 GiB address-space limit.

Initialize and record the previously attributed channel context before the runtime baseline. Record preparation, setup, execution/observation, close, session/answer disposal, shutdown and runtime disposal. The whole-lifecycle variant does not reset the peak between phases; the phased variant does, so its final whole-window peak is not interpretable. Total allocation traffic can be compared in both variants. Receipt storage is reserved before measurement; exact answer comparison uses in-place sorting without allocation. Expected answers and source templates are constructed before measurement. Their construction is outside this diagnostic's scope, not free architectural preparation.

Require complete runtime live restoration. Test repeatability by configuration, query position and phase; cancellation may perform different amounts of legitimate speculative work. Do not require its traffic to replay as if scheduling were deterministic. For completed work, inspect any phase traffic variation: bookkeeping crossing acknowledgements, transient channel operations, or variable speculative work must be distinguished from meter defects. If phase-local counts vary, use whole-lifecycle traffic for primary allocation claims, report phase ranges, or validate stronger quiescence. Peak variability from real concurrency is expected and must remain visible.

No timing hypotheses or architecture ranking are registered here. This is the last accounting screen before sizing and prospectively registering the bounded warm-worker cost comparison; a consequential defect can require a targeted repair.
