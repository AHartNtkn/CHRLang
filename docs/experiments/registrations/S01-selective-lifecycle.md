# S01 selective discovery: prospective lifecycle pilot

Compare the checked Direct composite-index lowering, Retained pair/incidence lowering, and generic Global Scan/Indexed execution of the exact same source. H1: repeated selective requests may repay retained eligibility. H2: pair construction and invalidation can dominate when requests are sparse, bindings affect many rows or consumption invalidates many pairs per receipt. Direct has the available composite index; the comparison must not manufacture its rediscovery cost by scanning right key buckets.

Eight families: stable selective and stable dense propagation; sparse and broad replacement; sparse and broad binding; selective and dense consumption. All rows use one common key. Selective left children are distinct v0..v(N−1), and every right child is v0. Dense left/right children are all v0. Replacement families use selective rows and change one/all right children between v0 and v1 before each request. Binding families start one/all left children at shared unknown X (other children distinct nonmatching values), first request before binding, then bind X=v0 and execute the requested rounds. Consuming families replenish N right rows between rounds, so repeated requests perform real new resource work. These are separate mechanism probes, not weights.

Each process uses one fixed prepared ruleset over eight queries: (N,R)=(4,1),(4,8),(8,1),(8,8), repeated twice. Four matching warmup queries precede measured preparation. Complete expected answers come from the independent owned-syntax scalar evaluator, outside measured intervals, and are checked after every query. The earlier mathematical/resource witnesses remain correctness evidence. Preparation is reused across changed queries; fresh query input clones are outside setup.

Measure preparation, setup, execution, observation, engine disposal, answer disposal and prepared disposal separately. These APIs expose no answer before completion; first observation is the final answer, and setup-to-first latency can be derived without summing observation twice. Charge retained initialization and all driver updates. Source creation, query AST construction/cloning, oracle checks, native compilation and process startup are excluded. This is not a complete cold-compilation or universal architecture claim. Work counts and allocator diagnostics must not contaminate primary timing.

Thirty-two cells × five timing and two allocation repetitions = 224 isolated processes. Randomized cell order within repetitions, seed 20260911, lowest permitted CPU fixed and recorded. Counter-free release timing uses the ordinary allocator; allocation diagnostics use a separate metered build and report requested heap traffic, not RSS. Freeze source, binaries, toolchain and order before comparison. Each process has 60 seconds and 1 GiB; each query has 2,000,000 advances. A cutoff or incorrect endpoint is not a completed cost and must be investigated.

Primary contrast: paired Retained/Direct full lifecycle per family, with components and per-(N,R) query results. Also compare both lowerings with the generic controls. A ≥20% paired median difference and all five ratios on the same side of one is a practically consequential pilot signal. Record uncertainty rather than turning a noisy median into a decision. Allocation diagnostics must replay exactly across two repetitions after excluding time and comparing traffic, net live changes and peak increments. Investigate consequential defects or cutoffs before disposition; select more repetitions or a bounded correction only when the uncertainty could change the architectural decision.
