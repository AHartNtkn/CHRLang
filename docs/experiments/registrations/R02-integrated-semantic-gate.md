# R02 integrated consuming execution: semantic gate

Implement one interpretation in which constructor identities, equality deductions and source activation share execution state. This gate asks whether that organization preserves finite-tree CHR observations while source applications can run before all posted equality deductions finish. Cost comparisons require a separate frozen registration after this gate.

## Selection and alternatives

R01's anchor-aware dedicated control now avoids a demonstrated repeated-discovery defect. R02 is selected because it can change the representation used by equality, matching, activation and consumption together. The strongest ready alternative, selective access maintenance, addresses known overhead inside the dedicated organization but is less likely to resolve this representation boundary. Direct finite solving remains an independent R04 option with its own inference-matched comparison; no candidate must await R02 success.

The integrated candidate uses union-find value identities with constructor descriptions, constructor incidence/congruence repair, distinct source occurrence IDs, binding-aware activation and indexed bound-argument access. Consuming rules claim occurrence tuples; propagation history records source IDs, not fused values. The dedicated control retains its own term/binding representation and anchor-aware matcher. Neither implementation may use the reference evaluator as its correctness argument.

Competing explanations: class/descriptor integration could avoid repeated dereference, normalization and wake-up discovery; class/index/congruence repair could instead cost more than the dedicated path. Early application could expose useful work sooner, or add speculation before eventual inconsistency. Predicate-only scans would confound the comparison with a known avoidable access defect, so the candidate must exercise sound indexed selective joins before a cost claim.

## Language and lifecycle boundary

Owned source ASTs, no OR, finite-tree body equations, nonbinding constructor heads, positive equality-entailment guards, consuming and retained heads, fresh body-local variables, exact joint selected outputs and residual occurrence multiplicity. No source rule priority is imposed. Adoption of a broader guard contract remains a separate owner decision; this gate does not impose a language restriction beyond its experimental fragment.

Prepared rules and query state have explicit ownership. Every fired body remains accounted for after its producer is consumed. Constructor child equations and index/congruence repair may remain pending while enabled applications fire, but publication requires complete consistency and source quiescence. Alternate services so source recursion cannot indefinitely postpone a pending contradiction. Cutoffs publish no answer and remain resumable. No comparison of execution costs runs under this gate.

## Independent checks

Replay each successful recorded rule/occurrence tuple from the original query. The test-only checker uses owned syntax substitutions and an occurs check, expands the entire source body and solves its equations atomically before the next recorded application. It does not import candidate, persistent or reference equality/matching routines. At completion, enumerate every injective ordered tuple of remaining occurrences for each source rule and require no enabled unrecorded application. Compare the replayed outputs/residual multiset jointly using the independent observer. Numeric fresh-variable names are not observations.

Source occurrence IDs follow initial query order and the source-body depth-first constraint order, so replay can reconstruct them without trusting candidate snapshots. Failed speculative traces need not serialize: test their pending-work witness and absence of published answers separately.

The bounded suite covers direct and aliased equality activation, repeated equal-valued resources, unknown heads, repeated variables/guards, successful and failed partial-equality interleavings, complete nested body obligations, direct and indirect constructor cycles, equality-only cycles, symbol/arity clashes, joint unknown aliases, fresh locals, nonconfluent source competition and propagation after representative changes. Vary initial arrival order on successful small cases. Include a recursive speculative consumer beside a pending contradiction to check finite service.

Run focused tests with default diagnostics and with counters disabled, package Clippy and formatting, then relevant workspace checks. Record actual witness counts, step bounds, failures, fixes and independent review. A passing semantic gate establishes only the checked fragment and observations. It does not establish integrated performance, general fairness, OR/search behavior or a universal architecture preference.
