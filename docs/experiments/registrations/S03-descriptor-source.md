# Descriptor-backed source execution gate

Package four after the continuing-service breadth review. Implement actual runtime matching, occurrence identities, equality, propagation history and descriptor-backed field changes for the existing deterministic atom/unknown source corpus. This cooperative Python executor is an experimental implementation, not a new baseline or native/parallel efficiency evidence. Native integration and choices remain explicit subsequent obligations.

Compare component admission/commit with a source-priority commit control over the same descriptor store. Derive conservative rule components from read/consume predicate conflicts, inserted predicates that enable other rules, and equality writers (initially connected conservatively to all rules). Match actual ordered distinct occurrence tuples and nonbinding repeated variables. Reserve fresh occurrence/variable identities without reuse after cancellation. Body preparation builds staged writes; install each field independently, commit a descriptor status, then materialize each field independently. Abort one partially installed descriptor once and retry its application. Readers resolve references through descriptor status. A version-validated complete snapshot checks the descriptor catalogue/commit generation; this retains a global observation-version responsibility and is not presented as its elimination.

Use all 77 existing deterministic identity-source cases and two added sources: independent ground consumers and independent recursive producers whose output order can differ. Freshly execute the unchanged serial reference adapter for complete ordered observations, and compare existing corpus outcomes with independent supplied expectations. Source-choice/failure forms must be explicitly rejected by this entry implementation, not interpreted as empty bodies. They remain required integration work.

Run each source with both commit policies, forward/reverse descriptor service and cancellation disabled/enabled: 632 deterministic runs if the corpus contains 79 sources. Before each run freeze source, implementation and reference binary hashes. Check final outputs and residual identities modulo alpha-renaming, preserving residual order for the serial comparison; report component-policy differences as counterexamples. Require the priority control to match every complete serial observation. At every installation/cleanup step, coherent snapshots must equal the latest committed store; cancellation must preserve that store and release claims. Require at least two simultaneously live descriptors on independent sources, a successful retry after partial installation and fresh identities in the existing corpus. No source/work time is measured.

Bound each source run to 10,000 service steps, 1,000 descriptors and at most 1,000 live source occurrences; whole gate to 60 seconds CPU/wall and 1 GiB. Serial adapter processes each have a three-second limit. Preserve failures and shortest available service traces. Any correctness failure requires causal repair or a scoped restriction with the omitted obligation still open, not a cost-loss label. Compare descriptors with atomic source outcomes, not merely with the same descriptor implementation. Run a full breadth review at this boundary or consequential obstruction before extending this local investigation.
