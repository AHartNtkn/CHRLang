# Useful union: bounded lifecycle sizing

This exploratory pilot tests whether substantive union's representation benefit survives preparation, query reuse and output costs. The preceding source/denotation gate supplies the exact logical-set contract. No raw CHR architecture or native compilation superiority is claimed.

## Configurations fixed before comparative runs

Six modes: combined diagram union, separate diagrams, graph-reduced disjunction, prepared name solving, direct explicit checks, and source-deduplicated explicit checks. Four families from the qualified screen: overlap, disjoint, redundant, single. Widths four/eight; three names; one/eight changing queries; membership/full logical output; immediate/two-answer-window/all retention. This gives 576 cells.

The shared source generator constructs only the selected family. Operand preparation is charged; combined union imports/copies its operands and releases temporary diagrams through existing implementation. Explicit membership short-circuits branch/edge checks. Explicit and reduced full-output generation prune invalid partial assignments and caller restrictions. Diagram output traverses accepted paths, expands skipped coordinates and prunes caller-rejected prefixes. Separate diagrams deduplicate collected output; name solving uses partial feasibility with its prepared alphabet. Source deduplication normalizes edge orientation and branch order, charging that work.

Caller restrictions repeat every five queries: unrestricted, coordinate zero fixed to name zero, fixed to name one, coordinates zero/one equal, and contradictory. Membership assignment q has base-three digits of `71*q+17`, padded to width. Every query independently checks complete answers against brute-force denotation outside measured phases. Exhaustive denotation is an oracle, not a timed competitor or an application weighting.

Each process preflights its entire session. Full-output preflight stops after its first accepted row, verifies it belongs to the independent answer, and then completes a fresh query against the same prepared object. Empty output must exhaust without invoking the visitor. Meter builds require all preflight ownership restored. Timing runs inherit this warmup and do not represent cold-process startup.

## Measurement and limits

Meter build: release, no default features, `alloc-meter` only. Two independent repetitions of all 576 cells, shuffled with seed 76021: 1,152 processes. Primary sizing build: release, no default features, ordinary allocator; five shuffled repetitions of the 192 retained-all cells, seed 76022: 960 processes. All code clocks are absent from allocation phases; allocation diagnostics are absent from ordinary timing. Each process checks that engine metrics are off. Collect five empty-clock diagnostics before timing.

Measure source construction, preparation, source disposal, request construction, execution/complete logical observation, request disposal, consumer retention/disposal, prepared disposal and final retained-output disposal. Total is the sum of measured phase intervals. Validate before consumer release, outside intervals; retained outputs are checked after preparation disposal. Allocation phases must form a continuous live-heap trace and restore the baseline exactly. Report requested traffic and peak excess above that process baseline separately from timing and from RSS.

Execution and observation are fused in this output adapter; first-row latency is not separately timed. Callback cancellation qualifies stopping at first output, not asynchronous interruption during compile/union. Oracle fixtures, process startup, toolchain compilation, argument parsing and fixed preallocated harness phase/consumer containers are outside measured totals. No complete language-architecture lifecycle claim follows. Report these exclusions with results.

Bound each process at 60 seconds wall/CPU and 1 GiB, diagram operations at one million charged ticks, and builds at 300 seconds. Freeze exact sources and binaries before confirmation. A preliminary all-mode/all-family width-four/eight-query full/window smoke qualifies the harness before the frozen matrix. Preserve every failure. No rerun or exclusion solely because a result is unfavorable.

## Hypotheses and interpretation

Union may repay construction at higher reuse or larger overlapping full output. One query, disjoint alternatives, redundant sources with competent deduplication and membership with early rejection may instead favor simpler controls. Compare each matched cell; no pooled workload score or universal winner.

Repetitions are sizing, not confirmatory statistical evidence. Show median and full observed ranges for matched total-time ratios; flag totals below 100 times the maximum median empty-clock cost times the number of measured intervals as insufficient signal. A ten-percent total-time contrast selects consequential confirmation; it is not a confidence interval or a final win criterion. Do not sum phase medians to obtain a session median. Allocation repeats must agree exactly after baseline normalization.

Investigate consequential overhead before generalizing. Potential avoidable costs include repeated identical operand compilation, retained construction nodes, per-query name transport, duplicate full-output construction and source preparation. Attribute the phase and compare a sensitivity bound before selecting a repair. At this result or obstruction compare completing cost confirmation with the structural-prefix generated/access controls and unfinished demand/integration costs. This is package two after the full portfolio review; the research remains active.

All measured child processes are pinned to the lowest permitted CPU, recorded in the freeze. Resource limits apply to smoke and clock runs as well. The matrix has a 30-minute wall bound; an interruption preserves completed receipts for resumption rather than restarting live work.
