# General integrated matching: complete lifecycle timing pilot

Hypothesis1: partial joins can turn their lower sparse/nested allocation into lower complete phase-summed time against conventional Scan. Hypothesis2: retained matching can lose on cold/dense cases because setup dominates, even if execution is cheap. Hypothesis3: specialization or indexing can change timing without reducing allocation. Test each by source regime; do not supply workload weights or infer a universal architecture winner.

Use the existing seven qualified adapters: local-scan, tuples, partial, scan, indexed, special-scan and special-indexed. Before comparative timing: run argument-free source preflight, validate252 exact old/new allocation comparisons and two diagnostic repetitions per cell, verify all ownership boundaries, and inspect clock overhead. Reject engine/kernel/observer counters at the measurement entry. Primary release builds use the ordinary allocator with no default features; allocation-meter runs are separate. No feature changes to execution mechanisms are included.

Preserve cutoffs and diagnose before changing bounds. A later confirmation requires prospective registration.

Each process validates every changing query against independent scalar semantics before measurement, warming that path. It validates the measured complete owned answer outside measured intervals. Measure source-build, prepare, input, setup, execute, observe, engine-drop, answer-drop, input-drop, prepared-drop and source-drop separately. Cancel-after-setup and cancel-after-one-adapter-call are separate lifecycle paths. Adapter calls differ in granularity, so cancellation timings cannot rank equivalent progress.

Primary total is the sum of non-cancellation phase durations, including source construction/preparation/disposal and all changing queries. Report phase-summed query-to-first-observation separately where useful. These sums exclude process startup, validation, reporting and between-phase harness bookkeeping. Source-to-native program compilation, stack storage, code size and sustained consumers are not fully accounted for, so no compilation-inclusive or full-architecture superiority follows.

Characterize10000 empty timed intervals in each build and retain minimum/median/p99 without subtracting them. Five-sample medians and ranges are exploratory. A pair is a strong pilot separation only if the candidate's entire range is below0.9 times the control's range, or above1.1 times it for a loss; every other pair remains unresolved. Even a separation is a prioritization signal, not a confirmatory speed claim. Investigate a consequential reversal, cutoff or concentrated cost before rejecting a representation. Broader guards, search, context support, cache ownership alternatives and lifetime remain required.
