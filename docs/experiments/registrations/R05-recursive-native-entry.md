# Native recursive artifact entry

T046 tests whether source-specific native execution is a credible optimization of the certified sealed recursive fragment, and whether its added preparation can be measured against direct equation execution and current Specialized. The strongest ready alternative is compilation lifecycle for R04's finite fragment. This entry uses the already validated recursive certificate and existing finite-tree kernel; it should not require a dynamic-library ABI or a general compiler infrastructure project.

## Correctness gate before comparison

Generate a Rust module from the authoritative `recursive::Prepared` certificate. Native statements implement each ordered equation, term construction, fresh variable and next argument tuple. The artifact may instantiate owned query syntax and export answers through the finite-tree kernel. It must not reconstruct source rules, interpret body equation templates, invoke Prepared execution or use a CHR occurrence store. Source predicate/constructor names must be emitted as correctly escaped literals.

Compile emitted modules in a separate Cargo package using the installed toolchain and only path dependencies for syntax, persistent term services and answer comparison. The execution package has no chr-compiled dependency. Test multiple control positions and source bodies, including fresh existential variables, against independent scalar source answers and the checked direct executor. One compiled module must serve changing depths, payloads, result equations and selected outputs. Unsupported inputs remain errors distinct from finite equality failure. Compiler failure must fail the gate and preserve its output; it must not select an interpreted fallback.

The bounded gate uses six independently emitted modules: two equation bodies across three control positions. Every module tests 24 accepted query combinations (two depths, three payloads and four results), plus unknown/partial/foreign/malformed controls, surrounding work and duplicate output names. Escaped quotes, backslashes, newlines and Unicode appear in source names. A seventh arity-one module with no equations checks the same constructor spelling at nullary/unary arities and an output-only variable at two depths. All 182 outcomes must validate. Existing T045 mathematical expectations and full-observation gates remain controls.

This gate performs compilation as correctness work, not comparative timing. Temporary artifact crates and compiler outputs identify the actual dependency and executable boundary. No elapsed values from the gate support cost rankings.

## Selected lifecycle boundary

Use a source-specific executable and a common request protocol for the prospective pilot. Compare native, direct-equation and current Specialized through the same session/process boundary. One process must accept changing queries, validate complete answers outside measured intervals and exit with an explicit outcome. Query decoding, encoding, startup/loading, shutdown and disposal are real costs; an in-process control cannot stand in for a subprocess lifecycle.

Keep three cost classes visible:

1. Shared prerequisites: compiled kernel/protocol libraries, generator and control executables. Record their build conditions separately; availability is not free cold installation.
2. Per-source preparation: certification, generation, artifact writing, compilation/linking. Direct and Specialized charge their own source preparation.
3. Session lifecycle: startup/loading, query decoding, execution, complete answer encoding, shutdown and disposal. First-request latency includes startup, while reuse keeps the same process alive.

If both clean dependencies and prebuilt dependencies are measured, run them directly as distinct conditions. Do not obtain compilation costs by subtracting unrelated builds. Record compiler options, incremental/cache conditions, artifacts and toolchain. Reuse rates are separate unweighted scenarios, not an assumed application distribution.

Exact workloads, repetitions, interleaving, resource caps and interpretation criteria require a later prospective registration once this executable/protocol path passes correctness. No comparative runs are authorized by this entry alone. If the path requires broad infrastructure, reconsider R04 rather than expanding automatically. No language restriction or complete lifecycle superiority is claimed.
