# R02 constructor repair and matcher maintenance pilot

Prospective follow-up to T028, registered before comparative runs. T028's measured cells did not perform constructor descriptor repair or source applications with pending equality. This experiment tests those missing mechanisms and whether output-only matcher maintenance materially explains the integrated candidate's costs. It has higher immediate decision value than the strongest ready alternative, R04 inference-matched solving: it resolves a concrete representation confound and missing mechanism on an already independently checked complete consuming path. R04 remains open.

## Hypotheses and controls

H1: constructor decomposition and nested descriptor repair may let integrated execution use equality information earlier and avoid repeated dedicated normalization. Its competing explanation is that congruence/parent repair and occurrence retention cost more than dedicated bindings even here. Compare integrated with generic-indexed, generated-indexed, generated-scan and generated-global-scan dedicated controls.

H2: matcher indexes and occurrence incidence for predicates absent from every prepared head contribute avoidable memory and lifecycle cost. Compare current integrated source with the library at commit 27e055b, using identical current workloads, build script, runner and replay tests. Only the current library limits matcher maintenance by exact predicate name and arity; both retain complete observations and constructor parent dependencies. Record source hashes for both. Historical library is a separate temporary workspace, not an execution mode. A reduction in requested heap supports this attribution; inconclusive timing does not establish speedup.

## Registry and semantics

`batch` posts n independent open/ticket pairs and one equation between n-ary tuples. Tuple decomposition binds every open variable to f^depth(a). `nested` posts open(K,f(X)), has head open(K,f(g(Y))), and decomposes one tuple equation binding each X to g^depth(a). Both consume pairs into result(K,Y), propagate seen(K,Y), and observe every X. Independent analytic full answers include all result/seen multiplicities and constructor contents. The semantic gate checks legal source replay, terminal enabledness and full joint observation. Counted integrated runs must show positive descriptor repairs and source applications with pending deductions in every query of these families.

Main registry: batch and nested × n in {8,64} × depth in {1,8}; current five variants plus historical integrated = 48 cells. Maintenance controls: independent, fanout, repair and build at n=64, depth=1, historical and current integrated = 8 more cells. Total 56 cells. Each process prepares once and runs sizes n,n+1,n,n+1. Five time processes plus one work and one memory process per cell: 392 processes, 1,568 complete answers requested. Shuffle using Python random.Random(20260911), retain order, no warmup exclusion or adaptive repetition.

## Measurement and freeze

Reuse the independently checked native R02 runner and its phase boundaries: owned-input preparation, query setup, execution, first complete observation, engine disposal, answer disposal and prepared disposal. Analytic validation is outside timed intervals. Four-query lifecycle sums preparation/disposal and all request-plus-answer-disposal intervals. Harness costs are separate. Compilation is not credibly isolated per source ruleset and is excluded; no full architectural lifecycle superiority follows.

Build each source in three isolated Cargo release target directories `/tmp/chr-r02-repair-{before,after}-{time,work,memory}`; historical workspace `/tmp/chr-r02-repair-before` is an archive of 27e055b overlaid with identical current workload/build/runner and common replay files. Use `-p chr-integrated` and respectively `--no-default-features --features experiment`, `--features experiment`, `--no-default-features --features alloc-meter`. Binaries in `/tmp/chr-r02-repair-bins/{before,after}/{time,work,memory}`. Freeze relevant source, generated files, registration, scripts, dependency feature trees, compiler/environment and binaries before running. Primary time has all integrated/compiled/kernel counters off and ordinary allocator. Work counts and requested-heap allocation diagnostics run separately; meter is not RSS. Check actual reported feature flags, allocator self-check, empty-clock calibration, and stable live bytes after each query answer disposal.

Children run serially pinned to minimum allowed CPU, with 2 GiB address space, 20 CPU seconds, 30 wall seconds, no core dumps; batch 15 minutes; query 1,000,000 steps. No concurrent builds or other experiments. Preserve every timeout, cutoff or failure; stop on validation/feature/retention disagreement. A cutoff is no answer or refutation.

Report five-process per-cell median/range, phase costs and heap requests. A direction smaller than 10% or with overlapping ranges is inconclusive. Ignore phase direction below 100 times median empty-clock cost; do not subtract overhead. Compare integrated work counts before/after only in identical units; do not rank architectures by unlike counters. No workload weights or overall winner. If integrated still loses on repair cases, retain contrary evidence and distinguish required representation machinery from a demonstrated defect. Further tuning requires renewed architecture decision value; this pilot does not close compilation, search, solver, conditional activation, reclamation or parallel questions.
