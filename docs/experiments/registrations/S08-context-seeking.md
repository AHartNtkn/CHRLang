# Seek across gaps in ordered context inclusion

The qualified ordered walk is faster on dense maps but 14.53× slower for two late keys and 10.73× slower for four spread keys in the 256-entry ordinary-operation pilot. Its cause is traversing context assignments absent from the support. Test a repair that retains sequential comparison for adjacent support keys but restarts the ordered-map range at the next requested key when a gap is encountered. This introduces no map copy, retained cache or density threshold.

Keep lookup and the complete ordered walk as controls. Reuse all 531,441 independent truth cases and the 51 dense/sparse/conflict/missing-key work configurations. The seeking candidate must preserve truth and substantially reduce comparisons versus the full ordered scan on the late sparse 256-entry case. Run existing source/cycle/context and consuming lifecycle controls; the active helper has seek-context enabled together with ordered-context and completed-traversal. A false return stub must fail the truth gate before implementing the repair.

Repeat native operation sizing with all three methods in the same ordinary release binary. Nine blocks of 20,000 calls per method/configuration, 2,000 warmup calls per method/configuration, cyclic method order by configuration and block. Validate result counts outside intervals. Freeze the three-method corpus, code, binaries and commands before confirmation. CPU 0, 60-second CPU/wall, 1 GiB. These are operation times, not architecture lifecycle superiority. If the operation passes, register paired full lifecycle against the lookup control using the qualified continuing and flat sources before choosing default behavior. Sparse and missing cases remain controls even if the repair is not universally faster.
