# Separate history eligibility from continuation-key cost

The first lifecycle pilot found almost no substantial reuse in its history source. A canonical-key trace establishes why: temporary occurrences remain live while the higher-priority recursive rule runs. The new `history-early` source changes only the temporary-consumption rule's priority, placing it before recursion. Independent complete-answer and cancellation gates cover both orderings and all seven engines. At depth64/resources, AlphaLive now executes 160 of 565 logical steps, whereas Alpha executes 565. This is a source-work observation before comparative timing.

## Separate requested-allocation attribution

A diagnostic traverses complete direct-execution cursors and records requested allocation for `Machine::key`, consuming key canonicalization (exact/alpha/live), and `Machine::step` separately. It does not retain/intern keys, replay transitions or time operations. This isolates the cost of making a key at a visited state; it is not the total allocation of the sharing engine and excludes queue operations from the step component.

Run the meter-only, counters-disabled `continuation_key_alloc` example twice. Each process covers five families exact/rename/history/history-early/distinct, depth0/16/64, resources absent/present and three key modes: 90 diagnostic cells per run. Require exact payload replay, independent complete raw answers and root requested-live restoration. Freeze diagnostic sources and binary; use the same process bounds. No asymptotic fit or runtime ranking from these byte counts.

## Decision and follow-through

If favorable projection saves source work but remains costly, distinguish owned export, canonicalization and retained-transition obligations before selecting an implementation repair. A compact or stable key may change those costs; its equality and alias semantics require independent validation. A small favorable source alone cannot justify continuation tables, nor can a representation-specific loss reject generalized reuse. Call-level reuse, broader relevance, eviction and sustained consumers remain required. Reconsider the strongest ready S08 lifetime and S02 integration alternatives at the next package boundary.
