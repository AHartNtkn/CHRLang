# Exploratory sizing of complete demand execution costs

This is prospective exploratory sizing, not confirmation. It determines useful sizes and resource limits for a later registered comparison, and can identify consequential defects. Do not declare an ordering from one timing sample per cell.

Use the box-building sources from S03 work attribution: plain (zero choices), opaque and discriminating (three independent binary choices). Controls: demand with static birth-context reuse, demand with current-context reuse, direct graph, Conditional, compiled global scanned/indexed execution, and checked direct lowering of this exact schema. The lowering must validate the supplied source and query, then construct the required complete output directly. It is a specialized source control, not another reference implementation.

Ordinary-allocator matrix: all seven controls, three families, depths 0/8/32, query counts 1/8, consuming endpoint enabled (126 cells); additionally depth32/query8 without the endpoint (21 cells). One process per cell, 147 total, shuffled with seed 7106. Alternate depth n/n+1 and query insertion order under one prepared ruleset. Independently validate every completed answer outside timing against the scalar oracle. Validate source/input eligibility and cancellation before this matrix.

Separate requested-allocation diagnostics: all seven controls, all three families, depth32/query8, with/without consumption, twice (84 processes). Require deterministic per-phase allocation traffic and query/prepared live-byte restoration. Requested bytes are not RSS. Meter self-check is required first. Primary timing builds disable engine/kernel/observer counters and use the ordinary allocator.

Record source construction, preparation, query-input construction, setup, execution with complete observation, first answer, engine disposal, answer disposal and prepared disposal. Tick APIs construct answers internally; do not claim to isolate their observation from execution. Keep exact expected fixtures outside the timed lifecycle. Report host wall time separately; fixture generation, validation, reporting and process startup/exit are outside the phase sum. Retained output is released after each query. Cancellation gate: interrupt the first query after one tick and validate a subsequent completed changed query on the same preparation; do not label interrupted queries complete.

Bounds: 60 seconds wall and CPU per process, 1 GiB address-space limit, 2,000,000 ticks per query. Pin to the first permitted CPU and record host/toolchain/binary hashes. A cutoff is incomplete evidence and requires attribution, not a losing timing. Do not restart an observed live process.

Interpretation: inspect phase balance, cold/prepared reuse, ordinary versus allocation-run behavior, and whether corrected reuse improves the intended source work in total cost. Strong direct lowering can overturn gains relative to general executors. Select confirmatory sizes/repetitions only after this exploratory result, and reconsider contextual/local consuming rewrites at that boundary. Compilation costs are not isolated by building this shared Rust harness; no compilation-inclusive superiority claim is permitted.
