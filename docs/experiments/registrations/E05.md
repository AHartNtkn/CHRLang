# E05 v1 — frozen first-order named-family equality requests

This experiment isolates the finite-tree equality service for opaque named families. It does not claim a complete CHR engine or HVM integration. Dynamic source-label birth, occurrence consumption and propagation history remain separate obligations. Within this first probe, every listed label is an independently active binary source decision in a frozen request.

## Representation and comparison

Use an immutable DAG of ordinary constructors, logical-variable handles and internal named alternatives. Source programs cannot inspect the alternative node. Two references to one named alternative use the same decision; distinct labels vary independently. Projection under a complete assignment produces only finite first-order terms.

Compare eager scalar projection with demand-driven named service on the same equation worklist and finite-tree unification machinery. The eager control projects all operands consistently for every assignment before executing. The named service keeps constructors and opaque handles shared, restricts all operands and existing bindings consistently whenever a decision is demanded, and never equates ordinary duplication with choosing opposite arms. Track request splits, contextual reads, unification pairs, occurs work, graph allocations, state copies and final projection/observation separately.

A variable can bind an unresolved family only when its contextual occurs check establishes absence throughout the supported family. If the answer differs between choices, refine the context; a possible cyclic alternative must neither reject valid siblings nor permit its own cycle. Each frozen request is transactional: partial successful bindings from a subsequently failing equation are not externally returned.

## Correctness cases and controls

Require complete assignment-by-assignment agreement with independently expected finite-tree solutions, including repeated-label correlation, independent-label Cartesian choices, both operand restrictions, alias propagation, direct and indirect occurs failure, a union of mutually exclusive edges that is acyclic in each projection, failure confined to one alternative, and two independent logical variables that must remain distinct. Verify the projected successful result satisfies every original equation and preserves the expected most-general variable relationships. Exact answer deduplication uses the independent E14 observer; source decision multiplicity is recorded before deduplication.

Mechanism workloads will vary labels, common constructor depth, repeated references and the point of discrimination. Include a shared constructor prefix whose leaf demands a decision, completely differing leaves, branch-local failure and irrelevant decisions. Report construction, execution and extraction costs. A request processed once but subsequently projected into all assignments has shared service work, not constant-size total observation. A naive eager enumerator is an ablation of distribution timing; E01/E03/E04 remain needed for whole-engine comparison.

Before comparative runs, register the exact generator, sizes, resource limits, independent expectations and counter predictions, then freeze source and registration. Exploratory debugging may refine the implementation and tests before that freeze. Full replay must reproduce non-time counters. No service-only result closes dynamic label lifetime, CHR effect correlation, scheduler fairness, realistic application coverage or backend compilation.

## Frozen matrix and predictions

The executable generator is `research/chr-family/examples/family_probe.rs`. Four families use k={0,1,2,4,8} active labels and W={0,1,8,64,256}; a cycle family uses k={1,2,4,8} and the same W. Total: 120 requests, two modes, 240 runs plus a complete replay. One fresh release process per request/mode, 60-second process bound, 1,000,000 service steps. A spent service budget is unfinished, not failure. The frozen service accepts at most 16 labels; this matrix stops at eight.

`opaque` binds X to W unary constructors around a tag of k named bits. Named execution should retain one successful region with one equation pair, while eager execution processes 2^k pairs. `prefix` equates the same W-deep bit tag with a W-deep tag of distinct output variables: named pairs W+1+k, eager pairs 2^k*(W+1+k), with no named distribution required. Each produces 2^k unique answers.

`correlated` equates two separately constructed, equal tags carrying the same labels beneath the W-deep prefix. It must preserve correlation while inspecting all labels. Expected named pairs W+1+3*(2^k-1); eager pairs 2^k*(W+1+k). Both have 2^k raw successes and one deduplicated empty answer. `discriminate` equates the bit tag with an all-a tag: only the all-left assignment succeeds. Expected named pairs W+1+3*k; eager pair count depends on the first failing field, so record it without assuming every field is visited.

`cycle` uses X = choice(0, s^W(a), s(X)); labels other than zero are active but irrelevant to this equation. Named execution should perform three pairs with one successful and one failed region. Eager execution processes 2^k pairs. There are 2^(k-1) raw successes and one distinct answer. This tests exact branch-local occurs failure, not merely constructor mismatch.

The independent hand-derived generator constructs expected observations outside measurement. Allocation readings separately charge request DAG construction, solver construction/execution, and complete projection/deduplication. Requested phase bytes sum to total requested bytes. Report baseline/peak/final payload; the baseline includes expected fixtures. Root/projection reads during output extraction are separated from solver reads. Output projection enumerates every active assignment, including irrelevant labels, and materializes raw answers before exact deduplication; charge that cost. `completed_regions` is not raw answer multiplicity. Timing fields are diagnostic only.

Five semantic tests additionally cover direct correlations and failure, opaque binding, unfinished observation rejection, and 144 generated two-equation requests under all four assignments. The generated tests build scalar terms from a separate test AST and compare each assignment against the independent reference interpreter's finite-tree unification, using E14 equivalence. Both modes are checked: 1,152 assignment comparisons against 576 reference executions. This strengthens projected MGU checking without importing reference runtime logic into the service. Dynamic births/effects, generated larger graphs and full CHR remain open.

## E05 v2 — strengthen the eager control with exact supported partitions

The v1 eager control deep-projects each assignment independently. Its result is a distribution-timing ablation, but allocation differences also include avoidable projection storage copies. Before interpreting those differences as a named-family advantage, add `Partitioned`: memoized immutable input projection, structural interning of projected first-order nodes, and exact grouping of identical projected equation lists with finite assignment supports. Run the same 120 requests in all three modes, with full replay, into separate v2 files. Source service behavior and expected observations remain unchanged.

Partitioned contexts contain ordinary projected terms and an explicit set of assignments with the identical request. They cannot create correlations from approximate equality or merge variable identities. Canonical projected nodes include raw variable handles, constructor names and ordered children. Every assignment still pays projection/cache lookup and partition construction costs, which are charged before service execution. It uses the same equation and occurs machinery. All generated assignment/reference checks must pass in this mode too.

Register projection memo hits, structural interning lookups and exact partition groups in addition to existing counters. `eager_nodes` counts allocated projected nodes in either eager representation. No reduction in work is predicted merely from structural interning. If each assignment has a different equation list, retain 2^k partition groups. Equal-request grouping is not answer deduplication and does not justify forgetting active assignment multiplicity. This v2 run supplies the explicit-supported-partition comparison called for by E05's sequence, while dynamic source effects remain open.
