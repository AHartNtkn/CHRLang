# S03 source executor: prospective correspondence gate

Connect the direct graph to ordinary source rules without calling another executor. Source occurrences retain stable identities and contextual availability. Rule matching is nonbinding: a first pattern variable captures a graph node, repeated occurrences require existing equality, and constructor patterns demand only the relevant graph roots. Pure guards use graph entailment. A successful consuming application atomically claims distinct occurrence IDs in its matching regions; propagation records rule/occurrence-tuple regions. Rule-local unknowns are fresh per application.

Pending source goals carry contexts and shared term references. Explicit OR introduces a dynamic birth; general effectful arms become contextual obligations. A pure OR tree whose leaves equate the same source variable to terms may instead build a named-choice term and perform one graph equality. This is an explicit lowering whose cost must later be separated from graph organization. It does not permit collapsing duplicate alternatives or ignoring failed equality arms. Conjunctions retain shared rule-local variable identity.

One service step executes a pending goal and chooses the first enabled rule/tuple in each uncovered context. This is a declared committed scheduling policy, not an enumeration of rule schedules. Pending obligations and enabled applications prevent publication in their contexts. Quiescent complementary contexts can publish complete outputs and residual occurrences while another context continues. Published and failed contexts cannot execute more work. Service operations may inspect a size-dependent finite store; this gate does not claim constant tick latency or bounded-memory infinite execution.

Before implementing behavior, connect the already registered 28-case mathematical word/source oracle and finite-sibling gate to the new executor. Preserve the independent scalar and Conditional checks. Use the same 290 expected raw answers and the existing 20,000-step sibling observation test, with a 60-second process limit. Add direct sources for constructor-sensitive competing consumers, propagation once per identified tuple, late eligibility after equality, repeated-head nonbinding behavior, aliases and constructor cycles, disconnected pending failure, and output/residual joint unknown identity. Derive their complete answers independently and check against the owned-syntax scalar executor where its schedule agrees.

Run package tests, compound gate and replay, and strict Clippy. Record exact commands, exits and source hashes. Cutoffs require investigation. This gate establishes correspondence only on its tested sources; generic source support alone proves no general correspondence theorem. No comparative timing follows until a credible compiled control and the graph's favorable/adverse workloads are registered.
