# S03 dynamic choices and source resources: prospective entry gate

Purpose: fix an independently checked source/observation contract before implementing a direct named-choice or derivation graph. This tests readiness of the existing Conditional comparator, not performance of a graph candidate.

A unary-depth generator consumes `build(N,X)` and constructs a list. Each step has explicit choice between a and b, or between a and a for duplicate-arm cases, or a versus a nested b/c choice. The latter distinguishes inactive dynamic births from unconditional label assignments. A query contains one or two independent generator calls, one token(H), and one task. A propagation rule observes token(H) once; the multihead task rule consumes its task and that token and emits an out residual containing the generated values twice and H twice. A rejected-first-b case consumes a completed out and fails; output-shaped data cannot publish before the remaining source obligation finishes.

Cases: binary one-call depths 0,1,2,3; binary independent two-call depths 1,2; nested three-way one-call depths 1,2; nested two-call depth 2; equal binary arms depths 1,2,3; rejection at depths 1,2. Repeat preparation with changing depths and both token-first and token-last query order. A separate unbounded sibling fixture must publish its finite sibling without claiming exhaustion.

The mathematical oracle recursively constructs all finite words with multiplicity. Two-call expectations are Cartesian products of independently generated words. Every answer includes exactly seen(H) and out(X,X,Y,Y,H,H), with X=Y for one call and independent roots for two calls. H remains unknown with joint identity across both residuals. No selected output roots are needed. First-b rejection filters those words only; duplicate words remain duplicate raw successes.

Cross-check the complete expected multiset against the independent owned-syntax scalar executor and the existing Conditional engine. Neither expected cardinalities nor values may be derived from candidate output. Use exact full answer equivalence and raw multiplicity. Negative checks must distinguish correlated versus independent calls, inactive-birth multiplicity, lost token observations, premature failed answers and merged unknowns. Bound finite cases at 200,000 scalar transitions and 2,000,000 Conditional ticks; each validation process has a 60-second wall limit. Cutoffs are unfinished results requiring diagnosis.

Run default and counter-free gates. No timings from tests are architectural evidence. The next graph implementation must pass this same gate plus separate finite-cycle equality, conflicting consumption and late-context witnesses before a comparative cost registration. A direct graph is not implemented merely by this comparator gate.
