# Checked phase boundaries versus resumable execution

T075 package two after the adaptive breadth review tests a consequential remaining assumption before cost measurement. The prior gate separates current resource keys from scheduling and propagation history. This package asks whether an initial non-propagating rule-priority phase suffices for complete ordered delivery, and whether existing resumable transition reuse preserves the source service schedule on the same adverse effects.

## Hypotheses and controls

The checked-phase hypothesis requires an exact initial rule-priority prefix, at least one removed head per selected rule and all selected head signatures in the projected initial region. These are tested syntactic conditions, not a claimed general correctness certificate. Use the existing frozen contraction probe with uncached and region-keyed execution. Compare complete multisets independently and raw delivery order separately against direct persistent FIFO execution.

H1: these conditions can preserve complete outcomes while phase batching changes which caller answer arrives first. Vary two caller branch lengths independently over 0, 1, 4 and 8, reverse branch order, and use variable offsets 0/100: 64 source configurations. Require raw multiset agreement, classify actual ordering differences and preserve all ordered outputs. A different order cannot be treated as an equivalent endpoint for prefix cancellation without an explicit caller contract.

H2: existing whole-state transition reuse can preserve the direct FIFO schedule on interference, propagation, fresh aliases, resource absence and early failure, without making the phase atomic. Use Direct, AlphaLive and CompactLive, service one logical step at a time, and compare each emitted answer and exhaustion against Direct. Independently check complete raw multisets using the unchanged scalar evaluator. This is an existing competing organization, not a new call-local implementation.

For H2, vary six body/effect families (competing consumption, intermediate observer, earlier binding, surviving propagation history, resource absence and early failure), same versus distinct caller tags, and offsets 0/100: 24 sources. Each source begins with two derivations. Record actual transition hits and executed versus logical work in metrics builds; identical semantic checks run metrics-off. Require retained answers to remain valid after run disposal, and drop partially serviced searches before starting the same prepared program again. Tables remain query-owned; do not claim cross-query reuse from preparation reuse.

## Oracle, bounds and interpretation

The scalar evaluator's branch queue convention is not assumed identical to persistent FIFO. It establishes complete multisets and explicit rule traces. Ordered equivalence is checked against direct persistent service, and the unequal-length witness must have its first result explained independently from source rules. Do not silently relabel an oracle ordering mismatch as a candidate failure.

Run the deterministic tests once per default and metrics-off build. Compile outside execution bounds; each test executable has 60 seconds wall/CPU, 1 GiB address space and 200,000 logical steps per query. Preserve source/configuration rows, outputs and diagnostics. No timings, allocation superiority or architecture ranking. Frozen prior sources are not edited.

A checked-prefix ordering failure requires an execution/scheduling remedy or a clearly different caller contract; tightening a fragment merely to avoid the witness does not establish general effectful reuse. A resumable success retains whole-state key costs and dependencies and must be compared with a genuinely local dependency/replay design before claiming the broader call-reuse question resolved. At this gate compare such an implementation with adaptive timing attribution, native ownership, conditional lifetime and incremental projection. Full breadth review remains due within two further packages after this one.
