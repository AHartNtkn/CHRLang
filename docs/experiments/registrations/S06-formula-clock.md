# Finite-formula clock and counter qualification

This is the second and final selected qualification package before registered timing and the T077 handoff. Make assignment-attempt diagnostics compile-time optional under the existing metrics feature; retain operational bounds. Check finite-name semantics with diagnostics on/off. Allocation comparisons already exist; this package supplies no architectural speed ranking.

Add compile-time phase clocks to the existing ownership runner. Fine phase sums are diagnostic: many no-op or membership phases may be too short. Also add a coarse retained-all session endpoint spanning preparation, changing requests, transport, observation and producer disposal, followed by separately measured final consumer disposal. Complete answers are validated after the coarse interval; all outputs remain owned until that validation. This endpoint rejects immediate/window consumers, whose intermediate disposal would prevent validation outside the interval. Source/oracle fixtures and fixed-capacity report/consumer storage remain outside measurement, as in allocation qualification. First/full observation coincide at the current atomic Output interface; no streaming first-value or process-start claim is made.

Clock calibration: five processes, each with 100,000 empty intervals, report min/median/p99/max without outlier exclusion. Qualification cells cross six modes, free/star/clique/overlap families, three/six variables and 1/16/128 queries (144 cells), with three names. Three-variable cases use membership; six-variable cases use full output. All retain outputs until validation. Run meter/clock-off twice, meter/phase-clock-on twice, ordinary/clock-off once and ordinary/coarse-clock-on five times per cell. Compare normalized allocation phases against the existing matrix and validate every complete answer; no relative-speed hypothesis is tested. Inspect fine clocks in the metered runs only for endpoint integrity, not ordinary timings.

Coarse timing uses only two measured intervals per session. A cell qualifies for primary timing only if its minimum observed session sum is at least 100 times twice the largest empty-clock median. Retain short cells as unqualified; do not subtract a guessed overhead. Report variability and all observations. If this threshold cannot supply a consequential comparison, investigate the measurement design before declaring timing ready.

Use isolated release target directories, frozen sources/binaries, 60-second wall/CPU and 1-GiB per-process bounds, and a 30-minute campaign limit. No default engine metrics or allocation meter in the ordinary primary candidate. Prospective primary configurations and repetitions will be fixed from qualification results before comparison; no primary timing matrix is run under this registration.
