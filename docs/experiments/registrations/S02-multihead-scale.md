# Controlled matching at smaller widths and single-query use

The earlier controlled study qualifies local graph scan gains only at width 64 with four queries. Smaller inputs and one query can expose preparation overhead and change the architecture's useful regime. Resolving this uncertainty with the frozen binary costs less than implementing another retention policy before knowing its target regime. Native identity, broader language support, reuse and complete architectures remain required investigations.

## Prospective comparison

Use the exact ordinary-allocator, counter-free binary frozen by S02-multihead-lifecycle. Do not rebuild. Compare all seven existing modes (`local-scan`, `tuples`, `partial`, `scan`, `indexed`, `special-scan`, `special-indexed`) on all six existing families (`sparse`, `broad`, `nested`, `cold`, `dense`, `three`). The five width/query-count pairs are (4,1), (4,4), (16,1), (16,4), (64,1). This fills the remaining size/reuse cells; do not pool them with the earlier confirmation to strengthen a result retrospectively.

Run 21 blocks per CPU/family/size pair on CPUs 0 and 8. Each block runs every mode once. Shuffle the 1,260 blocks with Python Random seed 7283, then shuffle modes within each block using the same generator: 8,820 processes. Record order before execution. Verify singleton child affinity before exec; change no system power setting. Each child retains 1 GiB address space, 30 CPU seconds, 45 wall seconds, and the frozen runner's 200,000 service-call bound. Stop on any failure, preserving its receipt. No retry, sample exclusion or adaptive stopping is allowed. The full serial driver has a 30-minute wall bound. Record binary, driver, registration and auditor hashes before running and verify them afterward.

The runner validates complete answers independently outside intervals. It measures source construction, preparation, query input/setup/execution/observation and disposal. Primary endpoint is the sum of all non-cancellation phase durations. Startup, validation, inter-phase bookkeeping and native compilation are excluded. Cancellation remains a separate diagnostic with unequal adapter progress; this study cannot establish complete architectural lifecycle superiority. ## Hypotheses and interpretation

Preparation may erase the graph scan advantage at small widths or one query. Retained joins may repay setup only with sufficient useful matching. Indexing and specialization may change those crossovers. These are hypotheses to test, not assumptions about a preferred architecture.

Compare each of six other modes against Scan, plus tuples and partial against local-scan. Across five size pairs, six families and two CPUs this yields 480 comparisons and 960 directional tests. Use within-block total-duration ratios. For each comparison test practical gain below 0.9 and loss above 1.1 using exact one-sided binomial sign tails with n=21, treating threshold ties conservatively. Apply Holm correction at familywise alpha 0.05 across all 960 tests. A result is a gain or loss only if its adjusted test passes; otherwise it is unresolved, not equivalent. Twenty-one blocks allow one unfavorable block still to pass the strictest correction when the remaining twenty pass (960 * 22 / 2^21 < 0.05).

Report medians, ranges, phase costs, both CPU placements and prior requested-allocation evidence. Blocks may share thermal/frequency effects; interpret sign tests conditionally on representative blocks. Inspect consequential crossovers and losses before drawing a design conclusion. Do not infer universal superiority, invent workload weights or call a narrow implementation loss an architectural impossibility. After this comparison, review broader integrated support and retention variants against the strongest ready native-identity, solver, reuse or coherent-architecture investigation.
