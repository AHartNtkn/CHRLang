# S10 progress and lowering composition gate

Register before new executions. Use compiled Global Scan, four contextual equality configurations, and direct conditional execution. No timing comparison or new baseline.

Progress sources combine a kept permit and propagation history with a choice between perpetual rewriting and a finite path containing equality, guarded two-head consumption and a fresh alias shared by outputs and residuals. Reverse choice arms and propagation-rule position independently: four sources × six configurations. Require the independently constructed finite answer within 200000 service calls, then require 1024 further calls without another answer or exhaustion. Drop the engine and compare the retained answer again. This is bounded service evidence, not a theorem about arbitrary fairness.

For lowering, reuse the independently qualified resource-fusion source families plain, choices, duplicates, shared and spare. Vary producer count 0 through 3. Compare each original path and a certificate-selected path against the independent scalar evaluator's complete raw answers. Include three changed queries: eligible original query; one permit removed when available; all owner keys replaced with one shared unknown. Check certificate outcomes explicitly. The selected path uses emitted rules only when the existing certificate succeeds, and otherwise executes original source rules. Query selection is test orchestration, not a new production dispatch layer. Each finite run must exhaust within 200000 calls. Record exact admitted/rejected and execution counts from the test.

A mismatch is consequential: minimize it and determine whether the source certificate depends on a scheduling policy absent from a candidate, or whether an engine violates source semantics. Do not weaken complete residual, multiplicity or alias checks. Cutoffs are unresolved progress, not exhaustion. Check default and feature-off builds and scoped strict Clippy. No compilation, time, allocation or universal architecture claim follows.
