# Bounded equality draining after source quiescence

Following matcher settlement, test whether draining unrelated equality after no source application is found reduces engine advances without changing complete fixed-priority observations. This is a source/work qualification before lifecycle timing. It repairs an observed scheduling cost; it does not substitute for measuring readiness analysis.

Implement an explicit ready-scheduled advance in the existing relational engine. Ordinary eager advance remains a comparison. At body-free boundaries settle matcher-relevant equality before selecting a consumer. If no source application can fire, drain remaining equality up to the call's deduction budget, then yield if work remains. Every call has a nonzero explicit deduction budget, shared by readiness and quiescent draining. Never publish with pending equality, and discard failed interpretations. Rotate the frontier after yielding so other branches receive service. Do not drain across pending source effects: early failure must retain its saving.

Qualification corpus: the existing 72 separated/shared source configurations, at budgets 1, 8 and 256 (216 cases); the original 24 priority configurations at those budgets (72); posted-request, constructor, repeated-variable and shared/disjoint resource cases at those budgets (63). At depth 64, separate successful output with budget 256 must use fewer advances than the previous 72, with complete independent agreement. Success at budgets 1 and 8 must also complete correctly. Add cancellation after actual consumption with equality pending, prepared reuse, and a two-branch source whose long pending equality must yield to a short branch. Verify the per-call serviced deduction bound by test-only observation of the servicing boundary, not timing.

Two serial frozen confirmations, 60-second process timeout and CPU limit, 1 GiB address space, 100,000 source advances per case. Test diagnostics are separate from production cost claims. Run scoped Clippy. A mutation that drains before pending source failure must violate the early-failure work assertion; a drain without the budget must violate bounded service. Preserve raw entry failures and freezes. At the result register lifecycle timing and requested heap costs for full settlement, selective settlement and bounded draining, with preparation reused across changed queries; compare the value of that pilot to partner plans and graph lifecycle work. ## Confirmation corpus freeze

The qualified suite records 351 complete-source equivalence rows (117 existing configurations × three budgets), 216 detailed separated/shared work rows from the same 72 configurations, nine cancellation/reuse rows and three branch-service rows. Detailed work rows are repeated observations of the separated/shared subset, not additional source diversity. All 14 library tests must pass, and the prior 120 readiness, 24 priority and 12 early-failure rows must reproduce. Both scheduling mutations must fail the named work/budget assertions. Budgets limit equality deductions, not total elapsed time or matching work per call.

Read metadata is owned by `Prepared::new_ready` and reused by its query engines. The final interface takes only a deduction budget; callers cannot supply another program's read set. The semantic fixture-entry freeze is retained separately, and final confirmations use this owned association. Ordinary preparation does not infer readiness metadata.
