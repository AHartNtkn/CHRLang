# Registered fresh-derivation source gate

The [post-pilot review](../results/S03-pulltab-postpilot-review.md) selects this mechanism before further local-lifting precision. Existing prepared demand plans encode single rule bodies. The new reusable object is an input-dependent residual plan formed by following multiple source calls. Cache it per query, keyed by predicate and already closed constructor arguments, then instantiate fresh graph identities for every distinct source application. This is memoized partial evaluation/runtime specialization as well as a derivation-reuse proposal; neither name supplies independent architectural evidence.

The first compiler follows known, nonoverlapping linear heads and ground-input tail calls. It substitutes head inputs and alpha-renames each entered clause's remaining locals. It may retain explicit choices and failure in the template: these are operations to instantiate, not cached concrete results. At an unresolved/non-ground call, a resource-matching boundary or a producer/effect prefix, retain the ordinary source operation. No resource claims or choice births occur during template construction. The root still completes normal head/resource matching before using a template; resource-headed roots initially remain outside template eligibility.

Use a maximum of 64 followed source calls per template and 64 retained templates per query. Cache-key discovery reads only existing closed constructor nodes, without forcing calls or choosing alternatives, and has a 4096-node bound. These are explicit experimental resource bounds, not rejection criteria for the architecture. A retained source call at a boundary continues through the ordinary source executor. Template lookup/construction, key ownership, fresh instantiation and retained memory must all be charged in later costs.

First test a recursive constructor-input chain with repeated equal-input applications, fresh unknowns and nondeterministic endpoints. Compare two uses of one application with two separately born applications: the former must remain correlated and the latter independent. Include distinct keys, branch-local calls, residuals, off-output failure, a finite sibling beside recursion, and consuming operations at retained boundaries. Check complete answers independently against the scalar evaluator and compiled scanning/indexing on confluent witnesses; retain explicit scheduling-policy limits for nonconfluent programs.

The structural gate must demonstrate that source-call discovery/expansion across multiple rules was eliminated, that a template was actually reused, and that concrete choice/unknown identities were not reused between applications. No comparative timing is authorized by this correctness registration. At the gate boundary compare a cost/work experiment with broader integration and reusable compiler artifacts; establish equivalence to input-dependent source specialization where applicable, rather than counting it as two independently tested architectures.

### Construction-size bound

Inspection identified a ground accumulator that doubles on each followed call. The 64-call bound alone does not bound template storage. Limit construction to 16,384 copied term/plan nodes, including substitutions and match bindings. If entering a clause would exceed that budget, retain that source call; if constructing the initial body would exceed it, decline the template. Validate a duplicating-accumulator source against complete independent answers and inspect that its continuation survives the bound. This is a resource guard on specialization, not a source cutoff or a failed computation.
