# E15 — mechanism composition

First compose the validated E06 finite net unifier with E09's sealed source and
scheduler services. The net executes equality only; source matching, guards,
occurrence/history handling and observation remain the existing independently
checked host mechanisms. This hybrid is not a complete net-compiled CHR engine.
Keep the reference and direct control independent. No silent backend substitution.

## Source/net boundary gate

Prepare a fixed, explicit constructor-name table and compile the net rules once,
outside request admission. Encode arbitrary finite source terms using App(name ID,
children), Ref(variable ID), unary IDs and Cons lists. Preserve variable IDs and
all original substitution entries. Yield through term/list/ID encoding, existing
net build/reduction/validation/readback, term/list/ID decoding and original-table
validation. Unknown names, malformed data and incomplete jobs cannot publish.
A failed request returns failure without a partial source substitution; a successful
request returns its complete decoded substitution. Host allocation remains outside
a hard real-time guarantee; account for preparation separately in later costs.

First check all 432 independent Rust reference requests at quanta 1,8,64, with a
2,000,000-action request cap and exact counter replay. Compare the joint projections
of all three source variables, allowing representative renaming but preserving
alias relationships. Verify the original table on success and failure. Add explicit
constructor/variable codec round trips, occurs failure and withheld publication.
These are boundary checks, not complete source correspondence or a scheduling
comparison. After this gate integrate the source transition, then validate projected
states (not raw union-find representative orientation), applications and scheduler
behavior before comparative execution. Other E15 interactions remain open.

## First composed source gate

After the boundary gate, inject the prepared equality service into the source-step
adapter as an explicit factor; direct unification stays independent. Give each
request the full immutable substitution snapshot and publish its complete result
only on success. Charge snapshot transfer as well as codec/net work.

At quantum 8, check all 64 E00 cases with the fixed scan selector and their existing
source-step budgets/answer limits. Keep the 2,000,000-action per-source-step cap.
Compare each continued/forked state to the independent control: exact occurrence IDs,
history, fresh counters and goal structure, plus joint-alpha projections of every
allocated variable, selected output, stored term and pending goal operand. This
permits a different alias representative without losing an original variable's
relationship. Raw substitution-table ordering is not semantic state equality.
Check final full residual observations, raw multiplicity and exhaustion/prefix
contracts against hand expectations and Rust reference. Prepare a sorted vocabulary
from the full finite rules/query before execution; include its preparation cost in
later measurements. Retain resource failures for investigation. This gate uses
atomic FIFO source-step ordering; integrated scheduler comparison remains next.

## Policy integration work comparison

Supply the prepared equality service explicitly to Search and all admitted source
jobs. Compile once per search; never select a backend from runtime failure. Compare
direct and net equality under FIFO, round off/on grouping, and async off/on grouping
(identity comparator, batch 8 except singleton FIFO). Fix source selection to scan.

Validate all 62 exhausted E00 cases at quantum 8 for both services (620 configurations).
Then run all 12 E09 controlled probes at quanta 1,8,64 for both services and five
policies (360 configurations), including the registered recursive finite prefixes.
Require full observations, raw multiplicity and exhaustion/prefix contracts.
Use a common 20,000,000-action run cap: the source gate's largest net case already
requires 6,300,045 actions before scheduler bookkeeping. Retain failures; this cap
is an experimental resource bound, not a language limit. Run exact replay.

Record all action categories, first/per-answer publication indices, source jobs,
represented transitions and queue peaks. Compare policies within each service;
separate alias/table representation effects on grouping from net operation cost.
Compilation/name-table preparation is explicit but outside these action counts;
subsequent timed/storage measurements must include it. This is not a native-speed
comparison. Test interleaved branch failure and a finite sibling of recursion through
the actual injected service before the matrix. Other E15 combinations remain open.

## Controller-status maintenance control

Compare terminal slot scanning with a maintained live-controller count. Compile
one controller-count delta per rewrite rule during service preparation, not request
admission. Public graph construction classifies each allocated tag; a completed
rewrite applies its precomputed delta once. Internal RHS allocation must not also
apply public-allocation updates. Controllers are exactly live tags other than DATA
and Out, matching the scan criterion. Check the maintained count against a fresh
full scan after each completed primitive in focused tests, including stuck graphs.

Charge one maintenance action per public allocation and per rewrite, plus one
terminal count check. The fixed rewrite signature bounds each delta update. Do not
claim maintenance is free. Both modes still build, reduce, decode and preserve the
original table; only status validation differs. Compile metadata once per prepared
service and include it in subsequent preparation measurements.

First run 432 reference boundary requests at quanta 1,8,64 for counted status
(1,296 configurations), plus the 64 composed source cases at quantum 8. Require
exact semantic/counter replay, original-table preservation and the existing source
projection checks/caps. Reproduce the 1,296-row scan boundary control. This first
comparison attributes service work; complete policy time/storage remains next.
