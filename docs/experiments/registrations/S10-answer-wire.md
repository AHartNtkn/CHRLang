# Common owned answer bytes before lifecycle comparison

Qualify equivalent publication for the common atom/unknown source fragment. Existing native printed constructor trees and Rust Answer structures are different physical endpoints. Introduce one explicit binary grammar, with consumer-owned bytes and predicate/atom dictionaries. This package is correctness and ownership evidence, not comparative timing.

Each answer starts with byte4. Terms are byte1 for an unknown or byte2 for an atom, followed by a little-endian u32 identity/dictionary index. Byte0 ends the output list. Each residual occurrence starts with byte3 and a u32 predicate index, then its terms and byte0; another byte0 ends the residual list. Preserve occurrence multiplicity and output order. Do not sort answers/residuals or alpha-canonicalize inside the encoder. The independent decoder checks complete answers outside execution. Dictionaries begin with sorted source predicates/atoms and append sorted query-only names; their lifetime and construction costs belong to the complete consumer boundary.

Native publication writes directly into a separately allocated byte vector. Transfer that buffer to the consumer, including its capacity; no pointer into the native graph escapes. Eliminate the memory-stream dependency from this encoder. The ownership build meters vector capacity, poisons reclaimed native query storage and retains bytes through prepared-state disposal. The ordinary build uses libc allocation and records serialization/transfer/disposal phases. Keep finite service unchanged. Adapt frozen native harnesses in a separate directory, retain their source hashes and audit changes. Use the existing1,048,576 accepted-call bound for substantive queries, quota8,15-second wall/10-CPU-second processes and96-GiB virtual-address allowance.

Rust builds dictionaries from source syntax and extends them per query. Its consumer object owns both the dictionaries and encoded bytes after typed answers are dropped. Add an explicit --wire option to the qualified common-source adapter; ordinary output remains the control. Validate dictionary contents against the independent source compiler rather than assuming two encoders share IDs correctly.

Replay all383 native prepared schedules and all96 substantive queries with ownership and ordinary builds. Recheck cancellation prefixes, raw complete answers, pending status, call counts and used graph words against their frozen observations. Retain consumers through session disposal. Check all applicable Rust configurations on the125 common and96 substantive queries, including ordinary finite and checked kept-read solving. Unsupported admission remains separate. Rust bounds stay15seconds/10CPU/1GiB. Compare decoded complete multisets with independent expectations, not merely successful parsing or equal byte counts. Test a fixed format vector before engine integration.

Before any cost matrix, the subsequent runner must charge dictionary construction/retention, source emission, representation conversion, counter settings, timing overhead and allocator scope. A smaller encoded result is not a performance result or a universal architecture preference.
