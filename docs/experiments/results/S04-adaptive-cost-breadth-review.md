# Next investigate reuse across callers with resource effects

Select T075 to test whether reusable computation can cross a caller boundary with live consuming effects. Existing private-call reuse rejects those effects; generalized continuation reuse already tests renaming and history relevance. The next experiment must investigate the missing effect dependency, not repeat those established capabilities.

The [adaptive cost pilot](S04-adaptive-cost-pilot.md) completes four packages: stateless eager qualification, ownership qualification, exact timing-runner qualification and comparative timing. No adaptive policy is selected. The research goal remains active.

## Why this experiment now?

**Effectful reuse could replace repeated execution beyond the current private fragment.** The existing call-reuse tests reject extra consumed tokens, kept facts and external constraint bodies. Testing reuse with current resource identities, fresh outputs and caller interference can therefore change which source programs admit reuse. A favorable outcome would justify a broader reuse implementation; a counterexample would bound a concrete transformation and direct investigation toward finer dependency tracking or resumable effects.

**The strongest ready alternative is targeted adaptive timing attribution.** It needs less semantic implementation and could resolve whether a policy wins in particular fixtures. However, it cannot by itself decide adaptive selection beyond those fixtures, and the current separated comparisons already show stronger contrary controls. No architecture choice currently depends on resolving a near-tie between the measured caps. This is a priority decision, not a claim that more timing precision is useless. Reconsider it at the effectful reuse source gate or any obstruction, before choosing the next package.

**Native local ownership has broader concurrency consequences but more prerequisites.** Dynamic choice and failure handling, publication ordering and descriptor lifetime still need source qualification. Effectful reuse offers a narrower independent source question using existing independent evaluators. Conditional equality/lifetime repair and incremental projection remain credible alternatives; their next comparisons appear below. Familiarity with adaptive code supplies no reason to extend its cycle.

## The next concrete gate

Before implementation, register a bounded source family where otherwise equivalent calls encounter distinct live resource occurrences. Compare direct whole-source execution with reuse that validates and transports current resource effects. Include competing consumption, a kept fact, caller-visible intermediate effects, late bindings, shared aliases, duplicate derivations and fresh returned identities. Treat these as separate controls rather than assuming that one atomic call boundary preserves every interleaving.

Require an independent complete-answer comparison and explicit progress/order observations before costs. A failed atomicity assumption must change the proposed transformation or establish its precise eligibility condition. It must not be hidden by excluding every contrary source and describing the resulting fragment as general reuse. Record which responsibilities disappear, which validation remains, and whether source inference or a language restriction supplies the boundary.

If the source gate qualifies, register ownership and lifecycle measurements that charge recognition, resource validation, replay/transport, preparation reuse, retained entries, cancellation and consumer disposal. If a defect or cutoff occurs, diagnose it and compare repair with the strongest ready alternative. Revisit adaptive timing, incremental projection, native ownership and conditional lifetime at that first gate; perform another full breadth review within four independently counted packages. No timing comparison is authorized by an unqualified effect semantics.
