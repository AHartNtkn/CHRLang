# Boolean support jobs account for most conditional stream allocation

Support-job construction and servicing account for98.2% of execution allocation on the depth64 inferred alias stream, and96.3% on the distinct stream. The instrumentation preserves all measured stage bytes, allocation calls, service counts and owner populations. Repeated Boolean work is now a justified investigation; a cache or representation change is not yet selected.

## Direct allocation evidence

The [prospective registration](../registrations/S08-support-allocation-attribution.md) repeats the eight stream-attribution cells twice. All16 processes complete and exactly replay. ## Architectural consequence

The large allocation gap is primarily in conditional Boolean work on this stream, rather than exporting the complete owned answers. An output-layout change cannot explain most of this witness's gap. The preceding cross-query study independently found equal retained output bytes across these engines; residual-output layouts remain a separate question.

This result does not distinguish necessary Boolean work from repeated temporary computation or expensive implementation choices. Each apply job currently owns a continuation and memo table; immutable canonical support nodes live in the arena. A completed operation can in principle remain valid in its own append-only arena, but profitability, cache keys, retention bounds and source-level effects require evidence. Cheap operations, sparse reuse and changed contexts are necessary contrary cases.

The next bounded experiment should count operation identities, cheap root identities, repeated substantive operations and work spent on their first and later evaluations. That can select between stronger local identities, bounded operation reuse and a different support representation. Preserve unchanged source work and complete observations before any cost comparison. Do not introduce collection solely because exhausted occurrence records are dead: earlier future roots remain unproved.
