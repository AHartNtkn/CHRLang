# Guarded search releases finite owners; allocation regimes differ

All four search paths release their finite query state and retained answers under the registered checks. Their allocation traffic differs enough to justify a runtime comparison. The local graph requests less memory than compiled scanning in some cases and more in others; this is no architecture ranking.

## What was tested

The comparison uses the existing local copied graph, compiled Global Scan/Indexed and contextual searches. Four source families place equality before or after nested alternatives, or place failure before or after the branching work. Every successful alternative enables a guarded two-head consuming rule and returns fresh aliased variables. Changing queries vary variable namespaces, inert payload values and whether a caller output aliases the result.

The registered matrix crosses those four families with choice depths zero/three, zero/eight inert facts, one/eight queries per preparation, and immediate/two-answer/all-answer retention. There are 96 scenarios per engine. Complete finite answers are checked against the independent scalar evaluator before measurement and again outside each query's phase measurements.

| Validation | Scope | Finding |
|---|---|---|
| Allocation confirmation | 384 configurations, twice each | All 768 processes pass; each pair has identical phase readings |
| Ordinary allocator | 192 configurations spanning early equality and late failure | Complete retained answers remain correct after preparation disposal |
| Cancellation and reuse | Four engines, two allocator builds, twice each | All 16 processes deliver the expected finite answer beside recurring work, cancel, and reuse preparation successfully |
| Exact live endpoints | Immediate-release queries and every final disposal | Query release restores prepared live bytes; final release restores the initial live bytes |

The cancellation witness checks the expected residual and its fresh alias, then runs another 32 nonterminal service turns before cancellation. It does not establish arbitrary fairness or bounded memory for indefinite execution. Finite queries have a 200,000-turn limit; processes have 60-second wall/CPU and 1 GiB address-space bounds. None reaches a cutoff.

## What the allocation readings mean

Preparation, query setup, service with answer construction, search disposal, consumer release and preparation disposal have separate readings. Local and contextual service return constructed answers, so execution and observation are charged together. The harness preallocates result containers and builds source/oracle fixtures outside these intervals. Their capacity is excluded; engine allocations and the contents of delivered answers are included. No timing or RSS was measured.

Immediate release gives an exact per-query restoration check. With retained answers, the experiment records live endpoints and verifies answers after preparation disposal, then checks exact final restoration. It does not independently identify each internal owner during retained-query intervals. Finite release therefore qualifies the next comparison without proving sustainable lifetime or optimal retention.

Summing the nonoverlapping phase requests gives the following bounded diagnostic contrast:

| Local graph requested bytes relative to | Lower | Higher | Equal |
|---|---:|---:|---:|
| Compiled Scan | 60 scenarios | 36 | 0 |
| Compiled Indexed | 96 | 0 | 0 |
| Contextual search | 15 | 81 | 0 |

These counts describe this matrix; they are not workload weights. Requested bytes measure allocation traffic, not live footprint or CPU cost. The opposing comparisons show why the earlier deterministic graph-scan result cannot decide this choice-capable path. The contextual organization is a consequential control for the next cost trial.

## Next decision

Register a counter-free runtime pilot over these qualified paths, including preparation reuse, first/full answer delivery, cancellation and disposal. Keep allocation diagnostics separate. Vary branching and copied payload independently of useful matching/equality work; include the favorable and adverse allocation cases above. Attribute a consequential loss before deciding whether a representation change could reverse it.

Joint structural theory/source integration remains the strongest ready distinct alternative. It could expose interactions between separately qualified theories, but needs a combined source contract before costs. The runtime pilot takes priority now because all four competing paths have qualified finite endpoints, and the allocation contrasts could reverse the practical choice suggested by deterministic measurements. Demand-driven expansion and conditional retention remain required; neither is answered by successful branch disposal.

This is package three after the normal/neutral breadth review. One further package triggers a full breadth review, whether runtime evidence favors the local graph or a control. Broader integrated mechanisms, sustained ownership, language tradeoffs and complete architecture comparisons remain open. The research goal remains active.
