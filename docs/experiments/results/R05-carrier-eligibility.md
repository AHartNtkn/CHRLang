# Pure-carrier eligibility evidence (T053)

A bounded contextual contraction is feasible. The prototype can avoid intermediate
occurrence creation, index maintenance and repeated selection while preserving
ordinary branch application order, exact occurrence identities and full answers.
It stops before the terminal rule and preserves finite sibling service. This is a
semantic and implementation gate, not a performance result or a general eager
relation optimizer.

The [reviewed design](R05-carrier-eligibility-design.md) explains why this question
has greater current decision value than further storage tuning. A valid direct
path could eliminate the pure countdown work in the remaining favorable
conditional case. Whether its complete lifecycle actually does so economically
is still unresolved.

## Implemented boundary

`PreparedRuleset::contract_carriers_inferred` derives plans from source structure;
`contract_carriers_checked` rejects requested predicates that do not qualify.
Existing sealed specialization and Global policy are required. Every head use of
a carrier predicate must be one of exactly two sole-removed-head rules. The
unguarded interior rule reposts only the same predicate, replacing one unary
constructor with its child and preserving distinct opaque slots in place. The
child slot is distinct from every opaque slot. The terminal head discriminates a
nullary constructor at the same position; its other patterns, guards and body
remain ordinary. Constructor identity includes both name and arity.

At each ordinarily selected interior step, the engine checks that only one live
carrier occurrence exists. It commits that first application and repost normally,
then inspects the remaining control one dereferenced node per service visit. The
scan changes neither bindings nor live occurrences. A finite spine ending at the
certified base permits direct replacement with the terminal occurrence, reserving
exactly the intervening fresh IDs. Ordinary remove/insert performs final index and
dependency maintenance. The engine returns to ordinary selection before the
terminal rule, including its guards, equations, failure or alternatives.

An unknown or malformed tail continues ordinary nonbinding execution. A rejection
token follows only the same selected/reposted occurrence chain, preventing a
quadratic series of unsuccessful scans. Equations clear it so a subsequently
bound tail can qualify. Other occurrences do not inherit that admission decision.
Cancellation disposes of partial scan state, and prepared rules remain reusable.

## Independent validation

All 13 carrier tests pass with counters enabled, disabled, and disabled alongside
arena sharing and fork diagnostics. The workspace suite, strict Clippy and
formatting also pass. [Receipts](r05-carrier-gate/) retain RED/GREEN, configuration
and workspace logs. Root inspected the selected service boundary and primary
replacement. Independent read-only review found no semantic blocker in inference,
singleton admission, ID reservation, index maintenance or rejection-token lifetime.

The tests establish the following outcomes:

| Gate | Evidence |
|---|---|
| Primary direct replacement | Depths 0,1,2,8,32 preserve the full aliased `done` observation and analytic final ID n+1. Logical application counts agree; certified interior work is identified separately. |
| Exact trace and audit | Expanded source commits match ordinary rule/ID traces and individual before/after audit views, then replay through an independent source evaluator. |
| Renamed syntax and control position | Three positions and unusual predicate/constructor names preserve opaque aliases and terminal binding/observer behavior. No workload name is recognized specially. |
| Multiple carriers | A concrete competing terminal-effect witness retains the short carrier's first winner and the long residual result, with zero contractions while both coexist. |
| Repeated control variable | `p(s(X),X) -> p(X,X)` is rejected; a finite spine does not justify its repeated-variable match. |
| External uses and interior effects | Carrier observers, repeated-variable steps, guarded steps and extra body work fail eligibility. |
| Unknown tails and later binding | Unknown, malformed and partial controls preserve residual behavior; a later equation can enable renewed contraction. A 32-node unsuccessful scan is not repeatedly performed along the same chain. |
| Terminal patterns and guards | Repeated terminal payload requirements remain nonbinding and are selected normally after contraction. |
| Terminal alternatives and failure | Both primary and traced paths preserve two raw completions and one source failure; independent branch replay and split-prefix work accounting validate the result. |
| Renewed singleton admission | After one contracted chain, a later rule creates two carriers. They retain ordinary execution, with analytic final IDs 7,14,15, three aliased residuals and exactly four earlier contracted steps. |
| Service and cancellation | A finite sibling completes beside source divergence; partial validation can be cancelled and prepared rules reused. |

Trace/audit mode uses the certified job but expands virtual applications through
ordinary commit and insertion operations, without selection. Its diagnostic costs
are real and charged in that mode. The primary endpoint has separate analytic and
full-view tests; diagnostic expansion alone is not its proof. Source application
counts include the logically corresponding applications, so those counts must not
be presented as physical dispatch counts.

The search contract preserves complete raw multisets, per-branch source identity
and finite service. Administrative tick counts and inter-branch completion order
can change, as with existing access/selection implementations. No exact-latency
or constant-time service promise is inferred. The resumable scan specifically
limits the new validation work per visit.

## Complexity and next experiment

The prototype needs a source plan, a per-engine resumable job, a narrow rejection
token and diagnostic expansion of certified applications. It leaves bindings,
occurrence order, terminal arbitration and general CHR execution intact. This
adds implementation obligations even though it avoids repeated intermediate work.
It does not require a mandatory language declaration or a restriction on programs
outside the inferred fragment.

A material measurement issue remains: unselected engines currently retain the
job storage and checks. The next task must provide a feature-off control or another
matched baseline that avoids making the incumbent pay candidate-only overhead.
Charge certificate preparation, validation, normal lookup, cancellation state,
observation and disposal in the candidate. Include depth-zero/small and rejected
control cases, plus the current arena ownership option where appropriate. Keep
trace/audit expansion out of primary timing and counters out of primary builds.

T054 selects that control isolation and a prospectively registered complete-path
comparison with competent explicit and conditional execution. It can determine
whether source lowering changes the bounded sharing recommendation. A mere
successful certificate cannot answer that cost question. Further storage tuning
remains lower priority; no broader contextual certificate is automatically queued.
T053 is complete and the architecture goal remains active.
