# Portfolio review: test surviving mechanisms together next

Test demand execution on sources that combine nonground posts with substantial consuming continuations. Compare the complete paths with existing explicit execution and qualified source-derived elimination. This can reveal whether the measured demand benefit survives work that a compiler can remove or that another executor can share.

The review follows call-reuse lifecycle costs, reserved-token selection, candidate borrowing and its targeted confirmation. The four-package interval is complete; the review count resets to zero. The research goal remains active and all unanswered comparisons remain required.

## Why this question has the greatest immediate value

The [candidate-borrow result](S03-candidate-borrow.md) confirms a real repair but leaves unsuccessful demand discovery costly. The [call-reuse comparison](S05-inert-lifecycle.md) finds substantial complete overhead despite reuse. The [reserved-selection comparison](S02-reserved-selection.md) eliminates duplicated source work but leaves a large complete-control gap. Another local repair can improve one component; none establishes how the surviving mechanisms interact.

Composition has already exposed consequential effects. [Fusion](S10-composition-lifecycle.md) increased eager tuple discovery; [post-choice work](S10-post-choice-work.md) showed real shared consuming execution alongside adverse allocation; the [resource-phase comparison](S06-capacity-phase-costs.md) showed that source-derived elimination can repay additional allocation. These results justify testing actual interactions rather than adding component costs or choosing from isolated winners.

**Select T078: a bounded mixed-source semantic/work entry, followed by complete costs.** Build from existing nonground post and post-choice source fixtures. Require common consuming work, independent work and early failure; vary choice count, continuation depth and arrival order independently. Preserve propagation history, duplicate resource identity, fresh aliases and complete residuals. Compare the repaired demand policies, direct conditional execution and existing generated/activation controls. Include a source-derived elimination control wherever its actual certificate accepts the source; qualification failures are explicit results, never oracle-generated shortcuts.

First establish that at least two coherent complete execution paths run these sources correctly and that the proposed saving actually occurs. Record each path's responsibilities and accepted program fragment. Then register exact lifecycle configurations, repetitions, limits and interpretation before comparative timing. Charge inference/certification, preparation, changing-query setup, execution/observation, consumer retention and disposal. Compilation remains explicitly unmeasured until isolated. A source gate cannot stand in for the cost comparison.

This is a new interaction experiment using existing baselines. It is not a new baseline project. Do not force incompatible engines or solvers into one path to satisfy a composition label.

## Strongest alternatives and the next review boundary

| Alternative | Decision it could change | Why composition goes first; when to reconsider |
|---|---|---|
| Sound demand discovery/normalization repair | Whether the remaining miss penalty is avoidable | The copy repair now has bounded evidence. Mixed sources determine whether that remaining penalty limits a complete competitor; reconsider at the source gate or obstruction. |
| Cheaper/coarser call recognition | Whether more useful work can be reused per lookup | Requires distinct relevance, fresh-result and invalidation semantics. Keep it required; compare its entry cost and consequence at the same boundary. |
| Broader integrated representation/persistent eligibility | Whether integration avoids encoding, ancestry or discovery costs | The bounded token repair cannot settle this. Reconsider an independently useful capability at the same boundary, without demanding a local timing win first. |
| Sustained ownership/publication | Whether retained paths remain viable over time | Mandatory once the mixed gate establishes a surviving retention mechanism; start earlier if that gate exposes growth or progress failure. |
| More compact/prefix timing precision | Whether near-threshold savings justify a specific policy | Preserve uncertainty. Run confirmation when an actual composed-path choice depends on it, not merely to fill a classification. |

At the first mixed source/work result or obstruction, compare advancing to lifecycle costs with those alternatives. Do not allow repeated entry refinements to displace primary costs indefinitely. A full portfolio review is due within four further experimental packages, sooner if a finding changes an architectural premise.
