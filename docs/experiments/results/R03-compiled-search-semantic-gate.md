# Compiled explicit search: independent semantic gate

The compiled control now executes source OR directly in generic and generated native bodies. It passes independent full-answer and branch-resource checks, including finite sibling progress beside recursive work. This supplies a missing ordinary execution control for R04's finite solver comparison and R03's conditional-execution question. It is correctness evidence, not a search performance ranking.

[Registration](../registrations/R03-compiled-search-semantic-gate.md), [default finite receipt](R03-search-gate/default-finite.json), [counter-free finite receipt](R03-search-gate/off-finite.json). Each receipt covers 338 queries ×48 configurations: generic/generated, global/active, scan/indexed and six rule orders. Together they check 32,448 query/configuration executions. Full observations, raw multiplicity per observation and exhaustion match the independent Cartesian assignment oracle. Actual engine/kernel instrumentation flags match each build. Hidden choices retain three raw completions despite one observation; repeated choosers of the same variable retain three successful assignments rather than nine.

## Branch responsibility and publication

A source OR produces two owned continuations. Both inherit pending conjunction work, values/bindings, occurrences, indexes, watches, activation state, propagation history and fresh-identity supply. Prepared rules and dispatch are immutable shared data. Initial storage uses a full arena/branch copy, with persistent binding maps retaining their existing structural sharing. It is a concrete copying control, not a claim that copying is the best storage organization.

The driver services one branch engine step per FIFO visit and appends both children at a split. Finite existing branches continue receiving service as other branches recurse or create alternatives. Each individual operation, body lowering and branch copy still has size-dependent cost; the gate makes no constant-time service claim. Competing CHR applications keep the ordinary engine's selected policy and do not produce implicit alternatives.

An ordinary branch exposes `pending_split` and cannot publish while OR is pending. `start_search` or `into_search` transfers branch ownership to the frontier. Operational events report split, successful completion, failed completion and exhaustion independently of metrics. A completed branch transfers its engine to the caller, who owns observation and disposal. Equal displayed answers remain separate raw events; deduplication is an independent observer operation.

Source counters belong to execution segments. A split transfers its retired segment exactly once through optional diagnostic work; both child counters start fresh while retained-state gauges carry their live values. Terminal events retain their final segment. Thus monotone counters can be accumulated over split and terminal events without losing or double-counting prefixes. Gauges are not additive. Counter-free builds return no diagnostic segment allocation; scheduler diagnostics also remain off. This ownership rule is tested with a shared choice prefix and two consuming children, totaling three applications.

## Independent validation

Hand fixtures run across all eight execution/policy/access combinations. The checker reconstructs each completed or failed branch from owned source syntax, its occurrence tuple trace and explicit choice lineage. It uses its own substitutions, nonbinding matching and finite-tree occurs check. Successful leaves must have the full analytic joint answer, expected live occurrence identities, exact propagation history, no pending source choice and no enabled source tuple. Failed leaves must have an independently detected clash, cycle or explicit failure; an invalid application or missing choice cannot count as source failure.

The split tree accounts for every leaf: each parent becomes exactly two children, and every exhausted-run child completes or fails once. Analytic observations check duplicate raw alternatives, independent choices, a shared fresh body variable, distinct versus aliased unknown outputs, sibling consumption of inherited resources, inherited propagation, post-OR conjunctions and off-output failure. A recursive branch leaves the search unexhausted while its finite sibling completes. Repeated queries of different sizes use one prepared ruleset and separate branch lifetimes.

The finite adapter prepares once per source rule order/configuration and executes all 338 changed queries. It uses the independently registered oracle's satisfying assignments to compare the complete multiset of delivered observations, as well as the unique observation set, raw count and exhaustion. No reference evaluator is linked by or invoked in the compiled control. Source and binary hashes cover the actual generator, engine, term storage, bridge and oracle.

Workspace all-target tests, Clippy, counter-free all-target tests, allocation-feature Clippy and formatting pass. The new source-search tests run in both instrumentation configurations. No comparative timing or allocation matrix ran under this gate; branch cloning, answer streaming, deduplication, preparation and disposal remain costs to measure prospectively.

## Decision and next investigation

This control makes a direct R04 contrast worthwhile: reusable native maintaining-arc-consistency search and support-CNF learning versus actual compiled source search, with conflict-only CNF as an inference-strength control. The finite relation has an independent denotation and source correspondence; its global reasoning can avoid work that ordinary execution performs. The implementation must retain repeated forbidden occurrences in full answers and scope query enumeration exclusions correctly across reuse.

Select the finite native/Boolean semantic gate next. The strongest alternative is direct conditional activation with resource-sensitive sharing. That alternative remains open, but requires simultaneous compatibility, publication and storage protocols; the R04 fragment can now test an independent explanation for avoiding execution with fewer unresolved semantic premises. Another copying-storage refinement would not yet distinguish that explanation. A solver/native difference alone must not become a language-wide architecture claim.

Installed solver availability is a local prerequisite, not a performance conclusion: an available Z3 shared library can provide an incremental Boolean control, while native bitmask domains supply the inference-matched comparison. Verify API/version and isolate its memory accounting before measurements; Rust requested-allocation counters do not cover external C allocations. Source-language adoption remains the owner's decision. OR now being executable does not close conditional sharing, solver selection, compilation amortization, long-lived reclamation or parallel coordination.
