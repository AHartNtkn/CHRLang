# Generated post execution preserves answers; activation changes discovery costs

Actual generated callbacks and generated access preserve the independent complete post answers under both Global and Active policies. Generation removes syntax and bookkeeping work, while activation helps some sources and adds work on others. These controls are eligible for the missing lifecycle comparison; operation counts alone do not rank them.

The [registered gate](../registrations/S03-post-controls.md) uses the unchanged shared post source, all six families, sizes1/8/32, both arrival orders and changed a/b queries. Three execution forms, two policies and two access methods give864 executions per run. Two diagnostic and two counters-off runs complete3,456 executions with exact repeated rows. Every completed answer is checked against scalar execution and analytical post expectations, and again after engine/source/preparation disposal.

**The policy comparison is valid for these sources because the answers actually agree.** Generated occurrence traces equal generic traces within each policy/access configuration. Global and Active traces need not agree. This does not generalize to all consuming CHR: the independently established early-consumption counterexample in the structural-prefix study remains applicable to its source.

Before each complete execution, separate states are cancelled at setup and after one advance. Preparation is then reused. The gate checks those finite lifetime boundaries, not continuing retention, arbitrary cancellation points or native parallel claims.

## What work changes

At size32, original arrival and indexed access, generic and generated forms have identical candidate counts within a policy:

| Source | Global candidates | Active candidates |
|---|---:|---:|
| Input posts | 129 | 161 |
| Output posts | 129 | 161 |
| Forward-produced posts | 689 | 257 |
| Unsuccessful matches | 97 | 97 |
| Duplicate resources | 225 | 289 |
| Repeated template input | 97 | 99 |

**Activation is not a universally cheaper access plan.** It substantially reduces forward-source discovery in this example but adds candidate work to input, output and duplicate sources. Changed readiness and source order matter; a result for one cannot select the policy for the others.

Both generated forms have zero generic AST visits. Generated access additionally has zero binding-slot copies, candidate-pool entries and key-template visits. The [audit](s03-post-controls/audit.json) includes all sizes/orders and verifies the zero diagnostics in counters-off builds. Counts are named operations, not equal-cost time units.

## Lifecycle follow-through and limits

The existing dependency lifecycle adapter now selects these generated function pointers and carries explicit Global/Active policy. Its independent post/reuse test includes all six new controls, with retained answers and cancellation, and passes in ordinary and allocation builds. Strict allocation-build Clippy passes. The initial unknown-mode failure is preserved as the adapter's failing test before implementation.

The subsequent [registered cost comparison](../registrations/S03-post-control-cost.md) compares the same post contract and charges preparation, setup, combined execution/observation and disposal. It checks allocation correspondence for existing controls rather than assuming that adding the adapter changes no costs. Actual compilation and artifact storage remain outside the pilot's measured lifecycle.

This is package two since the full prefix portfolio review. The cost comparison is package three. Demand's writable-head, dynamic-choice, broader discovery and sustained-lifetime questions remain unanswered; passive body posts do not establish those capabilities. No runtime engine algorithm or reference interpreter is changed by this gate.
