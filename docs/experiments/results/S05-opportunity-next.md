## The source and ownership questions to answer first

**Use complete answers produced progressively within one still-live search.** Repeating short queries alone cannot expose state retained until a long query ends. Begin with a finite stream whose continuation emits one answer and keeps generating later answers; vary repeated versus distinct values, output size and work between observations independently. Add failure, raw duplicate multiplicity, output aliases and consumption witnesses. Preserve the independent reference/scalar checks, and include a checked direct-source generator when it implements the same contract.

**Compare three consumer policies over the same source.** Release each observed answer immediately, keep a bounded window, or retain every answer. Record requested-live state at common answer counts and after consumer release, engine disposal and prepared disposal. Attribute the answer owner's bytes separately from the live engine's bytes. Measure ordinary service/observation costs in counter-free runs; do not interpret allocation-meter elapsed time as speed.

**Keep query-local retention separate from reused preparation.** The graph run owns nodes, contextual results, obligations and templates. The continuation search owns its machine, key map and transition nodes, including cached answers; prepared objects start fresh query owners. The compiled search owns its frontier and live branch engines. Those current code owners are hypotheses about retention, not measured lifetime results. Test both one long query and changing queries over the same preparation.

**Establish comparable delivery before timing.** Validate complete raw answers independently over bounded runs. At partial endpoints preserve the engine's valid answer prefix/multiset and finite-service behavior without imposing an unproved common order. Do not store all answers in the measurement harness merely to validate an immediate-release consumer; use an independent unmeasured replay or an exact source-derived online check with its cost explicitly separated.

## How findings change the next action

If state grows after immediate consumer release, identify the retaining owner and whether later work can still require it. Investigate reclamation, eviction or regeneration when a concrete mechanism could reverse the cost conclusion. A growing graph alone does not establish intrinsic graph cost; a flat short-run peak does not establish sustainability.

If current owners sustain delivery economically, compare the resulting trajectory against the strongest direct and lowered controls before preferring their complexity. A resource cutoff is an incomplete endpoint requiring investigation, never an architecture loss. An ordering or semantic mismatch stops dependent cost comparisons until the observation contract is established.

Register exact configurations, bounds, sampling points and repetitions after the source gate and exploratory sizing, before confirmatory runs. Revisit call-level reuse and distinct integrated execution after the source gate and first bounded lifetime package; apply the governing four-package breadth review if further refinements are proposed. Compact-output contracts, exact deduplication/indexing, publication/backpressure and broader reclamation remain distinct S08 questions.
