# Smaller incidence buckets reduce complete allocation

**Sorted-vector incidence buckets preserve the tested source behavior and reduce both total requested allocation and peak live allocation in all96 relational configurations.** The current result supports continuing to a runtime comparison, including high-degree repair; it does not select a default representation.

The [registered gate](../registrations/S02-incidence-vector-entry.md) first qualifies both ordered-set and vector builds with24 source/store/library tests each. A new16-configuration broad-incidence challenge varies width1/8/64/256, insertion order and merge order. Repeated columns and duplicate source rows survive repair correctly; equal constructor facts coalesce; exact occurrence matches and selective consumption agree with independently constructed expectations. A cloned branch receives incompatible bindings and retains its own resources.

Allocation improvement does not imply that relational execution overtakes the compiled competitor.

## What changed and why it needs an adverse timing test

Only each incidence bucket changes: an ordered set becomes a sorted unique vector under an experimental feature. The outer value map, relation keys, column indexes, source occurrence identity and equality algorithm stay in place. Binary search preserves the reference ordering and rejects duplicate attachments. Removal preserves that ordering too.

This uses less bucket storage on the measured sources, but vector insertion and removal can move a number of references proportional to bucket degree. The new broad-incidence test proves source behavior through those operations; its test duration is not performance evidence. The next registered lifecycle comparison must measure low-degree admission and high-degree merge/consumption, including reverse insertion and repeated columns, with the ordinary allocator and serious compiled controls.

No stronger language restriction is introduced. The fixture will express the broad repair as complete source execution for that comparison, and source construction, observation, cloning/cancellation and disposal will remain explicit.

## Decision

Keep the vector candidate for the next runtime experiment and keep the ordered-set control. This targets the largest measured admission allocation responsibility with a small representation change; another incidence design or graph attribution currently offers less immediate information than testing its known movement cost. Reconsider graph memo attribution, broader integration and direct solving at the runtime result. T072 remains active; package count is two since the portfolio review.
