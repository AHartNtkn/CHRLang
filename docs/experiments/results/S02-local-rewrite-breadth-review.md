# Next test call-level reuse across different callers

Advance to T075 call-level reuse. Four integrated-execution packages have made previously untested mechanisms concrete and exposed their source, scheduling and dependency obligations. A broad cost matrix now would confound those mechanisms with unequal source specialization and conservative matching repair.

## What the four packages established

The [forest gate](S02-chr-forest-gate.md) implements source-rule merging and compression over ground node identifiers. The [constructor/consumption gate](S02-chr-constructors-gate.md) adds consistency and consuming applications, with an explicit descriptor-order resource-selection counterexample. The [local handle gate](S02-local-ports-gate.md) supplies a distinct direct-repair organization and exposes selective versus broad activation. The [source-pattern gate](S02-local-pattern-gate.md) derives nested matches from a checked source fragment and finds a conservative invalidation cost.

These are correctness and operational findings. They do not establish an integrated architecture's total efficiency, general source support or necessary complexity. No timed comparison has been run for these new organizations.

## Selection against the strongest alternatives

|---|---|---|
| Call-level reuse with caller projection | Obtain repeated-computation savings without retaining shared execution or requiring identical whole states | Independent source semantics, compact whole-state controls and graph derivation controls exist. The missing work is a sound call boundary and fresh-result transport. Selected: it is a distinct unresolved mechanism, with a concrete witness where caller-only state defeats whole-state reuse. |
| General integrated source execution | Replace equality/matching boundaries across substantially broader CHR programs | The new operation models exist, but general heads, effects, history, scheduling and observation need implementation. | Precise local subscriptions | Avoid the conservative alias-recheck cost without losing nested wakeups | The 200-pattern oracle and exact broad witness provide a ready attribution test. Required before interpreting a material cost loss in this representation. It improves a bounded candidate rather than answering another architecture family, so it follows the distinct call-level source gate unless it blocks an immediate comparison. |
| Native lifecycle matrix for the current local fragment | Bound complete costs of the represented mechanisms | Needs counter-free builds, ordinary allocation, equal source specialization, reusable plans, owner accounting and cancellation. Required when the supported fragment can change a design decision. Running it now would risk assigning compiler/specialization differences to representation. |
| Structural solving and restoration/reconnection | Avoid enumeration or shared-state retention through other organizations | Both remain distinct required investigations in the sequence. Call-level reuse has more immediate source/control infrastructure; choose between these afterward using the new evidence. |

This is a research-order judgment, not negative evidence about integration. There are no workload weights or assumed probabilities. A favorable call-level result could change the complete architecture comparison; an adverse result would reveal which recognition, transport or resource costs sharing avoids.

## T075 entry requirement

Construct repeated substantive calls whose callers retain different pending work and output identities, so compact whole-state keys do not coincide. Reuse must execute the call once and transport fresh results into each caller while preserving raw multiplicity and joint aliases. Start from a declared source boundary, not by dropping fields from existing whole-state keys.

Challenge the boundary with shared live resources, later bindings, propagation history and similar calls whose future effects differ. Compare independent full-source observations. Distinguish a provably isolated call from a checker that misses an eligible case; do not infer that all callers are irrelevant from a pure example.

The first package must establish either this mechanism or a concrete counterexample to the proposed projection. Reconsider T072 precise dependencies and broader integration after that gate; reconsider sustained lifetime, structural solving and restoration as well. Register complete cost comparisons only after the validity/transport question is settled for the chosen fragment.

T075 becomes active. T072 remains pending for the stated required work; T074 lifetime and the rest of the mechanism schedule remain unfinished. The overall architecture goal stays active.
