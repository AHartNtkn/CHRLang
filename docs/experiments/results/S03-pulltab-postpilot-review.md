# After the local-lifting pilot: investigate fresh derivations

The next package should test reuse across independently born applications, with fresh choice identities and resource effects preserved. The local-lifting pilot now has a credible complete-cost comparison and contrary cases. Another local timing refinement would answer a narrower question than this still-untested execution mechanism.

## Evidence used in selecting the next package

The [pilot](S03-pulltab-lifecycle.md) shows no confirmed practical lifting gain, four bounded losses and 76 unresolved configurations. The dependency certificate has useful measured gains, and source-derived lowering changes the long-chain comparison substantially. These conclusions survive including source/input construction and expose opposing runtime/memory regimes.

The strongest ready refinements are resolving the favorable but noisy cold lifting cells, investigating repeated result traversal/obligation service, and T073's reusable lowered-query artifacts. The cold precision work could change a local strategy choice; traversal improvements could affect both demand variants; artifact reuse could improve measured compiler setup costs. None is declared unnecessary or resolved.

Fresh derivation reuse instead asks whether separate applications can share useful derivation work without sharing their dynamic identities or consumption. Existing prepared rule plans and reuse of one call's result do not establish that mechanism. It could change what is executed and retained across calls, rather than adjust the remaining overhead of moving a choice through one call. Its correctness gate is feasible using the independent source oracle and the existing identity countermodels.

Select that gate now. The pilot has already required several useful control and attribution repairs, and the next stage of precision would continue depth in one mechanism while this distinction remains untested. Revisit the three ready refinements after the gate, comparing what each could change and the evidence required. An actual implementation defect uncovered meanwhile still requires repair.

## Required first comparison

Start from independently born source applications with repeated substantive pure work, then include distinct requests, context-sensitive values and effects. Identify the reusable object precisely: a result, a derivation template, a sequence of operations or a prepared source plan. Show what discovery or construction it avoids beyond the existing prepared rules. If two proposed mechanisms are equivalent, demonstrate the equivalence and relevant ownership costs instead of naming the same cache twice.

A reused template must instantiate fresh local identities and independently born choices; it cannot replay a resource claim as though a new source occurrence had already consumed it. Test two calls that must yield independent choice products, two uses of one call that must remain correlated, failed and residual derivations, off-output effects and finite service. Compare complete answers independently before cost registration. Dynamic source restrictions must be stated, not silently adopted as language requirements.

T071 owns this next gate. Broader S02 integration, T073 lowering/artifact reuse, S04–S05 restoration and generalized reuse, structural solving, language choices, sustained lifetime, connected parallelism and complete-architecture/held-out comparisons retain their obligations. Scheduling this gate does not resolve any of them.
