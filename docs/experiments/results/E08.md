# E08: independent factors avoid repeated product computation

All 206 registered runs pass, and a fresh-process replay reproduces every non-time field. Inferred factor counts and source application counts match the preregistered formulas. Permanent independence provides a sharing mechanism distinct from common post-choice expansion: each regional answer stream is computed once and reused in multiple complete tuples.

## Evidence and semantic boundary

Freeze: `849220a`. Registration: [E08](../registrations/E08.md). Raw results: [batch](E08-factors.tsv), [replay](E08-factors-replay.tsv). Build with `cargo build --release -p chr-factors --example factors_probe`; run `python3 research/chr-factors/run_batch.py <output-path>` twice. There are 103 finite cases in two modes, each in a fresh release process with a 60-second bound and the registered outer-step allowance. Elapsed time is diagnostic. Workspace tests, Clippy with warnings denied and formatting pass.

Seven behavior tests cover the finite E00 registry, products, coupling/future linking, fresh residual variables and absent-input output aliases, empty-factor cancellation, finite product coverage with an infinite producer, and exact regional deduplication with complete raw multiplicity. The compiler joins predicates across all heads and body postings, then joins regions across shared query variables. It does not rely merely on current variable disjointness. Same-predicate invocations remain together, even if a finer certificate could separate them.

Both modes use E01 persistent scalar execution. A single factor directly forwards its answers with no product cache, renaming or second deduplication. Actual multi-factor execution records regional and global observers separately. The reference remains independent.

## Controlled product result

For eight independent binary components, W=256 and 16 unrelated ground occurrences, Scalar performs 524,543 applications; Factored performs 4,104. Requested allocation falls from 1,953,763,443 to 12,361,158 bytes. Peak live payload above baseline falls from 42,473,352 to 5,863,800 bytes. Both return all 256 distinct full answers, including residual constraints.

Factored inference produces nine regions: eight computation regions and one noise region. Its regional raw-completion sum and retained answer-cache count are both 17; their complete raw-product count is 256. These are different quantities. The scalar engine physically completes 256 alternatives. The factored engine enumerates 256 tuples from regional results, not 256 independently executed whole-store branches.

At W=0 on the same product, applications fall from 255 to eight, but the allocation difference is much smaller: 7,296,643 versus 6,027,398 bytes. Peak increments are 5,247,288 and 5,367,224 bytes respectively. Full output composition and exact deduplication now dominate. Both perform 64,256 term-pair comparisons at their final complete-answer observer; Factored additionally performs eight regional comparisons. Factoring does not remove the cost of returning the requested product.

## Contrary evidence and application coverage

With only one binary computation and noise, source applications are one in both modes. Factoring increases requested allocation from 69,901 to 97,200 bytes and peak increment from 44,031 to 63,017 bytes. A valid certificate is not sufficient reason to expect a profitable decomposition.

The mixed addition-forward/SK-type-inference query infers two regions and returns unary five with the expected polymorphic identity type. Both modes perform eight applications. Requested allocation rises from 59,531 to 63,064 bytes, while peak increment falls from 26,655 to 24,197. This is a small application composition showing mixed costs, not evidence of synthesis acceleration.

The SK ignored-hole query stays in one region and performs 32 applications in either mode. Certificate construction raises requested allocation from 522,127 to 528,839 bytes. The identity-product path avoids an additional cache or observation pass. This result illustrates the current certificate's limited reach on a connected relational application.

## Progress and remaining work

The infinite-producer test observes the registered finite product prefix without waiting for the producer to exhaust. An exhausted empty region refutes its product despite another region looping; the scalar declaration-order control remains unfinished at its bound. This is scheduling of certified commuting regions, not arbitrary reordering of dependent rules. Service bounds remain logical-step bounds; source matching and answer composition are still atomic finite operations. Canceled engine objects remain retained until the experiment ends, so no cancellation-reclamation claim follows.

The first E08 probe is complete; the direction remains open. Finer occurrence/ownership certificates, persistent fact interfaces, temporary separation and reunion, long-stream cache policy, resumable product service and broader synthesis coverage remain feasible and potentially material. The large controlled gain justifies those questions, while the small and connected application cases prevent generalizing it to all programs.

E10 structural solving is the next first probe. It does not depend on improving the decomposition certificate. No language or production architecture decision has been adopted.
