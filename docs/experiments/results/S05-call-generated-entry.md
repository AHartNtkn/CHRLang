# Generated call matching passes; a preparation cost is repaired

**Generated matching now preserves the tested caller behavior and requests fewer
heap bytes than both corresponding generic controls in every scenario.** The
investigation also found and repaired a temporary allocation in generated-source
validation. Peak ownership barely differs between generated and generic matching;
ordinary comparative timing and compiler amortization are next.

## Same programs, same observations

The existing emitter compiled eight descriptors: four caller families in both
branch orientations. It received rules only, with recursion depths and variable
namespaces supplied later by changing queries. The shared source gate checks
768 combinations, including scan/indexed/inferred modes, complete answer order,
independent scalar bags, first-answer cancellation, 2,304 cancellation restarts,
and outputs retained beyond preparation disposal.

The gate passes in counter-free, metrics and allocation builds, both before and
after the repair. The lifecycle runner is shared with the preceding experiment;
it accepts a generated descriptor rather than duplicating measurement logic.
All 864 lifecycle processes pass in each campaign: 288 scenarios, two meter runs
and one ordinary validation run. Ownership repeats exactly, consumers retain the
same bytes as the earlier controls, and disposal restores the initial heap root.
The ordinary runs qualify execution; their timings are not used comparatively.

Generated descriptors contain native continuations and update functions. The
executor dispatches to those continuations; inferred regions use their existing
direct cursor where eligible. Thus the two configurations test generation alone
and generation combined with inferred specialization.

## The adverse result led to a repair

Initially, generated plus inferred execution requested more total bytes in
sixteen cases. Every case had one depth-four query. For example, ordinary complete
consumption added 4,592 preparation bytes while saving 3,960 service bytes.

Preparation checked source identity by formatting the entire ruleset into an
owned string. The replacement compares the **same exact formatted content**
incrementally against the generated descriptor. It still rejects mismatched
rules; it adds no hash assumption or unchecked path.

A metered unit check first failed with 248 requested bytes for a small escaped
Unicode source, then passed with zero. It also checks changed, shortened and
extended content and the public mismatch error. Full generated source gates and
the compiled regression suites pass after the repair.

Across all 288 lifecycle scenarios the repair saves **exactly 4,088 preparation
bytes**. Every other phase requests exactly the same bytes as before. Peak
ownership is unchanged, because the temporary buffer was not responsible for the
complete run's peak. All sixteen total-allocation regressions are repaired.

## Heap costs after repair

Ratios divide generated cost by the corresponding generic control. Lower is
better. Each row covers all 144 caller scenarios.

| Configuration / control | Requested-byte ratio | Cases requesting fewer bytes | Peak-live-byte ratio | Cases with lower peak |
|---|---:|---:|---:|---:|
| Generated / generic indexed | 0.739–0.914 | 144 | 0.983–1.008 | 60 |
| Generated plus inferred / generic inferred | 0.842–0.963 | 144 | 0.992–1.010 | 36 |

Generated execution also has lower peak ownership than call traces in 110 of 144
ordinary generated cases and 112 of 144 generated-plus-inferred cases. The other
cases remain real counterexamples to a blanket memory claim. The generated
controls have not yet established a time advantage or a complete architecture win.
Requested heap allocation is not RSS.

## Compilation and the next decision

The qualifying source contains 132,842 generated bytes for eight descriptors.
Initial standalone release builds took about 26–30 seconds including dependencies;
the ordinary artifact is 2,152,944 bytes. These are artifact qualification
observations, not a replicated compiler-cost contrast. The next experiment must
separate shared toolchain/dependency work from user-program emission and compilation,
compare equivalent generic artifacts, and measure changed-query amortization.

The ready decision is whether call traces' repeated-query speed gains survive
these cheaper generated controls after complete runtime and compiler costs count.
Use the existing artifact workflow for that comparison. Bounded trace retention,
broader caller observers, sparse projection and the remaining architecture
portfolio still require investigation; this qualification does not resolve them.
