# Registered local pull-tab work comparison

This diagnostic package asks whether direct-argument choice lifting avoids repeated traversal or source expansion, and what graph ownership it adds. It precedes comparative lifecycle timing. The source gate is recorded in [the source report](../results/S03-local-pulltab-source.md).

Compare pull-tabbing off/on with StaticBirth cache validity fixed. Sources have one or four consumers, shared or independent choice producers, and zero, eight or 32 identity-producing calls between each choice and its consumers. Consumers either demand a direct a/b constructor, capture it opaquely, or demand it inside a box (outside the current rewrite). Both query insertion orders are included. This gives 72 source configurations and 144 strategy executions per repetition. Independent choices produce up to 16 answers; shared choices produce two. Each answer must preserve all consumer outputs jointly and leave no residuals. The independent scalar source evaluator and hand-built complete answer set must agree before diagnostic conclusions.

Hypotheses: direct lifting may shorten repeated traversal through computed producer results, but adds two calls, two conditional obligations and one choice node per rewrite. Opaque and nested-only demand should produce no rewrites. Identity producers must not be reported as eliminated source execution merely because their result is bypassed after lifting. Shared and independent sources distinguish correlation from repeated work.

Post-execution scans count graph nodes, call nodes, choice nodes, result edges and obligations. Since each source choice birth creates exactly one original choice node, additional choice nodes count local lifts; source expansion records equal all call-result edges minus those lifts. A separate optional work-diagnostics build counts force entries, pattern-match entries and edges examined by the lift-site walk. These are different operations, not a summed cost score. No diagnostic count will be presented as elapsed time or allocator usage.

Run two exact diagnostic repetitions in a release build, with a 100,000-tick candidate bound and 200,000-step scalar bound per source. Apply 60 seconds and 1 GiB to each test process. Record raw rows, binary/source hashes and commands. Any answer discrepancy or nonidentical repetition must be investigated. No timing threshold or architecture ranking applies to this package.

If direct lifting avoids traversal but adds ownership, register a bounded lifecycle pilot sensitive to depth, consumer count and opaque overhead. If it only adds work, determine whether that follows from this source shape or the mechanism before selecting its next investigation. Nested demand, fresh derivation templates and sustained memory remain independent obligations. Compare the next package against reusable lowered-query artifacts at this boundary.
