# Next: derive reusable execution from source

**Investigate reusable source-derived lowering next.** Exact-source elimination beats the repaired shared-deduction executor in every registered configuration. The consequential question is how much of that elimination a compiler can derive, and whether checking and preparing reusable artifacts repays its cost.

This review follows four T072 packages: the shared-deduction mechanism gate, lifecycle sizing, persistent-map attribution and full-control confirmation. T072 remains unfinished; the next active task is T073. The [mechanism ledger](../remaining-investigations.md) retains all unresolved assignments.

## Why this investigation comes next

The [confirmation](S02-deduction-confirmation.md) supports compatible deduction reuse and exposes contrary regimes. Persistent maps correct an important retention cost, yet scanning and inferred specialization remain faster in every substantive configuration. More timing precision on those same sources is unlikely to change their bounded selection. This does not establish an intrinsic limit on integrated execution.

Source-derived lowering could change what runtime work an architecture needs at all. Existing exact-schema controls demonstrate achievable results for their accepted sources; they do not show that general analysis can derive them. The [pure-prefix compiler](S06-prefix-lifecycle.md) does derive a bounded transformation, but expands target source and prepares it again for each query. Its short-case losses make reusable preparation a concrete issue, not an assumed optimization benefit.

## The next package must demonstrate reusable work

Start by deriving a parameterized artifact from the accepted pure-prefix source, reusing its analysis and target preparation across changing query values. Inspect the current compiler's query-dependent rule construction and fresh-variable allocation before selecting the artifact boundary. Keep query outputs, aliases, duplicate occurrences and consuming suffix behavior intact. A cached exact query is insufficient.

Require unchanged source with changed queries, source changes that demand new preparation, and near-miss programs outside the accepted fragment. Compare the existing source-derived compiler, ordinary compiled execution and applicable exact-source controls. Preserve independent scalar agreement and directly check fresh identities, complete residuals, failures and source competition. Eligibility must be inferred from source or recorded as an explicit language condition.

This first package establishes mechanism and correctness before timing. Then register a bounded lifecycle comparison that charges analysis, retained artifact, per-query setup, complete observation and disposal, with one-shot and repeated-query adverse controls. Ordinary native compilation, if introduced, must have separate credible accounting. Do not call repeated target preparation reusable compilation.

The broader T073 obligation includes recursive lowering with an effectful or unknown-input boundary and resource-aware derivations. A reusable pure-prefix result cannot discharge it. If reuse merely shifts unavoidable work, record that evidence and move to the broader discriminating source gate or the strongest alternative; do not keep tuning the accepted fragment automatically.
