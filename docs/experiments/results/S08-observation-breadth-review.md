## T075 entry obligations

Begin with independent source pairs that reach the same future computation through different histories and fresh names. Include near misses with different live resources, propagation histories, output aliases, pending effects and later bindings. Separate call-level reuse from whole-state reuse: different caller state may be irrelevant to one and essential to the other. Do not merge them merely because both use a map.

Define key soundness before optimization: equal keys must support equivalent future observable behavior with explicit transport of fresh identities and output bindings. Preserve raw answer multiplicity outside reuse recognition. Existing unique-answer presentation is not sufficient proof. Compare exact IDs, renaming, sound relevance projection and direct recomputation on the distinctions that survive analysis.

Only then register complete costs, including key construction, lookup, validation, replay, retention/eviction, changed queries and disposal. Use the strongest relevant corrected graph, compiled or exact-source control when it implements the same contract. Charge owned serialization if used; investigate stable representations when that cost could change the conclusion. Do not require the current key interface if it obstructs the mechanism being tested.
