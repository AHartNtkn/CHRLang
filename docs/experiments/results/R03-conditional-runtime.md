# R03 direct conditional runtime gate

The conditional engine now executes complete queries and passes an independent finite source gate. It discovers applications through occurrence insertion and equality-demand notifications, executes supported source bodies, and publishes full answers from certified support. A consuming application can serve two source histories without running a separate machine for each history. This establishes bounded semantic and mechanism evidence; comparative efficiency remains unmeasured.

## Execution and completion responsibility

The runtime indexes occurrences by predicate and arity. Insertion discovers injective ordered head tuples; equality demand dependencies retain positive and negative eligibility interests. Binding changes enqueue affected tuples with the changed support. Candidate ordering follows source rule order and occurrence tuple order. Discovery retains historical tuples and dependencies for the query lifetime.

Each finite round fixes its dirty candidate set. A selected application removes its support from the round's remaining region before executing its body. New occurrences, binding notifications and deferred candidate scopes enter subsequent rounds. Repreparation on the remaining scope discovers further matching frames; a single emitted token never certifies exhaustive ineligibility. The no-application remainder can therefore be certified without waiting for recursive activity on an already applied region to terminate. Component versions remain global, but serial ownership finishes each writer and body rather than repeatedly restarting disjoint completion jobs.

The runtime instantiates fresh body locals, runs conjunctions in order, services finite-tree equality and explicit failure, and creates a causal birth for every active source OR. A body acknowledgment occurs only after its goal stack and outstanding equality, discovery and notification work finish. Source OR creates alternatives; competing eligible source rules do not.

Publication records completed support independently of answer equality. Each observer freezes a birth prefix, occurrence count and per-variable binding-list bounds. Export traverses supported terms incrementally and uses one free-variable map across outputs and residuals. Source and observation work alternate; observers rotate. Future activity on a disjoint region cannot extend an observer's frozen scan bounds or make it deliver its completed support twice.

These are eventual finite-service arguments under finite prepared syntax and finite current stores. They do not establish a uniform latency bound. B-tree operations, allocation and copies of fixed rule syntax have size-dependent costs. Query lowering is synchronous.

## Independent evidence

The test-only scalar oracle owns syntax trees, substitutions, live occurrence identities, ordered tuple selection, propagation history and an explicit source frontier. It implements nonbinding heads/guards, finite-tree occurs checks, fresh locals and body sequencing independently of the candidate and reference interpreters. A cutoff is an explicit failure. Full observations are compared modulo joint variable renaming and residual multiset order, preserving raw multiplicity.

The gate contains:

- Twenty-five hand cases covering nonground aliases, independent/correlated/equal-arm choices, inactive births, partial equality failure, active off-output failure, fresh locals, propagation, delayed constructor and alias demands, conditional consumption, occurrence identity, simpagation, multiple matching environments, rule/tuple priority, conjunction tails and guard locals. Conditional cycles and same-value support expansion have explicit witnesses.
- A 192-configuration finite crossing corpus: four values in each of two OR arms, three reaction forms (consuming join, constructor propagation and equality guard), and both rule and input orders. Each configuration produces four raw answers, giving 768 checked corpus observations.
- Independent projected source-rule sequences for every successful history in the hand cases and crossing corpus. This projection is confined to tests. It supplements full observation comparison; it is not the candidate's discovery mechanism or a universal trace-equivalence proof.
- Six changing recursive-build queries through one prepared object at depths 0, 1, 3, 2, 0 and 4, checking all 32 raw answers against the scalar oracle.
- A supported trace witness with exactly two physical applications: choice introduction and one consumption of the original task/token tuple. Both projected histories have the independent expected source-rule sequence and complete answer.
- Two bounded divergent-sibling checks: a finite sibling publishes within 100,000 ticks beside recursive rewriting; a sibling that keeps introducing births cannot cause that answer to repeat during 5,000 further ticks. These executable witnesses and the finite-round audit support the progress design, without proving fairness for arbitrary infinite executions.

All 43 package tests pass with default features and with metrics disabled. Workspace all-target tests, strict workspace Clippy, strict counter-free package Clippy and formatting pass. Independent read-only reviews of the scalar oracle and runtime found no concrete semantic defect; root separately checked the source path and expanded the adverse corpus. ## Lifecycle and architecture disposition

The changing-query test proves independence, not amortized plan preparation. Before comparative reuse measurements, establish an actual reusable plan owner and charge its construction, query setup and disposal at their true boundaries.

The candidate retains support DAG nodes, terms, occurrence tombstones, discovered tuples, demand subscriptions and histories until query disposal. Observation scans historical prefixes. Required machinery includes conditional finite-tree bindings, Boolean support operations, resource authorization, causal births, dirty rounds, source bodies, completion certificates and joint export. Their time and requested-heap costs are still unknown; semantic work sharing alone cannot justify them.
