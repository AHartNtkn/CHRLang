# Native choices preserve bindings, occurrence histories and failed branches

The native source compiler passes 48 cases combining choices with equality and consuming effects. Complete answer multisets agree with independent expectations, and the reference agrees on unique answers and total multiplicity. All eight ongoing cases publish their finite answer while work remains pending.

The result qualifies a broader serial native source path for comparison. It does not establish concurrent ownership, full language support or an efficiency advantage.

## What the composition tests establish

| Interaction | Observed result | Why it matters |
|---|---|---|
| One choice binds a shared unknown | All uses agree within each alternative | Native copying preserves the tested correlation |
| Two independent source births | All four binding combinations remain | Independent alternatives are not accidentally correlated |
| Duplicate alternatives and propagation choices | Duplicate complete answers retain their raw multiplicity | A set of unique answers would miss a semantic error |
| Choice-dependent aliases before consumption | The aliased arm joins; the distinct arm uses the competing consumer | Branch-local equality affects actual rule selection |
| Fresh replacement after propagation | Fresh and same-variable arms preserve their different receipts and aliases | Occurrence history and variable identity survive branching together |
| Binding conflict or off-output failure | The entire failed source branch contributes no answer | Failed work is not discarded merely because outputs do not mention it |
| A continuing branch before or after a finite one | The finite answer appears and the continuing branch remains pending | The source path uses interruptible native service rather than blocking collapse |

The sources cross two variable numberings and both query orders. They include nested choices and choices inside propagation bodies. Their expected complete answer multisets are specified directly. The reference API reports unique answers, so its raw completion counter is checked separately; native observations must match every expected duplicate.

All 77 deterministic identity-source cases also pass through the extended compiler. This is semantic regression evidence, not an assertion that carrying choice identity leaves native work or allocation unchanged.

## How choices enter native source execution

The compiler generates a continuation for each body segment. A source alternative creates a native named choice around two continuations carrying the store, equality links, propagation history, fresh counters and remaining body work. Each arm receives a distinct descendant birth label. Body failure becomes native erasure, including when a result occurrence was inserted earlier.

Source labels occupy a checked namespace distinct from administrative duplication labels. Occurrence and variable counters can have the same numeric values in separate alternatives because their states and histories remain correlated within those alternatives. The tests exercise this property; the representation still needs broader source and lifetime validation.

The previous deterministic compiler remains a qualified experimental control. Neither compiler executes the CHR program during compilation or embeds expected answers. These generated matching functions run on the native graph reducer with a serial source-priority owner. This is not evidence that local resource claims can replace that owner.

## Failure is different from running out of choice identities

Three boundary sources have no answers: direct failure, two failed alternatives, and conflicting bindings after inserting a result. Both native quotas, ordinary collapse and the reference agree on complete failure.

A separate 24-choice spine has one valid source answer but exceeds the checked birth-label namespace. The native path returns `#ChoiceLimit`; the boundary checker classifies that as incomplete execution, not an empty answer set or a successful source answer. The reference still produces the expected answer. This is an explicit representation limit, not a semantic rejection of the source.

The ordinary source gate does not accept that marker as an answer. Broadening the namespace or changing label allocation remains required if this limit matters to the intended regime. No namespace change was made in this package.

## Validation and progress limits

The main study completes 192 native runs, 288 diagnostic/cancellation runs, 40 finite ordinary-collapse controls and 77 deterministic regressions. The boundary study adds 11 native/control runs. All 48 main sources and four boundary sources are checked against the unchanged reference engine through a syntax-only adapter.

The independent audit checks complete outputs, raw multiplicity, exact replay, disabled-diagnostic agreement, generated programs, runtime hashes and cancellation prefixes. The longest finite main case uses 15,027 service calls, within the registered 65,536-call bound. All eight ongoing cases already have their finite answer at 32,768 calls under quota 1, while a branch remains pending. This is bounded progress evidence, not a latency or throughput result.

Half-trajectory cancellation extends the earlier startup-prefix checks into pending source execution. It still does not demonstrate cancellation during contested concurrent claims, reusable-query heap reclamation or bounded memory over an indefinitely continuing computation. Service visits and CHR steps are different units; no performance ranking follows from their counts.

All 15 containing-package tests, scoped strict Clippy and formatting pass. Guards, constructor terms, malformed choice arms and extra semantic fields are rejected by the checked admission examples. The admitted atom/unknown fragment is broader than the finite case set; these tests do not constitute a proof for every admitted program.

The verbose event records are stored as deterministic gzip archives. Archive checksums and decompression hashes verify the exact original receipt bytes. To reproduce: run `gate.py`, then `boundaries.py`, `archive.py` and `audit.py` in the experiment directory using Python from the repository environment. The reference example and frozen native binaries named in the registration must be available.
