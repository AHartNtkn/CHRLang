# Size recursive-update total costs with separate work counts

Test whether avoided discovery/occurrence maintenance repays update frames, construction and retention. Retain contrary short and competing-call cases. This is exploratory sizing: one ordinary timing per cell, no inferential ranking or workload weights.

Five configurations: feature-off original/sealed; feature-on original/sealed/contracted. All use Global+Indexed. Cross pass, unary, nested, open, late, malformed, choice, multi, multi-choice and fail; depths 0/16/64; one/four queries; resource absent/present: 600 cells. Sources are unchanged from the allocation gate. Queries alternate depth and occurrence order, and reuse preparation.

Before timing, run all 600 cells twice with the existing counter-free meter binaries (1,200 allocation processes). Require exact per-phase replay and query/prepared restoration. This gates the new depth64 inputs. Then run 50 meter cancellation cases: all configurations/families, depth64/two queries/resources, interrupting the first query after 32 ticks. A structural test proves this interrupts live inspection in the single-call contracted families.

Run 600 ordinary-allocator timings, shuffled with seed 7511, and the same 50 cancellation cases. Finally run 600 independent metrics-enabled, non-meter work processes. Total 2,500, plus two meter self-checks. No warmup or outlier exclusion. Neither meter nor work elapsed times are speed evidence.

Freeze current sources, drivers, analysis, toolchain and six binaries (ordinary/meter/work, feature on/off); verify reused meter binaries and runtime sources against the preceding gate. Each process uses the first available CPU, 60 seconds wall/CPU, 1 GiB address space and two-million scalar/source steps. Preserve failures and cutoffs.

Primary time includes preparation, setup, complete execution/observation and engine/answer/prepared disposal. Source/input-inclusive totals, first observation, phases, requested traffic and peak growth remain separate. Full scalar answers are validated outside primary intervals. Work counts sum retired split and terminal segments once; compare source applications, forks, failures and answers across controls, and report candidates, contracted steps/checks and service steps. Requested allocations are not RSS. Native compilation is excluded.

H1: admitted longer recurrences can benefit despite retained constructor work. H2: short and competing-call cases can favor ordinary execution. H3: feature overhead must be separated from contraction. H4: constructor/output work can limit gains for nested/branching sources.

Use the complete costs and actual admission counts to select confirmation or consequential attribution. Exact/direct code may eliminate further work; this suite does not establish the best achievable implementation. Preserve that control obligation before whole-architecture comparison. Further refinement must compete with integration, observation and lifetime under the latest breadth review.
