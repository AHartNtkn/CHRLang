# E04: local dispatch and event caching have distinct effects

All 447 registered case/mode runs pass, and a fresh-process replay reproduces every non-time field. Local dispatch reduces irrelevant occurrence scans. Provenance caching reduces common expansion construction after choice, including when a context arrives later. Retaining events can increase memory substantially when reuse is sparse.

## Evidence and scope

Source/registration freeze: `52ba7ef`. Registration: [E04](../registrations/E04.md); fragment inventory: [64 E00 cases](../registrations/E04-inventory.tsv). Raw results: [batch](E04-graph.tsv) and [replay](E04-graph-replay.tsv). Reproduce with `cargo build --release -p chr-graph --example graph_probe` and `python3 research/chr-graph/run_batch.py <output-path>`, twice. Each run uses a fresh release process, 60-second bound and registered case budget. Environment remains rustc/cargo 1.97.1 on Linux 6.8.0-138-generic x86_64. Elapsed times are diagnostic.

The whole-program certificate accepts 56 E00 cases and rejects eight: five multihead/history cases, one overlapping committed-rule case and two literal lambda programs. Rejection is evidence about this fragment, not source failure or a proposed language-wide requirement. All accepted cases, the 75 carry grid cases and 18 discriminating cases run in three modes. Every grid expansion count matches its registered formula.

All 68 workspace tests pass; Clippy with warnings denied and formatting pass. Seven graph tests cover accepted registry observations, dispatch/cache expansion counts, distinct invocation and guard-local freshness, branch-local constructor demand/failure, closure invalidation by linking, alias-driven rechecking and delayed-context reuse. The reference implementation remains independent. Endpoint checks are not a whole-machine proof or a fairness result.

## Results

At k=8, W=0, noise=128, general dispatch scans 66,558 occurrences; local dispatch scans 511, with the same 255 applications and expansions. Caching then reduces expansions to eight while keeping 511 scans. This separates predicate filtering from event reuse.

At k=8, W=256, noise=0, local mode constructs 65,791 expansions; cached mode constructs 264 and records 65,527 hits. Requested allocation falls from 1,898,855,333 to 974,313,151 bytes. Both still match and commit all 65,791 source applications and inspect 66,047 candidates. Peak allocation above baseline rises from 3,788,762 to 4,344,039 bytes because cached entries and bodies remain live. Shared construction does not imply lower peak retention.

With 128 unrelated occurrences, local and cached modes request 2,112,086,876 and 1,187,544,694 bytes. Their peak increments are 211,924,657 and 215,588,496 bytes. Full residual outputs remain a major retained cost, while event caching adds retention. The cached figure is below E03 Ready's 1,629,326,125 requested bytes on that workload, but above E01 Persistent's 362,703,614. The engines differ in matching, terms, substitution snapshots, history and support services; those comparisons are clues for subsequent service/composition experiments, not isolated representation rankings.

The direct delayed-context test performs 12 projected applications using eight cached expansions and four hits, while preserving the branch-specific residual delay constraint. Reuse does not require simultaneous selection of a ready group. This addresses a different mechanism from E03's eager grouping.

## Contrary evidence

In the k=4, W=64, noise=16 discriminating case, local mode constructs 1,039 expansions and cached mode 1,028. Both examine 8,975 candidates. Requested allocation rises from 9,504,298 to 11,820,860 bytes; peak increment rises from 292,111 to 4,697,506 bytes, with 1,028 retained cache entries. The problem is sparse reuse plus retained bodies, rather than E03's repeated compatible-group previews. These require different optimizations.

The SK ignored-hole example has 32 applications and no cache hits. Requested allocation rises from 2,685,784 to 2,711,614 bytes, and peak increment from 94,237 to 310,067 bytes. The example's relational behavior remains correct, but it does not establish a sharing opportunity for this cache. Larger synthesis cannot be replaced by a favorable carry demonstration.

## Disposition

This first E04 probe is complete; the direction remains open. Mixed closed regions and general-CHR interfaces, compiler certificate precision, cache eligibility/reclamation, generated transition checks, dependency-based wake-up and resumable services remain feasible and potentially material. The whole-program rejection of the literal lambda example is a concrete reason to investigate regional compilation rather than infer a language restriction is acceptable. Event retention and opaque term copying should be compared with E05 services and E15 compositions.

The independent named-family service is next in the first-probe sequence. No production architecture or language restriction has been adopted, and no owner decision is needed to continue experimentation.
