## Concrete projection entry

First specify the finite denotation independently: a set of assignments satisfying a structural description, projected onto named visible coordinates. Compare direct enumeration of full assignments followed by projection with a representation that eliminates hidden coordinates before enumeration. Use the existing structural implementation as a control where its contract applies; do not force a different theory through its oracle.

Include hidden alternatives that collapse to one visible assignment, hidden constraints that preserve a visible correlation, an empty hidden domain, and constraints that become selective only after a caller adds information. Add an unselective case where almost every visible assignment is required. Distinguish fresh hidden names from caller-shared identities.

Explicitly pair set projection with derivation multiplicity. Two hidden witnesses may produce one visible logical solution but two CHR derivations. Determine which metadata or source restriction would preserve each observation contract; do not silently deduplicate raw CHR answers. Register denotations, finite domains, source correspondence, controls and bounds before implementation or comparative runs.

A correct entry proceeds to representation size, preparation/reuse, full observation and retained-owner costs on favorable and adverse sources. An incorrect projection requires repair or a scoped analytical resolution. Reconsider adaptive costs, local native ownership, conditional equality and broader reuse at the entry gate or a consequential obstruction.
