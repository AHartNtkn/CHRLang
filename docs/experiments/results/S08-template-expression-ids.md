# Stable template identities repair an observer-layout dependency

**The ownership gate exposed address-sensitive template allocation; derivation-local expression IDs repair the tested dependency.** All384 repaired source configurations now have identical normalized ownership under two reporting-buffer layouts. Complete answers remain correct. No answer-cache timing conclusion is accepted from the campaign that failed its entry gate.

## What failed

The ordinary runner was extended to record phase nanoseconds and execute repeated fresh sessions. Its384 metered entries found40 mismatches against historical requested ownership, all in template execution intervals. Differences were whole allocation/deallocation events in192-byte increments, while complete answers still validated. This prevented the prospective exact-ownership gate from passing.

The automatic driver ran its timing matrix before executing the final cross-history audit. That sequencing was defective: ownership entries must be compared immediately before warmups/timing. The raw3,200-process campaign is retained with an explicit [qualification-failed outcome](s08-answer-validity-timing/outcome.json); none of its ratios is used for a policy conclusion. The runner now enforces the entry comparison immediately before warmups/timing; invoking that gate on the retained failing receipts rejects them.

Source tracing found `template_term` using `Rc` allocation addresses as ordered B-tree keys for ground-expression reuse. A change in reporting storage changes heap layout, which can change key insertion order and B-tree node allocation. The192-byte granularity is consistent with those map allocations; the targeted representation change and layout challenge test this diagnosis directly.

## The repair and its responsibilities

Each new template expression receives a monotonically increasing ID within its derivation. Shared `Rc` edges preserve that ID. Ground-expansion memoization uses the ID rather than address order. Every expansion starts with a fresh memo, so IDs need not be globally unique across templates. Source node/fuel budgets, fresh variable identities, groundness and branch-local environments remain unchanged.

The expression now owns an additional integer. That metadata and any resulting allocation shape are charged in the repaired measurements; this is not a claim of free identity or a speedup. The identity test checks distinct expressions, shared edges and deterministic creation order. The graph/context suite passes32 tests, including choices, consuming claims, constructor cycles and answer-expansion retry; scoped Clippy passes.

## Direct challenge to the failure mode

The [repair registration](../registrations/S08-template-expression-ids.md) rebuilds lookup/seeking, answer-cache off/on and dependency/template/direct execution. The96 finite source cases retain repeated/distinct calls, successful/failed tails, resources, depth8/32, reversed insertion and two changing queries with complete raw-answer validation.

Each of384 configurations runs with reporting-buffer capacity9 and73, outside measured lifecycles. **All768 processes validate; all384 pairs have exactly equal normalized phase heaps and answer counts; all owners restore after disposal.** This tests the observed layout perturbation instead of accepting it as measurement noise. It does not establish independence from every possible allocator or workload.

Repaired seeking-template sessions at depth32, repeated calls, successful tail and forward insertion request634,316 bytes with a128,115-byte peak for pure execution; consuming execution requests835,156 bytes with a160,227-byte peak. These are complete two-query ownership totals for the repaired representation, not comparisons proving an architectural winner.

## Decision

Use stable expression IDs for the next comparison and retain the additional ownership in its costs. Re-register timing against this repaired representation. First audit every metered entry against the new ownership receipts; only then launch warmups and paired ordinary timing. Retain the same cache-off/on graph and direct controls, failed tails, resources and zero-support cases. Do not try to reproduce the address-keyed historical totals by changing fixtures or suppressing allocations.

The [full portfolio review](S08-expression-ids-review.md) keeps T074 active for that comparison and resets the review count. The answer-cache work–memory tradeoff remains established; its speed benefit remains unproven. All broader architectural and language directions remain in scope.
