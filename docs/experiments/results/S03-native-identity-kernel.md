# Native equality and occurrence history can preserve different identities

The native runtime now executes separate operations for equality, occurrence replacement and ordered propagation history. All 340 operation cases pass independent expectations, including nonbinding equality checks and branch-local bindings. This establishes usable operations for a source compiler; it does not yet establish native CHR source correspondence.

## What the operations preserve

| Question | Native evidence | Architectural consequence |
|---|---|---|
| Can two unknowns become equal without becoming a new occurrence? | Binding chains resolve to shared values; occurrence IDs remain separate fields | Equality and occurrence identity can coexist in this native representation |
| Does checking equality accidentally bind distinct unknowns? | 48 probes observe both the comparison and the same environment afterward | The tested matching predicate is observational and nonbinding |
| Can replacement preserve old unknowns while introducing a new one? | Removing occurrence 0 and inserting occurrence 2 with a different unknown leaves the other occurrence intact | A fresh occurrence and a fresh variable need separate allocation responsibilities |
| Does ordered history distinguish `(2,3)` from `(3,2)` and another rule? | Receipt membership checks ordered IDs and rule identity; distinct-head checks reject repeated IDs | Equal values need not collapse legal application multiplicity |
| Can choices carry different bindings? | Native alternatives produce separate atom bindings, duplicate alternatives remain duplicated, and conflicting bindings produce an explicit failure result | The operations can run under native choice; translating CHR failure and complete source effects remains separate work |

The equality model uses explicit variable-to-term links in a persistent list. Binding resolves both roots before linking them; unknown roots link toward the smaller ID, preventing cycles in these admitted operations. Atoms must agree. The independent oracle instead merges sets into equivalence classes, rejecting a class containing two different atoms.

Occurrence lists carry numeric IDs and term arguments. Addition takes a caller-supplied fresh counter; removal compares occurrence IDs. History stores rule IDs and ordered occurrence-ID lists. These responsibilities are present explicitly: this experiment does not show an equality service or history bookkeeping disappearing into local interaction rules.

## Coverage and the implementation finding

The gate enumerates all 256 two-binding sequences over two unknowns and two atoms, plus three longer chains using four unknowns. It adds 48 nonbinding probes, 16 empty-environment equality checks, ordered-history and distinct-head checks, removal/replacement cases, and native choice cases. Complete expected values are generated by the independent partition model or stated directly for the occurrence/history operations.

The initial executable equality stub returns false for an unknown compared with itself. The recorded failing case establishes the required behavior before implementation. The first emitter then exposed a separate defect: its variable substitution also rewrote a same-named function reference. The corrected emitter distinguishes variable occurrences from `@` references. The failing emitted input and parser bytes are retained; the final generated kernel reproduces exactly from its generator.

That emitter correction is local to this experiment. The earlier ground compiler and frozen runtime binaries are unchanged. No conclusion about their performance or broader correctness follows from this local failure.

## What was validated

The final gate completes 1,360 native runs: 340 cases, two service quotas and two identical repetitions. Another 1,700 runs check disabled diagnostics and cancellation prefixes. Twenty representative finite cases also agree with ordinary native collapse. The longest execution uses 1,619 service calls, within the registered 8,192-call bound; all final executions exhaust without unsupported observations.

An independent audit verifies case coverage, complete outputs, exact replay, service-visit bounds, stack baseline, counter-off behavior and cancellation prefixes. It also verifies current input hashes and that both runtime binaries match the prior consuming gate. Kernel regeneration is byte-identical. These are correctness and service-protocol checks, not speed or allocation comparisons.

The first completed gate covered 292 cases; its records are retained separately. The additional 48 probes strengthen the nonbinding claim. No failed or incomplete run was counted as passing evidence.

## What remains before native source correspondence

The operations accept atom/unknown terms and assume well-formed environments, unique occurrence IDs and a genuinely fresh caller-supplied counter. They do not supply constructor unification, an arbitrary-source admission checker, a rule matcher, rule-priority scheduling, automatic fresh body variables or propagation firing. Those responsibilities must be implemented and tested together against the [61 complete-source obligations](S03-native-identity-obligations.md).

`#Fail` is an explicit operation result in this gate. It is not yet the CHR branch-failure translation. Likewise, checking cancellation prefixes does not establish reusable-query heap reclamation, cancellation during contested effects or local concurrent ownership. Linked environments still introduce lookup, copying and retention costs that require later accounting.

**Continue T080 by connecting these operations to actual source-selected rule execution.** Start with the existing replacement, later-binding, ordered-history and effect-order sources; require independently checked complete residuals and aliases. Preserve the original broader task, including competing effects and local ownership. More isolated operation tuning has lower decision value than that integration.

At the source-gate boundary, compare broader native ownership work with integrated guard/search support and coherent architecture qualification. The earlier graph-scan timing advantage remains bounded evidence for another candidate. This native operation gate neither selects nor rejects an architecture, and the research goal remains active.
