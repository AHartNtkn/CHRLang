# Private work can be eliminated as well as shared

The reunion sources now have stronger, executable controls. Existing specialization works with both access policies, and a checked source-family shortcut eliminates their ground countdown work while preserving complete raw answers. This changes what the next cost comparison must include; it does not establish a runtime winner.

The [registered gate](../registrations/S04-reunion-strong-controls.md) validates **96 core queries across ten execution paths**, giving 960 full-answer comparisons per build against the independent scalar evaluator. Ordinary and diagnostic builds pass, along with passive-alias and rejection tests. All **23 ordinary and 24 diagnostic package tests**, strict all-target/all-feature Clippy and formatting pass. No comparative timing or allocation matrix ran in this package.

## Existing specialization is a real control

Generic and inferred-specialized compiled execution both preserve answers with Scan and Indexed access. The inferred checker accepts the single-head `job` and `walk` predicates and retains ordinary execution for the multihead `ready` join. Separate compiled-work diagnostics require actual specialized-candidate work in all 384 specialized runs and zero specialized-candidate work in all 192 generic runs. This checks execution, not merely an eligibility label.

The current carrier-contraction checker rejects `walk` in all eight family/owner combinations. Its implementation requires exactly two rule uses for the predicate and variable slots in non-control arguments. These sources contain multiple owner-specific rule pairs and literal owner keys. That rejection describes the checker; it does not prove their countdown work is semantically necessary.

## The checked shortcut removes the countdown, not the answers

The shortcut first verifies the entire source against the plain/equal/late/payload family for the supplied owner count. For each query it requires one job per owner, a ground finite natural counter, disjoint variable ownership and only the permitted passive payload or matching late-wait occurrences. It rejects additional active occurrences, changed rules and unknown counters, including a known prefix with an unknown tail.

For accepted input it constructs a query with each job counter replaced by zero. The same source rules still make the choices, bind outputs, perform joins and consuming effects, reject incompatible values, reactivate late waits and publish full residual answers. Passive aliases and unused output variables remain observable. The checked object retains its verified rules; it is not permission to execute the transformed query under another program.

The argument is specific: the recursive rule only strips the counter and preserves every carried value; the terminal rule sees zero in either execution. The counter is ground, so shortening it cannot discard a variable or a later binding dependency. Source priority and the checked ownership boundary keep private work from changing another owner's effects before the join. Extra active occurrences could alter competition, which is why they are outside this entry's premise.

This is a source-family control, not a general lowering algorithm. Its exact rule comparison is conservative, including source names and representation. Recognizing equivalent programs, broader effects, unknown inputs and repeated dynamic reunion remain separate investigations. The family and owner count are supplied by the experiment; general inference of that classification is not implemented.

## Eliminating and sharing work are different comparisons

The table uses four owners, base depth48 and seed0. Counts are calls to the shared ordinary source-transition operation; they exclude checking, query transformation, product materialization, copying and observation-internal traversal costs.

| Source | Ordinary Copy | Reunion | Shortened Copy | Shortened reunion |
|---|---:|---:|---:|---:|
| Plain | 3,124 | 888 | 244 | 120 |
| Equal join | 3,140 | 904 | 260 | 136 |
| Late binding | 3,256 | 1,064 | 376 | 296 |
| Retained payload | 3,124 | 888 | 244 | 120 |

Reunion avoids repeating private work; shortening avoids executing the countdown. Their combination can reduce transition calls further, but it also requires both mechanisms. The next comparison must charge their combined preparation, eligibility checks, query transformation, private caches, product states and disposal against the simpler paths. Fewer calls alone cannot justify that combination.

All 96 queries compare original generic Scan/Indexed, original specialized Scan/Indexed, original Copy and reunion, plus shortened Copy, shortened specialized Scan/Indexed and shortened reunion. The source/query generator is shared with the allocation harness, and its function definitions are verified identical to revision `235e5c83c` apart from public visibility. This is the same workload, not a replacement selected to favor the shortcut.

## Limits and next selection

The shortcut accepts complete finite counters and makes no claim of identical source-service traces, first-answer latency or resumable unknown-tail behavior. Its inspection is real work and must be measured. The existing reunion ongoing-sibling and cancellation tests continue to pass, but they do not extend the shortcut's eligibility to ongoing programs.

Register a bounded complete-cost comparison using the qualified controls. Include ordinary timing with engine/kernel/work counters absent, and separate allocation evidence for the newly added preparation and transformation paths. Reuse the measured source families and changing-query lifetimes; include short work, payload-heavy cases and cancellation. Retain a simpler shortened coupled path against shortened reunion, so a combined design must justify its extra machinery. Do not treat missing carrier eligibility as a reason to omit elimination.

T072 integrated dependency repair remains the strongest separate alternative. One bounded complete-cost comparison is selected because all competing paths are now executable and independently checked, and their costs can change whether reunion has an advantage after available elimination. Further specialization tuning requires a consequential defect or unresolved decision. This is T077's sixth package; the four-package review occurred after package four. Broader dynamic reunion, language properties, sustained lifetime, complete architectures and held-out challenges remain required.
