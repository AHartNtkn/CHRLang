# Factored serial contraction beats the tested persistent workers

Factored contraction establishes practical lifecycle wall-time and process-CPU benefits against four persistent workers in all ten registered cells. Its median incremental peak is also lower in every cell. The earlier persistent-worker advantage does not survive this stronger serial organization on these contractible sources.

This completes T069's bounded reusable-worker comparison. It does not reject parallel execution of work that remains substantial after applicable optimization, or select a universal language architecture.

## Factoring explains a large organization effect

On multi-region sources, factored contraction's median peak is approximately19.6–37.6% of unpartitioned contraction's peak. On tiny one-region sources it instead reaches approximately133–135% of the unpartitioned peak. Factoring avoids carrying independent regions together through whole-query branching, but adds certification, regional caches and product bookkeeping. Both consequences are measured.

This is a comparison of complete organizations, not an isolated byte attribution to a specific arena field. It resolves the consequential confound in interpreting the earlier unpartitioned contraction result. The compiled source service and product coordinator share responsibilities in this experiment without establishing that their interfaces should become production architecture.

## Bounded disposition and complexity

For these certified countdown programs, prefer eliminating repeated execution and separating independent work before choosing the measured persistent worker organization for speed. The kernel's checked source properties permit contraction; the conservative independence certificate permits factoring. Neither result requires making those properties mandatory across the language.

The serial combination requires compiler eligibility analysis, prepared rule plans, per-region source searches, answer caches and exact incremental products. The worker organization additionally requires channels, worker preparation, query generations, pending-request ownership, cancellation/drain and joined shutdown. The measured combined serial organization earns its machinery against workers here, but its tiny adverse cases prevent a universal combination policy. No aggregate complexity score or automatic routing architecture is selected.

Timing covers preparation, query setup/certification, joint execution/observation and full disposal. Process CPU is broader and includes validation/reporting. Allocation windows exclude expected-answer/harness setup and the separately attributed process channel context; requested heap is not RSS. Compilation of an independent native user program remains outside this comparison.

## What remains open, and why move on

T069's ownership, correctness, cold/reuse timing and matched heap questions now have evidence, including a stronger available serial control and the relevant factoring correction. More precision on the same worker-versus-contracted cells is unlikely to change this bounded conclusion: all ten pass the same practical wall and CPU screen, and the contrary tiny/representation costs are explicit.

Parallel execution of the contracted source service itself, work that resists contraction, larger prepared sources, large output streams, finer independence and connected work remain required S08/S09 directions. The current result cannot answer them. These stay in the coverage map rather than being counted as resolved by T069.
