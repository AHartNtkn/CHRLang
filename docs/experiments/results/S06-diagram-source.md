# Reusable diagrams match finite-name source sets, with an explicit observation boundary

All 360 finite-name source configurations match independent complete observations and completed-branch totals. Reusable diagrams, prepared name solving, finite projection and symbolic rebuilding also match all 1,440 projected-set comparisons per build. This qualifies the constructed finite source grammar for a cost comparison; it does not establish a general CHR replacement.

## The same requests reach four competing paths

The source programs explicitly choose three atomic names, check exclusions, and return selected coordinates. Six families cover unconstrained work, hidden-star exclusions, a clique, duplicate alternatives, overlapping alternatives and a star/clique union. Two alphabets, caller equality on/off, three output-coordinate lists and five changing requests give 360 configurations.

The requests include no restriction, either of two fixed names, contradictory restrictions and a name outside the alphabet. Outputs include ordinary pairs, reversed pairs and repeated coordinates. Each candidate preparation is reused across these requests. The independent reference starts a fresh search from the same rules for each request; this gate measures no reference cost.

The diagram compiles each branch, unions the branches and existentially forgets coordinate 2. Both caller-visible coordinates remain available even if the output repeats only coordinate 0. The prepared-name control solves each compiled branch. Existing finite projection supplies branch relations. The symbolic control instantiates fresh identities and rebuilds feasibility through its existing observation endpoint. All four return exact owned sets of output terms.

Caller equality is checked as a restriction on candidate visible assignments. This finite ground observation protocol is exact for these requests; it does not implement general caller unification, nonground symbolic output or restrictions that capture hidden variables.

## The source contract separates observations from search work

The initial exploratory assertion expected the reference to publish every completed branch. It failed because the reference canonicalizes complete answers and publishes each distinct output/residual answer once. Completed and duplicate branches are counted separately. The experiment corrects its oracle contract; the reference implementation remains unchanged.

The final independent oracle enumerates assignments per alternative and constructs their full ground residual constraints. It checks the reference's exact canonical answer set and total completed branches separately. It then projects those independently derived assignments to the requested logical set. None of these expected results invokes a candidate solver or reference routine.

All 360 searches exhaust within the registered 100,000-step bound. Debug and release confirmations each pass the complete matrix and two boundary witnesses under 60-second CPU/wall and 1-GiB address-space limits. There are 138 configurations in which completed branches exceed projected rows. These counts describe the selected matrix, not application frequencies or performance gains.

For the duplicate-free-alternative witness over two names, the source completes 16 branches but publishes four distinct full answers. The four-row logical set is therefore compatible with published values while hiding repeated search work. A difference in branch counts alone is not a difference in this reference's published answer semantics.

## Equal output sets can still lose a host effect

A separate witness adds a host rule that observes a surviving exclusion constraint and posts `seen(X,Y)`. A direct replacement returns exactly the same visible pairs and retains that observer rule, but does not post the exclusion constraint. The reference confirms equal visible output sets and a different residual observation: `seen` occurs only in the original source.

This is a concrete boundary on source replacement. A logical-set interface may intentionally expose only those visible pairs. A full-answer or interacting-host interface must preserve the residual obligations and resulting effects. This experiment provides no automatic analysis that proves a region isolated, and it does not adopt a restricted language contract.

## What the result changes

The diagram is now a credible candidate for a matched finite-name lifecycle experiment. Union and projection operate on the prepared representation while preserving the tested correlations, aliases and requests. Existing prepared-name solving and projection remain essential controls: their reuse may already achieve the relevant saving with less machinery.

Next qualify allocation and ownership before registering primary timing. Charge branch compilation, union/projection, intermediate nodes, caller setup, fresh symbolic transport, exact output, retained consumers and final disposal. Extend query reuse while retaining cheap/unselective cases. A traversal-only measurement would leave the architectural question unanswered.

Source correspondence does not price compilation, prove sustainable identity ownership or establish useful diagram ordering. Broader structural theories, source effects and complete architectures remain required. This completes package two of the current T076 investigation; the portfolio review is due by package four. Relevant-key repair, demand attribution and checkpoint/replay remain explicit competing next investigations.
