# Progress and certified lowering survive the tested compositions

All three execution organizations preserve finite-answer service in the new mixed sources. Resource fusion also preserves complete answers across their tested query variations, with rejected queries retaining ordinary source execution. These results support proceeding to whole-path cost measurement; they do not establish an architectural winner.

The [prospective registration](../registrations/S10-progress-lowering.md) fixes the cases and bounds. The [test source](../../../research/chr-direct-conditional/tests/composition_progress.rs) uses a [test-only dispatcher](../../../research/chr-direct-conditional/tests/composition_support/mod.rs) over the actual existing engines. No runtime implementation or reference-interpreter code changes are involved.

## Finite answers beside ongoing work

Four sources vary choice-arm order and propagation-rule position. Each combines perpetual rewriting in one alternative with equality, guarded multihead consumption, a kept resource, propagation history and fresh output/residual aliases in the finite alternative.

Compiled Global Scan, four contextual equality configurations and direct conditional execution all deliver the independently constructed finite answer within 200000 service calls. After publication, 1024 further calls produce neither another answer nor false exhaustion. The answer still agrees with the expected full observation after engine disposal. This is 24 ongoing executions per build.

The witness tests branch service through these combined mechanisms. It does not prove general fairness among competing rules, constant service cost, bounded memory during indefinite execution or reclamation of all canceled owners. Those require distinct evidence; an owned answer surviving disposal does not itself establish leak freedom.

## Fusion across execution organizations

The five source families are deterministic effects, independent choices, equal choices, shared payload aliases and spare resources. Producer counts range from zero to three. For each family/count, queries retain sufficient resources, remove one permit where possible, or replace all resource-owner keys with one shared unknown.

The existing source certificate admits 32 of the 60 cases and rejects 28. Eligibility is asserted independently from the fixture dimensions: ordinary queries qualify; a missing permit qualifies only with no producer or spare resources; unknown keys qualify only when no controlled resources are present. Query rejection selects the original rules in test orchestration. This does not add a production dispatch layer or waive the certificate.

Each case runs original and certificate-selected rules in all six candidate configurations: 720 finite candidate executions per build. The independent scalar evaluator supplies the complete original-source answer multiset for each query. Comparisons retain equal-choice multiplicity, spare and insufficient resources, unknown keys, fresh variables and their aliases. All executions exhaust within the registered bound and match those answers.

These families already have independent source-correspondence evidence in the [resource-fusion gate](S06-resource-fusion-gate.md). The new evidence extends execution-organization coverage; it does not expand the compiler's admitted language. In particular, observed agreement is insufficient to infer that every legal source schedule commutes with fusion. Broader consumers, dynamic resource production and competing rules retain their existing eligibility obligations.

## Validation and decision

Both [default](s10-progress-lowering/default.log) and [feature-off](s10-progress-lowering/counter-free.log) runs pass, along with [strict scoped Clippy](s10-progress-lowering/clippy.log). Each build executes 720 finite candidates, 60 scalar checks and 24 ongoing candidates. The [source hashes](s10-progress-lowering/source.sha256) identify the tested inputs. No comparative timing or allocation run occurred.

The first [mixed-source gate](S10-mixed-source-entry.md) and this progress/lowering gate now justify registering a bounded whole-path lifecycle pilot. It should compare ordinary compiled, contextual and direct conditional execution, with certified lowering as an explicit paired configuration. Use existing credible access and contextual-storage controls where their costs can change the conclusion. Charge source inference, query certification, prepared rules, query setup, execution, complete observation, cancellation and disposal separately. Measure work and requested allocation separately from ordinary-allocator timing; compilation remains a distinct obligation wherever it cannot be isolated credibly.

This next cost pilot has higher immediate decision value than more isolated fusion timing: it can reveal whether the different equality, search, claim and completion responsibilities dominate the local savings. Favorable source sharing, independent alternatives, early failure, changing aliases, zero work and output-heavy cases must all participate. Freeze exact cells, repetitions and resource bounds before comparative runs. T078 remains active; sustained lifetime, broader source correspondence, other unresolved mechanisms and held-out challenges remain required.
