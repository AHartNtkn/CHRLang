### Depth, breadth and stopping within this sequence

**Each distinct mechanism gets a correctness gate and a decision-relevant comparison.** Use a favorable witness that actually activates its benefit, an adverse witness that charges its obligations, independent complete observations and the strongest applicable control. If an analytical argument replaces implementation, it must apply to that mechanism and its claimed regime. A nearby prototype's loss is insufficient.

**A failed or favorable pilot determines the next experiment.** Attribute a loss to an inherent obligation, an implementation defect, missing eligibility or insufficient measurement. Repair consequential defects. Challenge a gain with preparation, lifetime and adverse conditions. Register any confirmation prospectively. A resource cutoff requires diagnosis and a justified next bound or analytical limit; it is not a rejection.

**Review breadth after every four completed packages, counting correctness and attribution work.** Also review at each numbered comparison's boundary. Explain any further refinement while a distinct ready mechanism remains untested. This review changes the order when warranted; it does not cap necessary investigation or excuse leaving a consequential failure unresolved.

**Language and lifetime work starts with each candidate.** Its first gate records accepted programs, declarations, observation/progress obligations and retaining owners. Its first cost comparison includes changed queries, early cancellation and disposal. Sustained consumers and restriction comparisons begin when relevant paths exist; the current sequence assigns their follow-through to investigations 9 and 11.

**A direction leaves the required work only through evidence.** Use the five-part decision record below: tested proposition, result and contrary evidence, architectural consequence, strongest remaining challenge, and remaining scope. If a feasible unanswered challenge could change the choice, schedule it. Finishing this document, a pilot, or the first cycle does not finish the research goal.

### 1. Execute equality, matching and consumption in one organization — T072 / S02

**Decision:** can one substrate remove enough repeated discovery and cross-service state to replace dedicated equality and matching services?

First compare parent/root changes expressed as CHR rules with strategic local port rewrites, where an equality or constructor change services the incident applications directly. Ground application identifiers must distinguish source-level class merging from host unification. A partition-only test establishes a building block; it cannot settle constructor consistency or CHR execution.

Extend each genuinely distinct organization to constructor decomposition, clashes, finite-tree occurs checks, suspended nonbinding matches, fresh values and occurrence-sensitive consumption. Include a chain in which each equality enables a match, whose body contributes another equality. Vary unrelated work between these events to establish whether interleaving avoids useful work or only moves queue operations. Include propagation history and competing consumers under the declared source scheduling contract.

Compare the strongest applicable compiled scanning/indexed path, the measured relational/contextual path, and the new organizations. First establish a competent merge strategy and access policy: an avoidably deep forest or global scan cannot support a general cost rejection. Use an independent connectivity oracle for the forest and independently checked complete source answers for the extended executor. The reference interpreter stays independent.

Vary merge fan-out, class depth, constructor sharing, activation selectivity and consumption contention independently. Charge index/incident repair, stale references, discovery, preparation, outputs and reclamation. Include repeated changed queries, early cancellation and mostly distinct small work. Separate an eliminated responsibility from the same responsibility implemented in another queue.

**Required conclusion:** identify which boundaries disappear, the regimes where that matters, and the ownership obligations that remain. A loss with a repairable cost requires attribution and repair when consequential. If the organizations are operationally equivalent, explain their scheduling, representation and ownership costs; representability alone is insufficient. Carry credible alternatives into S10. Broader integrated execution stays open if this gate covers only a fragment.

### 2. Reuse a call across different callers — T075 / S05-B

**Decision:** can economical reuse replace the need to retain shared execution when whole states differ?

Construct callers with distinct irrelevant pending work that invoke the same substantive computation. Compare direct recomputation, exact whole-state keys, the existing compact renaming/relevance keys, call-level keys and applicable graph derivation reuse. The call-level implementation must transport fresh variables and results back to each caller without merging observable source alternatives.

Challenge the key with callers differing in a live consumable, a later binding, an alias, propagation history and residual multiplicity. Check complete answers with independent semantics. Show a case where whole-state reuse misses and call-level reuse succeeds; otherwise the distinctive mechanism has not been tested.

Vary useful repeated work, caller-only state, reuse distance and near misses independently. Compare bounded retention and eviction/recomputation with indefinite caching. Measure key discovery, validity checks, replay, output transport and lifetime as well as saved execution. Include changed queries over prepared rules.

**Required conclusion:** whether recognizing reusable calls is competitive with sharing execution, under which state dependencies and retention budgets. The compact whole-state measurements provide controls, not an answer to this question. If relevance analysis is too conservative, distinguish a checker limitation from a semantic barrier and investigate the consequential false negatives.

### 3. Solve structural possibilities without enumerating them — S06-C/D

**Decision:** can compact structural solving eliminate enough search to justify a different representation or language theory?

Begin with finite constructor spaces, intersections and equality between finite paths. Compare explicit enumeration with lazy construction, state reduction and a direct structural solver. Use selective overlapping constraints that admit few answers, then disjoint, redundant and unselective constraints. Vary description size, depth, equality density and answer size separately; a tiny description can denote a large answer set.

Validate small denotations by exhaustive enumeration and independently check larger returned witnesses. Test empty spaces, jointly aliased outputs and bounded unfinished exploration. Measure construction, intersection, reduction, witness production and full enumeration as separate endpoints where isolable. Include reusable constraints with changed assumptions and charge retained state.

Treat existential projection, names, disequality and normal/neutral distinctions separately. For each, state its meaning and construct a source where it avoids work. If it changes the language, attach an S07 comparison of expressiveness and implementation responsibilities; do not silently substitute its answers for consuming CHR answers.

**Required conclusion:** distinguish the cost of compact reasoning from unavoidable output enumeration, and establish where its source correspondence holds. Finite-table or trace-solver results cannot discharge this test. Carry useful structural mechanisms into direct derivation/learning comparisons and S10.

### 4. Restore state and reconnect temporarily independent work — S04

**Decision:** can explicit search obtain graph-like economy through reconstruction and temporary independence?

Compare competent copying, persistence and undo with checkpoints plus replay. Vary checkpoint spacing, mutation density, read volume, branch depth and failure placement independently. Then compare immediate splitting with a demand-sensitive policy; freeze the policy before held-out tests.

Add regions independent now but joined later by a binding, a call or a consumable. Compare permanent grouping with occurrence-level dependency tracking and actual reconnection. Same-predicate independent occurrences test precision; a delayed shared consumer tests soundness. Preserve choice correlation, propagation and committed consumption across restoration and reunion.

Measure analysis, checkpoints, replayed work, separation, reconnection and retained memory over complete queries. Use the corrected existing restoration controls and independent complete-answer checks. Include no useful separation and frequent reunion as adverse cases.

**Required conclusion:** whether reconstruction or temporary separation can substitute for persistent shared execution, and whether an adaptive policy generalizes. A permanent-region result does not resolve reconnection.

After this cycle, use the tables below to execute the remaining access and partial-join policies, graph support representations and native correspondence, direct derivations/learning and broader lowering, stable-identity failure caching, and connected parallel ownership. Their order is reconsidered using the new evidence; their obligation is unchanged. Broader graph derivations remain required even if one local lifting transformation has no measured advantage.

Language and sustained lifetime investigations accompany every candidate above. Test the source restrictions or declarations that remove runtime obligations, including programs just outside eligibility. A short-lived benchmark cannot resolve these costs.

Include a simpler single organization against any proposed combination and charge duplicated machinery and boundaries. **A package finishes when its bounded question has an answer; a direction finishes only when its consequential variants are resolved.** After every four packages, including correctness and attribution work, review all still-untested mechanisms before choosing further depth. An interrupted investigation remains required and gets its next review point. An experimental limit or lower priority is never a negative architectural result.

## How each investigation becomes an experiment

**Select a bounded question without shrinking the architecture obligation.** Use the [priority comparison](sequence.md#how-priority-is-justified) to choose between this investigation and the strongest ready alternative. A package may establish correctness, diagnose a consequential cost or make a comparative measurement. State which purpose it serves before starting, and return to selection at that boundary.

**First establish the mechanism and correctness.** State the architecture decision, the responsibilities the candidate removes and introduces, its source contract and an independent oracle. Include a favorable witness that activates the mechanism, an adverse witness charging its overhead, and tests capable of detecting an incorrect implementation.

**Then register the comparison before its timings.** Freeze exact sources, sizes, seeds, configurations, controls, endpoints, repetition counts, practical thresholds, resource limits and analysis. The [sequence's measurement rules](sequence.md#registration-bounds-and-interpretation) require counter-free ordinary-allocator timing, separate diagnostics and complete lifecycle accounting. Sizing is exploratory; confirmation uses a prospective configuration.

**Investigate consequential outcomes.** A loss triggers an attribution check: inherent obligation, repairable defect, weak control, missing eligibility or insufficient measurement. Repair and rerun when the defect could change the decision. A favorable result requires adverse controls and sensitivity, not automatic adoption. A cutoff requires diagnosis; it does not establish architectural inferiority.

**Finish with a bounded decision and explicit remaining scope.** Link raw evidence and state what would reverse the conclusion. If feasible work could materially change the architecture decision, keep that question open and scheduled. Finishing a test package, this plan, or the first breadth cycle does not finish the research goal.

### Follow-up is determined by what the experiment learned

| Outcome | Required next investigation or disposition |
|---|---|
| The candidate violates the agreed source contract | Determine whether the mechanism requires that violation or the implementation is defective. Repair the latter. A different language contract receives a separate S07 comparison. |
| The candidate loses, but its intended benefit never occurs | Establish a source where the mechanism actually operates, or demonstrate why the promised benefit cannot occur under its premises. The first loss answers only the tested source. |
| The candidate loses with a consequential avoidable cost | Correct the cost and rerun the affected contrast. Use a bounded attribution experiment before broadening the matrix. |
| The candidate wins in its intended regime | Test adverse placement, preparation/reuse, retention and source restrictions. Carry the surviving advantage into S10; do not infer that combining winners is economical. |
| Both directions have credible favorable regimes | Measure the consequential boundary and test whether source analysis can identify it. Report the tradeoff even if no reliable selection policy exists. |
| Measurements overlap or reach a limit | Diagnose variance or unfinished work. Increase precision or bounds when it could change the decision; otherwise give a sensitivity argument for the bounded conclusion. |
| Further precision cannot affect a supported bounded decision | Record why, preserve the broader unresolved mechanisms, and advance to the next investigation. |

## Evidence required before a question can leave the sequence

Each review entry must link to a short decision record with five parts:

1. **The exact proposition tested.** Name the mechanism, source fragment, observation contract and regime; distinguish it from nearby designs.
2. **The result and contrary evidence.** Link prospective registration, independent correctness checks, raw runs and analysis. For analysis-only conclusions, state premises and the argument or counterexample.
3. **The architectural consequence.** Explain which responsibility, representation or language choice changes. Report conditional tradeoffs directly, without invented workload weights.
4. **The strongest remaining challenge.** Identify a plausible implementation repair, different regime or distinct mechanism that could reverse the conclusion; investigate it if feasible and consequential.
5. **The scope still open.** Give its next investigation and dependency. An exact external resource or necessary language-adoption decision may block that item; scheduling preference and implementation effort are not experimental results.

**A measured loss has three different possible next steps.** Repair avoidable costs when they could change the conclusion; test a favorable regime when the mechanism was not exercised; or retain a bounded adverse conclusion when the implementation is credible and the mechanism did operate. None automatically rejects a whole family.

**A measured gain also requires follow-through.** Check preparation/reuse, adverse work placement, memory and source restrictions, then carry the candidate into a whole-architecture comparison. A component gain cannot establish the cost or simplicity of combining it with other components.

**Completion requires more than all rows having labels.** The S11 audit must explain, entry by entry, why remaining feasible work cannot materially change the supported architectural choice within its stated scope. Any still-consequential untested mechanism keeps the research open. A completed sequence document is only a plan.
