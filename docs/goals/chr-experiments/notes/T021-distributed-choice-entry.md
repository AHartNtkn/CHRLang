# Direct distributed-choice graph entry

The user clarified a concrete proposal through an authorized side-conversation
relay. A choice's alternatives have matching free-variable/wire interfaces; an
unused port is internally padded by a trivial/existential connection. Corresponding
wires meet named disjunction nodes in one graph. Same-name interactions correlate
left/left and right/right; different names distribute independent choices. This
is architectural intent for investigation, not production adoption.

Investigate the proposal on that graph representation's own terms. Do not require
an incumbent store, unifier or whole-transition API as an eligibility condition.
The current architecture-assumption audit applies across the portfolio; this
entry does not substitute for questioning other inherited boundaries.

The user specifically leaves failure realization open. Invalid alternatives must
cease contributing trustworthy answers. Immediate physical reclamation of all
consequences is a separate obligation. Local validity connections, explicit global
compatibility checks, lazy checks/reclamation and combinations remain candidates.
No global branch-management design is assumed by that correctness requirement.

Required discriminating cases include shared computation surviving failure of only
some alternatives, and a failure with no ordinary data path to an output still
invalidating the corresponding answer. Also examine unused interface ports,
multiwire correlation without mixed answers, independent labels, fresh dynamic
choice occurrences, finite-tree equality and lifetime/reuse of labels. Internal
padding must not leak a new source residual predicate or accidentally ground an
unconstrained output.

The next entry must give executable local rewrite/projection rules, independent
finite observations, explicit completion/validity assumptions, and charged sharing/
