# E17 independent application entry

Read-only preparation identifies work that can proceed without a successful
sharing engine or E16 performance result. This is a proposed investigation, not
registered comparative evidence or a change to the language contract.

The unrestricted SK duplication query already appears in
`crates/chr-reference/examples/explore.rs`: constrain P with no_c and evaluate
P applied to two distinct constants to the first applied to the second twice.
The registry's app-sk-duplication supplies the whole duplicator; app-sk-ignored-hole
supplies its K wrapper. They do not measure unrestricted program synthesis.

Next workloads should include unrestricted P with resumed answer requests,
P = a(a(s,F),G), and P = a(a(k,Q),H). The known D = a(a(s,s),a(s,k))
has three application nodes. Its K-wrapped family retains no_c(H); validating
some ground H instances is insufficient to prove the whole nonground family.
A parametric K-reduction argument can check that family. Distinct program syntax
remains distinct output even when programs behave alike.

An independent ground SK enumerator and normal-order reducer can check bounded
synthesis sets. Sizes zero through three contain 102 trees; through four contain
550. Syntax size and reduction fuel must be separate bounds. Reduction cutoff is
unknown, not failure; finite-domain completeness requires resolving every member.
Run unrestricted prefix searches separately, with staged cumulative source-step
budgets, wall/memory bounds, retained residuals and explicit unfinished status.
The documented absence of an answer within 50,000 reference steps is unresolved.

Type-driven synthesis can target u→u, u→v→u and
(u→u→w)→u→w, using distinct ground type atoms. Independently infer principal types
with fresh K/S schemes and a separate finite-tree type unifier. Bounded ground
inhabitants and unrestricted prefixes answer different questions. Coupled
infer(P,T), no_c(P), and duplication evaluation provides connected recursive work;
its bounded expected set is the intersection of independent type and evaluator
oracles. Returning open target-type variables is necessary when their
specializations are part of the answer.

The literal lambda notebook translation has its own contract: residual neq,
norm dependent on companion var occurrences, and occurrence-sensitive constraint
consumption. It is not a generic capture-avoiding beta reducer. Bounded forward and
backward steps, partial redexes, and resumed lamEq with explicit var constraints
can be checked with hand steps and a separate finite relational checker preserving
residuals. Residual norm(T) is not evidence of normalization. A different binding
contract requires the owner's decision, but literal-contract experiments do not.

These investigations need no owner decision at entry. Their pilot registration
must define independent oracle limits, resumed versus cold sessions, answer
membership/coverage claims, cutoffs, and resource bounds before measurement.
